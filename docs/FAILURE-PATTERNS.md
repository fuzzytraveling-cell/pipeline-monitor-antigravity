## P1　git 的某一種問法，看不到某一類改動

**一句話判準**：我用的這個 git 指令，**看不到哪一類東西？** 新檔案？add 過的？整個資料夾？

- `git diff` 看不到還沒被追蹤的新檔案（L2，兩次）
- `git diff` 沒帶 HEAD 時看不到 `git add` 過的改動（L2 第三次）
- `git status --porcelain` 把整個新資料夾算成一行（L2 第三次）
- 讀 `--shortstat` 時假設一定有「insertion」字樣，只刪不加就變成 +0 −0（L2 第三次）
- 沒章時拿 `git diff HEAD` 當「這次改動」：看不到這一輪**已經存檔**的改動。Claude 收工前一存檔，分級變「沒有改動」、收工 hook 放行（L11 的第二次，這一輪的起點）
- `git diff --name-only` 預設把「刪一個、加一個」配成搬家，只印新路徑：`git mv` 搬走危險清單上的檔，分級看不到它、T2 掉成 T1（這一輪的起點，魔鬼教官抓到）

⚠️ 漏掉的方向永遠是**讓改動看起來比實際小**——危險的那一邊。

**哪裡會再犯**：任何「數這次動了幾個檔案／幾行」的地方，任何新加的 git 查詢。
**釘住它的測試**：`scripts/status.test.mjs` 標 P1 的段落（含搬家新舊兩個路徑都算）；`scripts/origin.test.mjs` 標 P1 的段落（存檔過的改動從起點那一刻的版本還看得到）；
`scripts/gate.test.mjs` 標 P1 的段落（`git mv` 搬走危險檔，收工 hook 照 T2 擋）。

## P2　同一個事實在兩個地方各算一次，遲早給出不同答案

**一句話判準**：這個值，程式裡有幾個地方會**各自算出來**？

- 文件抄第二次就是第二個真相來源（L9）
- 同一個畫面上「還沒存進保險箱」與「改動」用兩種問法算，3 大於 2（L2 第二次、第三次）
- 「專案名 → 檔名」在 hook.sh、讀紀錄、寫章三處各寫一次（誠實修補 C）
- 規格的路徑抄在 README、`package.json`、`hooks.json`、`stages.json` 與程式檔標頭；工作項一換狀態（搬資料夾）全部靜默過期，只有 CLAUDE.md 的表有測試守著（L21）
- 「這一輪改了什麼」：五關的 B 會翻存檔紀錄補檔案，分級與收工 hook 還在比上一次存檔；B 還拿存檔的時間當改檔時間，同一個存檔動作，分級說「沒動」、D 說「又動了」（這一輪的起點）

**哪裡會再犯**：hook.sh（sh）與 status.mjs（node）要對同一件事有共識的任何地方；
同一個畫面上兩個看起來應該相等的數字。
在 docs/ 以外寫 `docs/…` 路徑的任何地方——路徑只住 CLAUDE.md 的表，別處只寫名字（L21）。
兩種語言各寫一次的規則，一定要有一條**真的跑兩邊**的測試釘住——翻譯得再像也是兩份。
**釘住它的測試**：`scripts/status.test.mjs` 標 P2 的段落；`scripts/sensor.test.mjs` 真的跑 hook.sh 對 `safeName()` 的那段；
`scripts/skills.test.mjs` 對 `stages.json` 的 skill 名與 `skills/` 資料夾的那段；
`scripts/specLink.test.mjs` 標 P2 的段落（規格連結:五關、分級卡、收工 hook 說同一件事）；
`scripts/collect.test.mjs`、`scripts/gate.test.mjs`、`scripts/origin.test.mjs` 標 P2 的段落（這一輪的起點:存檔前後四處同一張單子、共用資料夾一份分級、基準只算一次）；
`scripts/specLink.test.mjs` 標 P2 的規格搬家段落（寫規格那一關的旁白終端機、網頁各抄一份：每一種情況真的各跑一次，要一字不差）。

## P3　設定／路徑寫對了，不等於它真的在做事

**一句話判準**：**這條路徑失效的時候，誰會知道？**

- `import.meta.url` 是編碼過的，路徑有空白就永遠不執行（L1）
- `.gitignore` 漏一行，私人資料就上去了，沒有任何徵兆（L12）
- 資料夾搬走，hook 的絕對路徑靜默失效（L13）
- 透過捷徑（symlink）執行，`argv[1]` 跟真實路徑對不上（誠實修補 E1）
- worktree 沒有自己的設定檔就說「沒掛上」，但紀錄裡明明有它的事件——方向相反、同一個根：
  拿設定檔回答「活著嗎」（L13 第二次）

**哪裡會再犯**：任何把絕對路徑寫進設定檔的地方；任何用「設定／檔案在不在」推論「它在不在做事」的地方。
證據跟設定打架時，**證據贏**。
**釘住它的測試**：`scripts/privacy.test.mjs`、`scripts/mount.test.mjs`、`scripts/status.test.mjs` 標 P3 的段落；
`scripts/gate.test.mjs` 標 P3 的段落（收工 hook 整條路真的跑一次、每次跑都留心跳——沒有心跳的 hook 跟沒裝一樣）。

## P5　一個 0 有兩種意思：「本來就沒有」跟「做完了」

**一句話判準**：這個 0，是「沒有東西要做」，還是「東西做完了所以剩 0」？兩種都可能的話，不准只畫一種。

- 空的分支三階梯亮了兩格「都存好了／已經併進去了」——0 被讀成「做完了」（L16）
- 快轉合併之後分支尖端跟 main 一樣，畫成「跟 main 一模一樣,沒有東西要併」——0 被讀成「本來就沒有」（L16 的第二次，方向相反）
- 規格分批做、記的 AC 代號在檔案裡找不到了（改過號），這一批變成「0/0 對過」，收工 hook 就不要求了——0 其實是「對不上」（施工對話認規格，魔鬼教官抓到）
- 沒章時收工前先存檔，「這次改動」差 0 個檔案，被讀成「沒有改動」、分級卡畫綠臉、收工 hook 放行——0 其實是「改過的都存進去了」；
  找不到這一輪的起點時只看得到還沒存的，那個 0 要講「看不全」（這一輪的起點，2026-09-21 實測）
- 同一件事的第二個身體：切到別的分支存檔、再切回來，差 0 個檔被畫成「沒有改動」——0 其實是「動過的不在現在這條線上」，證據在 reflog（這一輪的起點，魔鬼教官抓到）

**哪裡會再犯**：任何「數量是 0」就決定亮不亮燈、寫哪句話的地方；任何「跟基準沒有差別」的判斷（差 0 個檔案、差 0 個存檔、差 0 行）。
先問：**差 0 是因為沒動過，還是因為動過的都進去了？** 分不出來就要說分不出來，或去找第三個證據（這次是 git 的 reflog）。
**釘住它的測試**：`scripts/collect.test.mjs` 標 P5 的段落（三階梯：空分支一格不亮、快轉合併 merge 那格要亮、沒證據要說分不出來）；
`scripts/ui.test.mjs` 標 P5 的段落（建議卡那一區：一張都沒有也要畫、伺服器沒回答不准講成「沒有」、要開在這裡的卡掛在別頁要指路）；
`scripts/specLink.test.mjs` 標 P5 的段落（這一批記的代號對不上檔案要講出來、不結案）；
`scripts/gate.test.mjs`、`scripts/tier.test.mjs`、`scripts/collect.test.mjs`、`scripts/origin.test.mjs`、`scripts/ui.test.mjs` 標 P5 的段落
（這一輪的起點:存檔之後收工 hook 照樣擋、你調高的還在；「看不全」跟「沒有改動」各一張臉）。

## P6　同一件事有好幾條路，感測器只接了其中一條

**一句話判準**：這件事**還有哪幾條路**會發生？每一條感測器都看得到嗎？看不到的那幾條，畫面有沒有講？

- 你自己打的斜線指令不經過 Skill 工具，感測器只接了 Skill——規格寫出來了，儀表板卻說「這一輪還沒跑」（L19）
- Claude 在 app 裡叫出來的建議卡不經過 `--suggest`，儀表板一張都沒有（app 建議卡這份規格的起因）
- 建議卡的一生有「提出」跟「收回」兩條路，規格只看到提出，還把收回當成 app 的叉叉（L22）
- 規格有兩條路來：這個對話自己跑 A 寫的、別的對話寫好點頭後拿來施工的。只接了前一條——規格明明在，儀表板說「這一輪還沒跑」、收工 hook 叫施工的對話重寫（施工對話認規格）
- 「這是哪個對話」有兩條路：感測器記的、指令的環境變數帶的。規格只看到前一條，寫「CLI 沒有對話代號」，差點整套靠時間去推（L22 的第二次）
- 「這份規格是不是這個對話寫的」只看感測器的 Write，用 Bash 寫的看不到（L8 的形狀）——自家的規格被收下，畫面還說是「別的對話寫的」（施工對話認規格，魔鬼教官抓到）
- 「改檔」有一條路是刪檔：刪掉的檔沒有修改時間，只刪檔的回合收工 hook 安靜放行、D 照樣結案（這一輪的起點，魔鬼教官抓到）
- 「這一輪從哪開始」有一條路是對話中途換進這個資料夾：只認這裡的第一句話，換過來之後、下一句話之前存的檔全落到起點前面（這一輪的起點，魔鬼教官抓到）
- 「這一輪的規格在哪」有兩條路：別的對話寫好、`--spec` 連上的；這個對話自己跑 A 寫的。只有連結那條會跟著搬家找——A 寫的規格開工照規矩搬到進行中，
  A 那格說「找不到這一輪的規格檔」、收工 hook 安靜地不再要求對清單，而且照錯誤訊息跑 `--spec` 也會被擋回來（規格搬家，2026-09-22 實測）。
  同一件事還有幾條路（魔鬼教官抓到）：記在主資料夾、記在工作區外、對話待在專案的子資料夾、對話的資料夾已經不在——以前都只憑檔名在工作區找，同名的另一份就被安靜頂替

⚠️ 漏掉的方向永遠是**畫面比事實安靜**：沒接到的那條路不會報錯，只會讓畫面少一樣東西，而少一樣東西看起來就像「沒有」（R1）。

**哪裡會再犯**：任何「接一個工具或事件來代表一件事」的地方；任何規格裡寫著「不接 X」的地方——先確認 X 到底是什麼、多常發生。
接不到的路，畫面要明講「這裡看不到」，不能只是不畫。
**釘住它的測試**：`scripts/sensor.test.mjs` 標 P6 的段落（斜線指令兩種證據都認；app 的建議卡記得到、讀取端當成一張卡）；
`scripts/sensor.test.mjs` 標 P6 的收回卡段落（Claude 叫了收回要記到、標在卡上）；
`scripts/ui.test.mjs` 標 P6 的段落（接不到的那條路——app 的叉叉——畫面要明講；收回的分不出是哪一張也要明講）；
`scripts/specLink.test.mjs` 標 P6 的兩個段落（別的對話寫的規格連上了,收工 hook 不叫重寫；沒連上時兩條路都講——「自己寫的」不只看 Write）；
`scripts/gate.test.mjs` 標 P6 的段落（對話中途換進資料夾，起點是它在這裡的第一筆紀錄）；
`scripts/specLink.test.mjs` 標 P6 的規格搬家段落（A 自己寫的規格搬到進行中之後清單照畫、收工 hook 照樣要求對清單，指的是新位置；
魔鬼教官第一輪那段：記在主資料夾、工作區外、子資料夾、資料夾已經不在，都照記的地方找，不拿同名的另一份頂替）。

## P7　系統塞進來的字，被當成使用者說的話

**一句話判準**：這一筆「使用者說的話」，**真的是人打的嗎？** 系統會不會往同一個欄位塞東西？

- worktree 對話的第一則訊息前面被系統附加一段 `<system-reminder>`，截 200 字之後使用者打的字整個不見（誠實修補 E3，2026-09-11）
- 背景工作做完時，Claude Code 把一則 `<task-notification>` 當成一句話送進對話——同一個 hook、同一個欄位，連 `prompt_id` 都常沿用前一句人話的。
  收工 hook 把「這一回合」的開始當成那則通知，程式在那之前改完，就被當成「這一回合沒改程式」放行；「N 則訊息」也把它數進去（D 多輪先問人 AC-8，2026-09-22 07:20 實測，LESSONS L26）

⚠️ 漏掉的方向：回合的邊界被系統挪晚，**在那之前做的事就看不見了**——畫面比事實安靜（R1）。

**哪裡會再犯**：任何讀 UserPromptSubmit 的 `prompt` 的地方——回合從哪開始、對話有幾則訊息、第一句話、畫面上「你說的原話」。
分辨只在讀的那一端做一次（`lib/events.mjs` 的 `saidByHuman`）；感測器照舊全部照記，不在熱路徑上判斷。
**釘住它的測試**：`scripts/sensor.test.mjs` 標 P7 的 E3 段落（剝掉 system-reminder 之後才截 200 字）；
`scripts/rerun.test.mjs` 標 P7 的段落（系統通知不重算回合、不算訊息數、不當成你說不用再跑的那句話）。
