## P1　git 的某一種問法，看不到某一類改動

**一句話判準**：我用的這個 git 指令，**看不到哪一類東西？** 新檔案？add 過的？整個資料夾？

- `git diff` 看不到還沒被追蹤的新檔案（L2，兩次）
- `git diff` 沒帶 HEAD 時看不到 `git add` 過的改動（L2 第三次）
- `git status --porcelain` 把整個新資料夾算成一行（L2 第三次）
- 讀 `--shortstat` 時假設一定有「insertion」字樣，只刪不加就變成 +0 −0（L2 第三次）
- 沒章時拿 `git diff HEAD` 當「這次改動」：看不到這一輪**已經存檔**的改動。Claude 收工前一存檔，分級變「沒有改動」、收工 hook 放行（L11 的第二次，這一輪的起點）
- `git diff --name-only` 預設把「刪一個、加一個」配成搬家，只印新路徑：`git mv` 搬走危險清單上的檔，分級看不到它、T2 掉成 T1（這一輪的起點，魔鬼教官抓到）
- 「跟起點比有沒有差」看不到**改了又還原**：你驗收之後用 Bash 把改動還原（`git checkout`、`restore`、`stash`），檔案回到起點的內容、git 說沒差，
  E 照樣寫「你說驗收過了」、D 照樣「沒問題」——講的是已經不在的那一版（E 自動驗收，魔鬼教官抓到）。感測器記過的檔，現在的修改時間照樣看得到
- 沒章時「這一輪開始那一刻的版本」只問 reflog：app 10/1 起開的資料夾沒有開資料夾那一筆，第一次存檔才有、而且比起點晚——
  起點查不到，存檔過的改動又看不到了，分級「看不全」、收工 hook 放行（L11 第三次的身體，多份規格與新資料夾的起點，2026-10-02 實測，LESSONS L31）

⚠️ 漏掉的方向永遠是**讓改動看起來比實際小**——危險的那一邊。

**哪裡會再犯**：任何「數這次動了幾個檔案／幾行」的地方，任何新加的 git 查詢。
**釘住它的測試**：`scripts/status.test.mjs` 標 P1 的段落（含搬家新舊兩個路徑都算）；`scripts/origin.test.mjs` 標 P1 的段落（存檔過的改動從起點那一刻的版本還看得到）；
`scripts/gate.test.mjs` 標 P1 的段落（`git mv` 搬走危險檔，收工 hook 照 T2 擋）；
`scripts/verify.test.mjs` 標 P1 的段落（驗收之後用 Bash 還原改動，E 不再照樣寫你說驗收過了）；
`scripts/rerun.test.mjs` 標 P1 的「第一輪的範圍」段落（中途存過檔，`--round D` 第一次、`--round C` 照樣列存檔過的；skill 的字照 `--round` 給的範圍）；
`scripts/origin.test.mjs`、`scripts/gate.test.mjs` 標 P1 的新對話接手段落（換人之後從換過去的版本算；同一個對話自己換分支不算換人——換分支之前改的危險檔照算）；
`scripts/origin.test.mjs`、`scripts/gate.test.mjs` 標 P1 的「app 新開的資料夾沒有 reflog」段落（照 app 現在的做法開資料夾、存檔之後：起點看感測器記的版本號，收工 hook 照樣要 D；
起點是第一句話、是叫 A 的那一刻各一段；reflog 最早那一筆是同一秒的存檔時不當成資料夾剛建好）。

## P2　同一個事實在兩個地方各算一次，遲早給出不同答案

**一句話判準**：這個值，程式裡有幾個地方會**各自算出來**？

- 文件抄第二次就是第二個真相來源（L9）

- 「這一輪 A 寫了哪幾份規格」：A 那格看每一筆結論，分級卡的 A 那一行只取最後一筆——同一頁一邊說 2 份、一邊只講最後交的那份；

  10/5 有一句結尾已經不一樣，測試只能一句一句追著兩邊對字（規格：終端機與網頁說同一句，收成 lib 一份、伺服器帶過去）

## P3　設定／路徑寫對了，不等於它真的在做事

**一句話判準**：**這條路徑失效的時候，誰會知道？**

- `import.meta.url` 是編碼過的，路徑有空白就永遠不執行（L1）
- `.gitignore` 漏一行，私人資料就上去了，沒有任何徵兆（L12）
- 資料夾搬走，hook 的絕對路徑靜默失效（L13）
- 透過捷徑（symlink）執行，`argv[1]` 跟真實路徑對不上（誠實修補 E1）
- worktree 沒有自己的設定檔就說「沒掛上」，但紀錄裡明明有它的事件——方向相反、同一個根：
  拿設定檔回答「活著嗎」（L13 第二次）
- 只綁 127.0.0.1 就說「只有這台電腦看得到」，伺服器卻不看網址（Host）與哪一頁送的（Origin）——
  別的網站透過你的瀏覽器照樣讀得到、按得到（L28）
- **清單寫對了那一天，不等於今天還對**：危險清單是某一天拍的照片——之後新加的程式檔、改了名的危險檔，分級永遠算不到最高那一級，
  畫面照樣畫得像清單是完整的。「清單哪天定的」也不能看設定檔最後一次存檔（改的可能是別的地方）（危險清單會過期，2026-10-05，L34）
- **記號寫了、讀的那一端沒讀**：jq 不在時感測器有留故障記號，但專案還沒有紀錄檔時讀取端不讀它，
  終端機叫你「開新的對話才會開始記」——照做永遠等不到；儀表板從來不講。讀到了也只數次數：
  `--report`、按鈕寫的紀錄（不需要 jq）被當成「感測器還在記」，壞三天講成剛壞（L33，規格：agent回報與故障記號）
- **證據在手上、那一句沒用它**：紀錄清空之後那一句只看紀錄，不看感測器掛得好不好——資料夾搬走（捷徑指空）又過了 90 天，
  對話頁全清掉，儀表板上紅色那一行再也看不到，那一句還說「沒開過對話就沒事」（90天清空之後的說法，魔鬼教官第一輪抓到）

**哪裡會再犯**：任何把絕對路徑寫進設定檔的地方；任何用「設定／檔案在不在」推論「它在不在做事」的地方。
證據跟設定打架時，**證據贏**。
**釘住它的測試**：`scripts/privacy.test.mjs`、`scripts/mount.test.mjs`、`scripts/status.test.mjs`、`scripts/faults.test.mjs`、`scripts/tier.test.mjs` 標 P3 的段落；
`scripts/gate.test.mjs` 標 P3 的段落（收工 hook 整條路真的跑一次、每次跑都留心跳——沒有心跳的 hook 跟沒裝一樣）；
`scripts/ui.test.mjs` 標 P3 的段落（假的網址、別的埠送來的按鈕真的送一次，要被擋下）；
`scripts/expiry.test.mjs` 標 P3 的段落（空的紀錄檔分不出是清空的、還是感測器從來沒寫進去：兩種都講，不准講死「過期了，沒事」；感測器壞著照講；
感測器掛壞了又過了 90 天，儀表板上紅色那一行看不到，那一句照講壞了、附修法）。

## P5　一個 0 有兩種意思：「本來就沒有」跟「做完了」

**一句話判準**：這個 0，是「沒有東西要做」，還是「東西做完了所以剩 0」？兩種都可能的話，不准只畫一種。

- 空的分支三階梯亮了兩格「都存好了／已經併進去了」——0 被讀成「做完了」（L16）
- 快轉合併之後分支尖端跟 main 一樣，畫成「跟 main 一模一樣,沒有東西要併」——0 被讀成「本來就沒有」（L16 的第二次，方向相反）
- 規格分批做、記的 AC 代號在檔案裡找不到了（改過號），這一批變成「0/0 對過」，收工 hook 就不要求了——0 其實是「對不上」（施工對話認規格，魔鬼教官抓到）
- 沒章時收工前先存檔，「這次改動」差 0 個檔案，被讀成「沒有改動」、分級卡畫綠臉、收工 hook 放行——0 其實是「改過的都存進去了」；
  找不到這一輪的起點時只看得到還沒存的，那個 0 要講「看不全」（這一輪的起點，2026-09-21 實測）
- 同一件事的第二個身體：切到別的分支存檔、再切回來，差 0 個檔被畫成「沒有改動」——0 其實是「動過的不在現在這條線上」，證據在 reflog（這一輪的起點，魔鬼教官抓到）
- 90 天清理改成「過期的滿一週才清」之後，停了三個月的專案紀錄全部過期、還沒清的那幾天，讀出來是「有紀錄、一筆都沒有」——
  0 其實是「都過期了」，終端機說「沒有一筆來自這個 worktree」、儀表板說「這一輪還沒跑」（90 天清理不丟紀錄，魔鬼教官抓到）
- 一輪寫了好幾份規格，其中一份讀不到：讀得到的都對完了，「還有 0 條沒對」被講成「Claude 對完清單」——0 其實是「讀得到的都對完了，另一份不知道」
  （多份規格與新資料夾的起點，施作時推出來的；魔鬼教官又抓到對話列、E 那一格的「N 條裡」也沒講）；
  E 驗收那一格，改格式之前的回報一條都對不上，被講成「沒有一條有結果」——0 其實是「對不上」（同一份規格，2026-10-05 實測）
- 上面那條 90 天清理的第二個身體：改成當場清之後，錯話換到清完之後——紀錄檔在、一筆都沒有，終端機說「感測器可能沒在運作」、
  感測器那一行說「還沒有來自這裡的紀錄」，儀表板叫你去掛一個早就掛著的感測器、說「還沒有結案的對話」——0 其實是「三個月沒用、都過期了」；
  而空檔也可能是從來沒寫進去，分不出來就兩種都講，不准反過來講死「過期了，沒事」（90天清空之後的說法，2026-10-07 假裝 12/16 實測）

**哪裡會再犯**：任何「數量是 0」就決定亮不亮燈、寫哪句話的地方；任何「跟基準沒有差別」的判斷（差 0 個檔案、差 0 個存檔、差 0 行）。
先問：**差 0 是因為沒動過，還是因為動過的都進去了？** 分不出來就要說分不出來，或去找第三個證據（這次是 git 的 reflog）。
**釘住它的測試**：`scripts/collect.test.mjs` 標 P5 的段落（三階梯：空分支一格不亮、快轉合併 merge 那格要亮、沒證據要說分不出來）；

## P6　同一件事有好幾條路，感測器只接了其中一條

**一句話判準**：這件事**還有哪幾條路**會發生？每一條感測器都看得到嗎？看不到的那幾條，畫面有沒有講？

- 你自己打的斜線指令不經過 Skill 工具，感測器只接了 Skill——規格寫出來了，儀表板卻說「這一輪還沒跑」（L19）
- Claude 在 app 裡叫出來的建議卡不經過 `--suggest`，儀表板一張都沒有（app 建議卡這份規格的起因）
- 建議卡的一生有「提出」跟「收回」兩條路，規格只看到提出，還把收回當成 app 的叉叉（L22）
- 規格有兩條路來：這個對話自己跑 A 寫的、別的對話寫好點頭後拿來施工的。只接了前一條——規格明明在，儀表板說「這一輪還沒跑」、收工 hook 叫施工的對話重寫（施工對話認規格）
- 「這是哪個對話」有兩條路：感測器記的、指令的環境變數帶的。規格只看到前一條，寫「CLI 沒有對話代號」，差點整套靠時間去推（L22 的第二次）
- 「這份規格是不是這個對話寫的」只看感測器的 Write，用 Bash 寫的看不到（L8 的形狀）——自家的規格被收下，畫面還說是「別的對話寫的」（施工對話認規格，魔鬼教官抓到）
- 「改檔」有一條路是刪檔：刪掉的檔沒有修改時間，只刪檔的回合收工 hook 安靜放行、D 照樣結案（這一輪的起點，魔鬼教官抓到）
- 「這一輪從哪開始」有一條路是對話中途換進這個資料夾：只認這裡的第一句話，換過來之後、下一句話之前存的檔全落到起點前面（這一輪的起點，魔鬼教官抓到）
- 「這一輪從哪開始」還有一條路是**新對話接手舊資料夾**：app 把收掉的對話留下的資料夾換一條新分支給新對話，沒跑 A 的新對話就接著上一個對話的一輪——
  上一手的 A、C 畫成這一輪跑過、上一手的章當基準、收工 hook 照 T2 要補 A、C；上一手的頁面還畫著新對話的分支與改動（新對話接手舊資料夾，2026-09-24 實測，LESSONS L29）。
  同一件事的另一條路：換人之後你在儀表板上替上一手按結案，那一筆帶著上一手的對話代號、記在同一個資料夾，新對話又被算成「共用」（魔鬼教官抓到）
- 「這一輪的規格在哪」有兩條路：別的對話寫好、`--spec` 連上的；這個對話自己跑 A 寫的。只有連結那條會跟著搬家找——A 寫的規格開工照規矩搬到進行中，
  A 那格說「找不到這一輪的規格檔」、收工 hook 安靜地不再要求對清單，而且照錯誤訊息跑 `--spec` 也會被擋回來（規格搬家，2026-09-22 實測）。
  同一件事還有幾條路（魔鬼教官抓到）：記在主資料夾、記在工作區外、對話待在專案的子資料夾、對話的資料夾已經不在——以前都只憑檔名在工作區找，同名的另一份就被安靜頂替
- 「這一輪的規格在哪」還有一條路：**一次 A 寫了好幾份**。結論只留每一關最後一筆、A 寫了哪份只認一份——
  畫面只掛最後交的那份、寫「全部 5 條」其實 15 條，收工 hook 只要那 5 條（多份規格與新資料夾的起點，2026-10-02 實測，LESSONS L32）
- 「這一輪要做哪幾份規格」還有一條路：**同一個對話叫第二次 A 再寫一份**——一輪從後來那次算（定義不改），第一份掉出這一輪，
  A 那格還說它「沒記到」；A 寫完自己那份又 `--spec` 別份，也不講換掉（同一份規格，魔鬼教官抓到）
- 「這一輪從哪個版本算起」的證據有兩條路：git 的 reflog、感測器每一筆記的版本號。只接了 reflog——app 一換開資料夾的做法，起點就查不到（同一份規格，LESSONS L31）
- 「清理換檔會丟掉哪些行」有兩條路：先打開檔案、晚點才寫的（hook.sh 的 shell 先打開、jq 算完才寫）；被暫存檔 fsync 卡住的 append（任何寫的人，包括你按的按鈕）。
  規格只看到前一條，寫「你蓋的章不會丟」（90 天清理不丟紀錄，魔鬼教官抓到、重現過）
- 「這裡記不到」有好幾條路：這台電腦的感測器壞了（故障記號）、掛壞了（資料夾搬走、捷徑指空）、沒掛上（plugin 拆了）、你退出了。
  紀錄清空之後那一句，規格只接了第一條和最後一條；魔鬼教官第一輪補了掛壞了、第二輪才補沒掛上——修一條路的時候沒問「旁邊還有哪幾條」（90天清空之後的說法）

⚠️ 漏掉的方向永遠是**畫面比事實安靜**：沒接到的那條路不會報錯，只會讓畫面少一樣東西，而少一樣東西看起來就像「沒有」（R1）。

**哪裡會再犯**：任何「接一個工具或事件來代表一件事」的地方；任何規格裡寫著「不接 X」的地方——先確認 X 到底是什麼、多常發生。
接不到的路，畫面要明講「這裡看不到」，不能只是不畫。
**釘住它的測試**：`scripts/sensor.test.mjs` 標 P6 的段落（斜線指令兩種證據都認；app 的建議卡記得到、讀取端當成一張卡）；
`scripts/sensor.test.mjs` 標 P6 的收回卡段落（Claude 叫了收回要記到、標在卡上）；
`scripts/sensor.test.mjs` 標 P6 的 90 天清理段落（換檔之前打開、換檔之後才寫進舊的那一份的，補到新檔）；
`scripts/ui.test.mjs` 標 P6 的段落（接不到的那條路——app 的叉叉——畫面要明講；收回的分不出是哪一張也要明講）；

`scripts/gate.test.mjs` 標 P6 的新對話接手段落（收工 hook、儀表板、終端機都從接手那一刻算：T1、只要 D，上一手的 A、C、章不算）；

## P7　系統塞進來的字，被當成使用者說的話

**一句話判準**：這一筆「使用者說的話」，**真的是人打的嗎？** 系統會不會往同一個欄位塞東西？

- worktree 對話的第一則訊息前面被系統附加一段 `<system-reminder>`，截 200 字之後使用者打的字整個不見（誠實修補 E3，2026-09-11）
- 背景工作做完時，Claude Code 把一則 `<task-notification>` 當成一句話送進對話——同一個 hook、同一個欄位，連 `prompt_id` 都常沿用前一句人話的。
  收工 hook 把「這一回合」的開始當成那則通知，程式在那之前改完，就被當成「這一回合沒改程式」放行；「N 則訊息」也把它數進去（D 多輪先問人 AC-8，2026-09-22 07:20 實測，LESSONS L26）
- 反過來的同一件事：**Claude 做的，被當成你做的**。Claude 聽你說完之後替你跑 `pipeline-status --clear E`，紀錄跟你自己按的按鈕一模一樣（`source: human`）——
  9/16 那一筆就是。E 有了 Claude 自己走一遍之後，Claude 替你說「驗收過了」的機會只會更多（E 自動驗收 AC-9，開工前檢視抓到）
- 第四次（2026-10-05，真的紀錄三筆）：子 agent 做完時，Claude Code 把一則 `<agent-message …>` 當成一句話送進對話——
  收工 hook 為同一件事 15 分鐘內擋了三次；它也會被當成「D 之後你說不用再跑」「E 之後你說驗收過了」的原話。
  **看到一種加一種會漏**，所以從這次起：開頭是沒見過的 `<標籤`，不算你說的、畫面講出來（L26 的第二次，規格：agent回報與故障記號）
- 再反過來一次：**你做的，被當成 Claude 做的**。你在對話框用 `!` 自己跑 `--clear E`，走的是同一個工具、環境一樣帶著對話代號，
  被當成 Claude 代記——不附話被拒收、附了話不算數（E 自動驗收，魔鬼教官抓到）。分得出來的證據在讀的那一端：感測器會記下你打的那一句 `<bash-input>…`

- 第五次（2026-10-25，跟第一次同一個機制）：在 app 按建議卡開的對話，第一句話被 app 包一層「Background (from the session that started this one):」＋背景說明＋「Task:」＋要貼的話——
  背景說明是另一個 Claude 寫的，卻擠在「你說的第一句話」最前面。截 200 字之後要貼的話剩 59 字（比對要 60），照卡開的對話認不出「已開始」，卡永遠掛著（建議卡開的對話認得出已開始，LESSONS L39）。
  這次只剝掉包裝、記下 `prompt_wrap` 當證據；那一句還被算成你說的話，是另一半，還沒處理

⚠️ 漏掉的方向：回合的邊界被系統挪晚，**在那之前做的事就看不見了**——畫面比事實安靜（R1）。

**哪裡會再犯**：任何讀 UserPromptSubmit 的 `prompt` 的地方——回合從哪開始、對話有幾則訊息、第一句話、畫面上「你說的原話」；
任何標著 `source: human` 的紀錄——先問：**寫這一筆的，可能是 Claude 替你跑的指令嗎？** 指令的環境帶著對話代號，就是 Claude 在跑。
分辨只在讀的那一端做一次（`lib/rounds.mjs` 的 `saidByHuman`／`promptKind`）；感測器照舊全部照記，不在熱路徑上判斷。
新的系統格式不准預設成人話：認得的系統訊息、認得的你的動作之外，一律算「沒見過的」——猜錯的代價是多問一次，不是替你說了話。
**釘住它的測試**：`scripts/sensor.test.mjs` 標 P7 的 E3 段落（剝掉 system-reminder 之後才截 200 字）；
`scripts/sensor.test.mjs` 標 P7 的「建議卡開的對話」段落（剝掉開頭的 Background／Task 包裝之後才截，背景多長都認得出已開始；你自己打的字不會被剝掉一段）；
`scripts/rerun.test.mjs` 標 P7 的段落（系統通知、子 agent 的回報不重算回合、不算訊息數、不當成你說不用再跑的那句話；沒見過的格式收工 hook 取會擋的那邊）；
`scripts/verify.test.mjs` 標 P7 的段落（Claude 代記的「驗收過了」要對得回你在 E 之後說的話；通知不算；記一筆不算數的不蓋掉你按的；你用 `!` 跑的認得是你）。
`scripts/gate.test.mjs` 標 P7 的「這次先不看」段落（收工 hook 問了之後沒有你說的話，Claude 代記的「先不看」不算；算數的也附上感測器記的那一句給人對照，不是 Claude 轉述的）。

## P9　存檔的時間，不是事情發生的時間

**一句話判準**：我拿來比的這個時間，**存檔（commit）、rebase、cherry-pick 會不會把它往後推？** 我要問的其實是「那一刻在不在」，還是「什麼時候存的」？

- B 翻存檔紀錄補檔案時，把存檔的時間當成改檔的時間：D 說沒問題之後一存檔，D 就變成「之後又改了程式檔，要再跑一次」（這一輪的起點，2026-09-22 實測；L11 的第二次）
- 危險清單「判斷之後才新加的」看那之後的存檔新增了哪些：判斷時還沒存檔的新檔，一存檔就變成判斷之後才新加的——
  判斷過的檔又被講成「危不危險還沒有人判斷」；收工 hook 要問的話，每存一次檔就再問一次（收工hook問危險清單，2026-10-06 寫規格時重現，L35）

⚠️ 這一種的方向通常是**多問、多擋**——看起來比較保險，其實是假話（講成沒人判斷過、講成又改過），而一直亂叫的工具三天後就沒人看。

**哪裡會再犯**：任何「X 之後才發生的」拿 git 的時間（`--since`、存檔時間）判斷的地方。要問「那一刻在不在」，就記下那一刻的版本去比，不要拿時間猜。

## P10　畫面上的記號說得比證據多：顏色、燈號、表情替結果背書

**一句話判準**：這個肯定的記號（綠色、亮燈、笑臉）會在哪幾種狀態出現？**讓那個狀態成立的每一條路，是誰說的、憑什麼？**
