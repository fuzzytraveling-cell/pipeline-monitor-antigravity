## 這是為了解決什麼

app 建議卡那一攤 D 連跑三輪，用量上限就是這樣用掉的。紀錄顯示：**第二、三輪是 Claude 在同一回合裡照 skill 那句「處理完之後再跑一次」自己跑的，中間一次都沒收工**——所以煞車不能只裝在收工 hook 上。

2026-09-21 再對一次 9/17 兩個對話的紀錄：其實是**兩個問題疊在一起**，上面那段只講了第一個。

| 9/17 的每一輪 D | 從叫到記結論 | 跑法（對話自己選的，skill 沒要求） | 找到 |
|---|---|---|---|
| 上午第一輪 | 3 分半 | 紀錄裡看不到 | 1 條 |
| 上午第二輪（skill 那句「處理完再跑一次」叫的） | 47 秒 | 紀錄裡看不到 | 0 條 |
| 上午第三輪（你說「選項二」之後改了幾行，結論過期，Claude 自己叫的） | 56 秒 | 紀錄裡看不到 | 0 條 |
| 下午第一輪 | 29 分鐘 | 一個獨立 agent，Claude 逐條查證 | 3 條 |
| 下午第二輪 | 看不到，沒叫 skill | 再一個全新的獨立 agent | 4 條，2 條是第一輪的修法弄出來的 |
| 下午第二件事第一輪 | 16 分鐘 | 三個獨立 agent，每條再派一個反駁 | 1 條，被駁回 |

**第二個問題：一輪 D 有多貴，完全看「怎麼跑」，而以前沒有任何規則管這件事。** 時間是紀錄裡兩個時間戳相減；9/21 你決定不跑的那一輪，按紀錄估約 12 分鐘、59 萬 tokens。
兩個問題還會互相放大：貴的跑法找到的條數多（連自己修法弄出來的都算進去），每一條又變成再跑一輪的理由。
所以 **AC-1 到 AC-9 管「跑幾次」，AC-10 到 AC-13 管「一次多貴」**——只做前一半，一輪還是 29 分鐘，只是少跑兩輪。

**開工前提**：`docs/進行中/` 已滿（上限 2 份），要先騰出位子；**建議排在「施工對話認規格」之後**，不然這份的施工對話會被收工 hook 逼著重跑 A。

## 驗收條件

**AC-1　skill 本身就不准自己重跑：修完先停下來問你**
> **白話**：師傅交報告、工班照單修完，要不要請師傅再來一趟，是屋主決定，不是工班自己叫。
> **會發生的情況**：D 找到 3 條、Claude 修掉 → Claude **不再叫 D**，停下來問你（說明照 AC-3）。紀錄裡同一輪看不到第二次 D，除非你說了要跑。
> **技術**：`skills/chaos-check/SKILL.md` 刪掉「使用者或你處理完之後再跑一次這一關」，改成「這一輪已經有 D 的結論 → 不准自己再叫，先問」；取代五關 AC-8 的「修完再請他看一次」。
> 收工 hook 第一次叫 Claude 跑 D 的那段話，也預先交代「修完不要自己重跑，先問人」，並照分級講跑法（AC-11：T1 自己看，不派 agent）。

**AC-2　「一輪」看的是這件工作，不是你說了幾句話**
> **白話**：同一張圖、同一件工程，師傅驗過一次之後，再驗都要屋主點頭；換一件工程才重新算。
> **會發生的情況**：D 找到問題 → 你回「修掉吧」→ Claude 修完 → **不會**自動再跑 D，照 AC-1 先問你。你之後又交代「順便把標籤對齊」→ 一樣先問。
> 新的 A（寫下一份規格）或蓋章之後，才重新算第一輪。
> **技術**：這一輪（`roundStartOf`：最近一次 A 或蓋章之後）已經有 D 的結論（`stage_report`）、之後又改了程式檔 → 狀態是「要不要再跑，你決定」，不是「要再跑」。

**AC-3　問你的時候講四件事，而且時間只准從紀錄拿**
> **白話**：工頭問屋主之前，先說清楚：修了哪裡、為什麼值得或不值得再驗、上次驗花了多久、不驗的風險。
> **會發生的情況**：「第一輪之後我改了 events.mjs 的去重跟兩條測試；我覺得不值得再跑，因為……；上一輪從叫 D 到記結論花了 29 分鐘（紀錄算的），用了多少 tokens 儀表板看不到；不跑的風險是……」。
> **技術**：`skills/chaos-check/SKILL.md` 寫明四件事；時間從感測器算（D 被叫到 `stage_report`），**只在 `lib/events.mjs` 算一次**，問人、`--round D`（AC-10）、儀表板（AC-13）都拿同一個數（P2）。算不出來就說「上一輪花多久紀錄裡看不到」，**不准估**（R3）。
> 「值得或不值得再看」照 AC-12 的標記講，不是每次重新想。

**AC-4　你說不用，儀表板照實寫是誰記的、你說了什麼、過了多久——不是綠勾**
> **白話**：屋主說「不用再驗了」——看板寫「工頭記下：屋主說不用」，貼上屋主的原話和日期，不寫「驗過了」。
> **會發生的情況**：D 顯示「⏸ Claude 記下：你說這一輪不用再跑 D（你說：『不用跑了』，3 小時前）· 第一輪 Claude 說找到 3 條」。不劃掉、不打勾；分級卡那一項是「跑過,你說不用再跑」，不算 ok。
> **技術**：新指令 `pipeline-status --decide D skip "<你的話>"`，事件 `stage_decision`（`source:'human'`、`via:'claude'`），只准 `rerunAfterChange` 的關。
> 畫面附的話**從感測器拿**：D 被叫**之後**（不含叫 D 的那句斜線指令本身）你說的最後一句的前 200 字。
> 沒有這樣一句話 → 不算數，畫面寫「Claude 記了你說不用，但 D 之後沒有你說的話，分不出是不是你說的」，收工 hook 也不認。
> ⚠️ 這只擋得住「根本沒問你」，擋不住「你說跑、Claude 記成不用」——那要靠畫面上你的原話讓你自己對得出來（R2：寫清楚證據只有這麼大）。

**AC-5　你的決定只管到你說話那一刻的改動**
> **白話**：屋主說「剛修的不用再驗」，不代表之後再動的工也不用驗。
> **會發生的情況**：你說「不用再跑了，順便把按鈕改藍色」→ 改藍色那次，不算在你的決定裡；那次改動之後 D 又是「要不要再跑，你決定」。
> **技術**：決定蓋到的是「你那句話的時間」之前的改檔，不是 Claude 記下 `--decide` 的時間。

**AC-6　每一輪都要叫 skill、收尾都要記結論；沒記就提醒一次，還在跑就說還在跑**
> **白話**：師傅每來一趟都簽到、交報告；報告還沒寫完，就說還沒寫完，不准先交一張空白的。
> **會發生的情況**：Claude 把 D 交給獨立 agent，也先叫一次 `/pipeline-monitor:chaos-check`；D 跑完沒記結論想收工 → 擋一次「D 跑過了但還沒記結論」。D 還在背景跑 → Claude 照實說還在跑，**不准**先記 ok 交差。
> **技術**：這一輪最後一次 D 之後沒有 `stage_report` → 收工 hook 提醒，**沒改檔的回合也要看**（取代五關 AC-1「回答問題的回合安靜」，只限這一項）。提醒的話寫明「還在跑就說還在跑」。
> ⚠️ 感測器照舊不接 Agent 工具、不從 agent 的指示猜它是不是在做 D（P4）。沒叫 skill 的那一輪，儀表板照實不知道。

**AC-7　收工 hook 一個回合可以為「不同的事」各提醒一次，但同一件事不重複**
> **白話**：工頭下班前可以先提醒「還沒驗」、驗完再提醒「報告還沒交」，但同一件事不念第二次。
> **會發生的情況**：擋「D 還沒跑」→ Claude 跑 D → 收工時再擋「還沒記結論」→ 記完 → 修了發現 → 收工時再擋「要不要再跑，先問人」→ Claude 問你、收工放行。同一件事擋過就不再擋。
> **技術**：取代五關 AC-1 的「`stop_hook_active` 就放行、同一個 prompt 最多擋一次」：改成這一回合 `gate_blocked` 已經記過的**種類**不再擋，新的種類照擋（種類是有限的幾種，不會迴圈）。
> 有「問人」那一行時，擋的話最後那句「先把缺的跑完再收工……這是分級的要求」換掉，不准跟「不要自己再跑」打架。

**AC-8　系統通知不算「你說的話」**
> **白話**：對講機響一聲「背景工作做完了」，不是屋主開口。
> **會發生的情況**：D 交給背景 agent、做完的通知進來 → 不算新的一句話：不重算回合、不算 AC-4 的「你說的話」、不會出現在畫面上當成你的原話、對話的「N 則訊息」也不算它。
> **技術**：開頭是 `<task-notification>` 的 UserPromptSubmit，讀取端只在一處判斷（真實紀錄已有兩筆這種形狀，測試用它）。

**AC-9　儀表板、終端機、收工 hook 對「要不要再跑」說同一句話，「最後一次改檔」也只算一份**
> **白話**：看板、對講機、工頭講的要一樣；而且「存檔」不算「動工」。
> **會發生的情況**：只有三種說法：「還沒跑」「修過之後還沒再跑，要不要跑由你決定」「Claude 記下：你說不用再跑」。D 說沒問題之後你只說「commit」→ 三處都還是沒問題。
> **技術**：判斷只在 `lib/events.mjs` 算一次；D 過期的「最後一次改檔」只算感測器的改檔事件與檔案修改時間，**不算存檔（commit）時間**，收工 hook 改吃同一份（P2）。
> 過期比的是 **D 被叫的時間**，不是結論記下的時間——修完才記「沒問題」，也算結論之後改過（取代五關 AC-9 的比法）。

**AC-10　再跑只看「第一輪之後改的」，不重讀整批**
> **白話**：師傅第二趟只看上次報告之後動過的地方，不重新驗整棟。
> **會發生的情況**：第一輪 D 看了 30 個檔找到 3 條；Claude 修了 3 個檔；你說再跑 → 第二輪 D 只拿那 3 個檔（含它們的測試檔）的改動來對清單，
> 回報第一行明講「第二輪只看了第一輪之後改的 3 個檔：a、b、c」，儀表板照那一行列。整批 30 個檔的結論還是第一輪的，第二輪不重講。
> **技術**：新指令（暫名 `pipeline-status --round D`）一次回答六件事：這一輪第幾次跑 D、分級是哪一級、上一次從叫到記結論幾分鐘（AC-3）、
> 第一輪之後改了哪些檔、其中哪些在危險清單、這一輪有沒有動到測試檔（後兩個給 AC-12 用）。skill 開工第一步先跑它，照它說的分路走。
> 「第一輪之後改了誰」= 兩種證據取聯集：感測器的改檔事件、git 說有改動的檔案裡修改時間比 D 被叫晚的（Bash 寫檔繞過感測器，L8；新檔案也算，L2），
> 跟 `roundView`／`gate.mjs` 算「最後一次改檔」的是同一份程式（P2）。diff 的基準是 **D 被叫那一筆紀錄的 `head`**（感測器有記），不是現在的 HEAD——第一輪之後 commit 過的改動才不會消失。
> 它說「這一輪還沒有 D 的紀錄」→ 這是第一輪，看整批。拿不到清單（不是 git、感測器沒記到這個對話、那筆紀錄沒有 `head`、指令不存在）→ 看整批，
> 並明講「拿不到第一輪之後的清單，這次看的是整批」（R1）。
> 代價要寫進 skill：修法跟沒重讀的那些檔之間的交互，第二輪看不到；所以回報不准講成「全部看過」。

**AC-11　跑法照輪次與分級分：T1 一律自己看；T2 第一輪才可以派 agent；第二輪以上一律自己看**
> **白話**：第一次驗屋，房子大才多請幾個師傅；第二趟只是看修得對不對，一個人去就好。
> **會發生的情況**：T1 第一輪：Claude 自己讀改動、對清單，不派 agent。T2 第一輪：**可以**派獨立 agent 多角度看，派幾個由 Claude 判斷，
> 但回報第一行要寫「派了 N 個 agent」。第二輪以上不論分級：Claude 自己看 AC-10 那份清單，不派 agent。
> 沒設定分級、或設定讀不懂的專案：自己看，回報明講「這個專案沒設定分級，我照最省的方式跑」——不是把它當成 T1，是講明成本上取最省的那條。
> **技術**：`skills/chaos-check/SKILL.md` 開頭照 `--round D` 的答案分三條路寫清楚；收工 hook 第一次要求 D 的那段話照分級講跑法（AC-1）。
> 「派了 N 個 agent」是 Claude 自己說的：感測器不接 Agent 工具（明確不做），儀表板只能標「Claude 說」，證明不了。
> 工具管得到的只有 skill 裡的字和收工 hook 那句話，Claude 聽不聽要實測（L19 的形狀），列在「還沒驗證的」。
> 規格原本「明確不做」的「不限制 D 用 agent 還是自己跑」刪掉，由這一條取代。

**AC-12　每條發現修完標「小修」或「建議再看」；門檻是查得到的事實，Claude 只准往上調**
> **白話**：師傅報告每一條後面註明「這種小問題，修完不用再來」或「這個動到結構，修完要再看」，屋主一眼就能決定。
> **會發生的情況**：Claude 修完第一輪的 3 條，問你的時候（AC-3）每條各一行：「[P2] 兩處各算一次 → 小修，改 1 個檔，有測試守著」、
> 「[R1] 沒問到當沒有 → 建議再看：改到 lib/events.mjs，在危險清單」。最後一行是建議：全部小修 → 「我建議不跑」；有任何一條建議再看 → 「我建議跑」。你的決定才算數。
> **技術**：「建議再看」的硬門檻只有兩條：① 修法改到的檔在危險清單——`--round D` 直接算給它；② 第一輪之後改的檔比 D 指出的檔多（修法蔓延到別處）——
> 由 Claude 拿 `--round D` 的清單對自己第一輪報的位置，工具不從報告文字猜檔名（P4）。
> 其餘是「小修」，但要照實寫「有沒有測試守著」（這一輪有沒有新增或修改測試檔，跟分級的 tests 同一個判斷）。
> Claude 可以把小修往上調成建議再看（要寫理由），**不准往下調**——跟分級「只准往上」同一條規矩。
> 危險清單空的 → 硬門檻只剩「蔓延」，問人時明講。這是 Claude 對自己修法的判斷，只能當建議；儀表板不畫它，畫的是你的決定（AC-4）。

**AC-13　儀表板 D 那格印「上一輪從叫到記結論花了 N 分鐘」**
> **白話**：看板上寫上次師傅來了多久；花了多少一直看得見，下次才不會又燒掉。
> **會發生的情況**：D 那格多一句「上一輪從叫到記結論 29 分鐘」；還沒記結論的輪次照舊只印「N 分鐘前叫的」。tokens 感測器看不到，就一個字都不印，不估（R3）。
> **技術**：跟 AC-3 同一個數（`lib/events.mjs` 算一次），終端機與網頁各自只負責印。

## 混沌推導（只寫有觸發的）

▸ **時間**：D 交給 agent 跑二十幾分鐘，Claude 同時在改檔 → 改檔比 D 被叫晚 → 過期，照實。感測器時間只到秒 → 沿用收工 hook 的兩秒誤差。
▸ **輸入畸形**：`--decide` 給了不是 D 的關、沒給你的話、給了 `skip` 以外的字 → 回一句白話的錯誤、不記。
▸ **併發**：兩個對話共用一個工作區 → AC-4 的「你說的話」只從記這一筆的那個對話拿，分不出是哪個對話就不算數。
▸ **權限**：記不了檔 → `--decide` 大聲失敗（跟 `--report` 一樣）。
▸ **AC-10 的時間**：D 交給 agent 跑、Claude 同時改檔 → 那些檔算「第一輪之後改的」，照實列，第二輪就會看到它們。第一輪之後 commit 了 → 基準是 D 被叫那筆的 `head`，diff 還看得到。
