# 功能：儀表板讀規格 —— 把 AC 畫出來、勾選只產生回覆文字、等點頭幾天

> 2026-09-15 Oscar 提的：A 產出的規格要開檔案才看得到；想在儀表板上用勾選框處理 AC。
> 他自己先講了顧慮：**儀表板反向控制對話會有問題。** 這份規格的立場跟他一樣——
> 方向不變：感測器記、大腦算、畫面顯示；**人是儀表板跟對話之間唯一的通道。**
> 對應 [`../ROADMAP.md`](../ROADMAP.md) 階段 ④「從網頁下指令」——那一格仍然是「也許永遠不做」。

## 這是為了解決什麼

A 寫完規格會停下來等點頭。現在要看那份規格得去開檔案，或在對話裡往上捲；「這份規格等點頭等了幾天」沒有地方看。

## 白話

- 規格檔本身就是事實（第一級：檔案系統）。儀表板讀 `docs/規劃中/*.md`，把每一條 AC 的白話、會發生的情況畫出來，你不用開檔案。
- 勾選框**不控制任何東西**。它只把你的選擇拼成一句回覆，例如「AC-6 刪，其他照規劃」，你複製、貼進對話。
  跟現在「建議新增的對話」卡片同一種做法：儀表板開不了對話，只能把字準備好讓人貼。
- 「點頭」已經有事實：規格從 `規劃中/` 搬到 `進行中/`。儀表板顯示「等點頭 N 天」，不加按鈕。

## 驗收條件

**AC-1　規劃中的每一份規格都列出來，附「等了多久」**
> **白話**：像門口的收件匣，看得到有幾份在等、最舊的等多久。
> **會發生的情況**：案件頁多一區「等你點頭的規格」，每份一行：標題、等了幾天。
> **技術**：來源是 `docs/規劃中/*.md`；「等了多久」用 git 第一次加入那個檔案的時間，還沒 commit 的用檔案時間並標明「還沒存」。

**AC-2　每一條 AC 白話在前，照檔案原文顯示；解析不了的整段照原文，不假裝解析成功**
> **白話**：看不懂的字條就整張貼出來，不要自己改寫。
> **會發生的情況**：照四層格式寫的規格，AC 分條顯示；手寫的、別的專案格式的，整段原文顯示，並標「這份不是照範本寫的」。
> **技術**：R1——解析失敗不是「沒有 AC」。

**AC-3　勾選只產生文字，一鍵複製；不寫任何紀錄、不改任何檔案**
> **白話**：勾選框是草稿紙，不是遙控器。
> **會發生的情況**：勾了、取消了幾條，下面出現一句可以直接貼進對話的回覆，按一下複製。重新整理就歸零。
> **技術**：純前端；`/api` 不新增任何寫入端點。

**AC-4　儀表板不反向控制對話**
> **白話**：對話只聽你的，不聽儀表板的。
> **會發生的情況**：對話裡看到的選項跟儀表板上的一致，因為都來自同一個檔案；但決定只從你嘴裡（鍵盤）進到對話。
> **技術**：測試釘住「沒有任何一個 API 端點會寫 AC 的決定」。這是老毛病 P2 的預防：同一個決定不准住在檔案、紀錄、對話三處。

## 混沌推導（只寫有觸發的）

▸ **輸入畸形**：規格不是照四層格式寫的 → AC-2，原文顯示。
▸ **容量**：`規劃中/` 有幾十份 → 只列標題與等了多久，點開才讀內容。
▸ **時間**：規格檔改了、對話裡討論的是舊版 → 顯示檔案最後修改時間，跟對話的最後動作時間並排。

## 明確不做

- 不做勾選寫回檔案、不做寫紀錄給對話讀、不做任何「儀表板叫 Claude 做事」的端點。
- 不做「讓 Claude 看得到儀表板」——可行，但另一份規格（見下面的討論）。

## 討論：讓 Claude 看得到儀表板，可行嗎（Oscar 2026-09-15 問）

**可行，現在就有兩條路，都不用新的基礎建設：**

1. **推：hook 注入。** `SessionStart`／`UserPromptSubmit` 的 hook 印出來的字會進到 Claude 的上下文——`remind.sh` 的分級提醒已經在用這個機制。
   可以在你送出訊息的那一刻附一行「儀表板上：你取消了 AC-6」。
2. **拉：skill 叫 Claude 自己去讀。** SKILL.md 裡寫「開工前先跑 `pipeline-status` 看人的決定」——`tier-setup` 已經是這樣做的。

**限制**：Claude 只在你送出訊息的那一刻看一次。儀表板的按鈕叫不醒正在跑的對話，也叫不醒沒開的對話。
所以「真正的交互」最多做到**「每次你開口，它先看一眼儀表板」**，不是雙向即時。

**風險**：同一個決定住在檔案、儀表板紀錄、對話三處（P2）。要做的話只有一種安全的形狀：
儀表板的紀錄只記「人的決定」（跟現在的「你說處理完了」「調高」一樣）；對話讀到了要說「我從儀表板看到你說…」；兩邊打架時**檔案為準**。
