## 這是為了解決什麼

第二段的主任只會問；你回「照建議收尾」之後，併、推、重啟、蓋章還是這個對話憑記性一步一步做——做完說「推上去了」沒有東西替它作證，哪一步沒成也可能被一句話帶過。

## 白話

交屋手續主任排好、你簽了字，這一次他自己跑完：去地政事務所過戶（併進 main）、送件到市府（推上 GitHub）、電路改過才換電表（重啟儀表板）、最後請技師簽保固（蓋章）。
每一站回來都拿收據給你看——「市府說收到的就是這一份」「電表上的日期是新的」——不是「我去過了」。哪一站被退件，他停在那裡回來問你，不自己想辦法硬闖。你的簽名只用在這一次。

## 驗收條件

**AC-1　你回一句之後，主任照它問的順序做完，每一步講「成了沒」**
> **白話**：一站一站跑，每站回來講「成了／沒成（原因）／沒做（為什麼）」，最後再看一次白板。
> **會發生的情況**：主任問完那一個問題（〈主任技能〉AC-3 的樣子），你回「照建議收尾」→ 同一個對話接著照問題裡的順序做。回報一步一行，例如
> 「併進 main：成了——main 現在就是這條分支最後一個存檔（v0.40.0）」「推上 GitHub：沒成——GitHub 上有這台沒有的存檔，沒推」「蓋章：沒做（前一步沒成）」。
> 第一個沒成的就停，後面的寫成沒做，問你怎麼辦。做完再跑一次 `pipeline-status --todo`，照白板講還差什麼（通常是「只差按結案，你按」）。
> **技術**：`skills/director/SKILL.md` 的「不動手」改成「你回答之前不動手；回答之後只做問題裡的」，「使用者回答之後」那一節寫順序與每一步叫哪個指令；
> 技能說明（plugin 清單上那一句）、README 那一列、對話頁 F 那一列「怎麼叫主任」跟著改。新的 `pipeline-status --wrap <步驟> "<你的原話>"`（步驟：merge／push／restart／stamp）
> 做事、自己確認、印一行結果——「成了」只在它確認過之後印（R2）；中英兩種（`lib/lang.mjs`），技能照你講的語言回。

**AC-2　併進 main：只快轉；快轉不了就停下來問**
> **白話**：過戶只走最單純的一種——登記簿上的 main 原地往前移到你這一版。對不上就回來問，不改登記簿。
> **會發生的情況**：在專案的主資料夾把 main 快轉到這條分支最後一個存檔；做完確認 main 真的就是那一個，才說「併進 main 了」。會停下來問的：
> 這個對話的資料夾還有沒存的檔（沒存的不會跟著過去）；主資料夾不在 main 上、或主資料夾有還沒存的改動；main 在這條分支開出來之後多了別的對話的存檔（快轉不了）——
> 講「main 多了 N 個別的對話的存檔，要先把 main 併進這條分支、再跑一次檢查，才能快轉」，你說好才做。併進來的照前半〈併進來的不算這一輪〉，不會算成你改的、不會因此問 D。
> **技術**：`--wrap merge`：在主資料夾跑 `git merge --ff-only <分支>`，前後各問一次 main 指到哪個存檔。不做真的合併、不 rebase、不 reset。

**AC-3　推上 GitHub：推完當場問 GitHub，對得上才說推上去了**
> **白話**：送件之後打電話問市府「收到了沒、收到的是哪一份」，對得上才算。
> **會發生的情況**：推的是整個 main（之前併了還沒推的會一起上去——主任的問題裡講過）。推完當場問 GitHub 上的 main 是哪一個存檔，跟本機的 main 一樣，才說「推上 GitHub 了：GitHub 上的 main 就是 v0.40.0」。
> GitHub 拒收（上面有這台沒有的存檔）→ 不硬推，講原因、停。推了但問不到 GitHub → 講「推了，但問不到 GitHub 上現在是哪一版」，不說推上去了。
> 專案沒有 GitHub（main 沒有上游）→ 這一步寫「沒有 GitHub，不用推」。GitHub 上自動跑的測試結果這台看不到——照講，不說「GitHub 上也綠」。
> **技術**：`--wrap push`：`git -C <主資料夾> push <main 的上游> main`（絕不加 --force），之後 `git ls-remote` 問那一條，跟本機的 main 比；白板「推了沒」那一格不改（照舊看本機記得的）。

**AC-4　重啟：服務跑的程式改過才重啟；重啟完確認跑的是新的**
> **白話**：電路真的改過才換電表；換完看電表上的日期是不是新的。
> **會發生的情況**：併完之後問儀表板的服務「你啟動之後有沒有程式改過」（白板最上面那一句的同一個來源）：沒有 → 「不用重啟：服務啟動之後程式沒改過」；
> 有 → 重啟，重啟完再問一次，服務說啟動之後沒有程式改過，才說「重啟了，跑的是新的程式」；還是有 → 講是哪幾個檔、停。連不上服務 → 講「連不上，不知道要不要重啟」，不說不用重啟。
> 只改了畫面、文件、測試的不重啟（服務每次現讀，或根本不讀）。別的專案收尾通常是「不用重啟」——服務跑的是 pipeline-monitor 的程式。
> **技術**：`--wrap restart`：`/api/serve-state` 的 changed；重啟用 `restartService`，之後再問一次。直接叫 `--serve-restart` 也補上同一個確認、講同一句（兩條路，P6）。

**AC-5　蓋章最後做；D 的事沒了結不蓋**
> **白話**：技師簽保固是最後一站；驗屋師傅還在等你回答要不要再看一次，就不簽。
> **會發生的情況**：蓋章排在併、推、重啟之後，在這個對話的資料夾跑這個專案的檢查，全綠才蓋；紅了停，照原文講哪一項紅。
> 收尾途中 D 找到要修的、修完改了程式 → 先問你 D 要不要再跑，你回答之前不蓋（蓋章會結掉這一輪，D 的問題就跟著不見）。
> 工具自己也擋：分級要 D，而這一輪的 D 是「還沒跑」「叫了還沒記結論」「要不要再跑等你決定」——不蓋，講卡在哪一句（跟白板同一句）。
> **技術**：`--wrap stamp`：先讀這個對話這一輪 D 的狀態（`rerunOf`，跟收工 hook、白板同一份），過了才走 `doCheckpoint` 同一套（還沒存的檔照舊直接拒絕）。

**AC-6　沒有你那句話，工具不動手；一句話每一步只試一次**
> **白話**：你的簽名只用在這一份、這一次。
> **會發生的情況**：`--wrap` 每一步都要帶你的原話；工具在這個對話的紀錄裡找：主任最後一次被叫之後、你打的話裡有這一句——找不到就不做，印「找不到你在主任問完之後說的這句話，這一步沒做」。
> 同一句話每一步只試一次：推過一次（不管成了沒），要再推就要你再說一句；主任又被叫了一次，之前的話全部不算。別的對話傳來的、包在對話開頭的說明、Claude 自己寫的字都不算你說的（P7）。
> **技術**：找你說的話跟 `--decide` 同一套（`saidByHuman`、感測器記的前 200 字）；「主任被叫」＝感測器記到這個對話叫 `director` 那支技能。每試一步記一筆（步驟、你的原話、那句話的時間、結果），「只試一次」靠它。

**AC-7　只做問題裡有的；你改哪一步照你改的；按結案留給你**
> **白話**：合約上沒寫的不做，你劃掉的那一項不做，交屋鑰匙留給你按。
> **會發生的情況**：你回「照建議收尾，但先不要推」→ 推那一步不做（回報寫「沒做：你說先不要推」），其他照做。問題裡沒有的——別的對話的收尾、別的專案、按結案——都不做；
> 白板最後只差按結案，就講「只差按結案，你按」。你的回答不是照做（「等一下」「先不要」）→ 一步都不做。
> **技術**：工具只認原話在不在，分不出你劃掉哪一步——這一條靠技能；回報每一步都附你的原話，讓你自己對得出來（R2：證據只有這麼大）。

**AC-8　這個專案自己的結案步驟照手冊做：推之前在乾淨副本跑一次測試**
> **白話**：這個工地自己的規矩——交屋前請另一個技師在空房子裡再試一次水電——照工地手冊做。
> **會發生的情況**：pipeline-monitor 推上 GitHub 之前，從存檔 clone 一份乾淨的副本，在乾淨的環境跑 `npm test`（P8：換一台電腦會不會不一樣）。紅了就自己再跑一次快轉之前的 main：
> 紅的一樣（同一條、同樣的數字）講「這一條上一版在這個環境也紅，不是這次改的」，停下來問你要不要照推；不一樣就停。手冊沒寫這一步的專案就沒有這一步。
> **技術**：`CLAUDE.md`「改完之後」加一行指標（推之前 `npm run test:clean`，指到 L24）；新的 `scripts/clean-run.mjs` 把 L24 三次學到的環境（空的家目錄、UTC、清掉環境變數、
> 不讀系統的 git 設定、短的暫存路徑）寫成一支。主任技能第三步「手冊寫明的結案步驟」：手冊寫「推之前」的，排在推的前一步。

## 混沌推導

▸ 網路：推、問 GitHub 失敗 → 照講「推不上去／問不到 GitHub」，不說推上去了。app 的「跟上 main」今天抓 GitHub 失敗（10/30 也一次）——主任不靠它，用本機的 git。
▸ 併發：兩個對話同時收尾 → 後到的快轉不了（main 多了別人的存檔）→ AC-2 停下來問；同時推 → GitHub 拒收後到的 → AC-3 停。兩個對話搶到同一個版本號 → 測試會紅（既有的檢查）→ 蓋章那一步停。
▸ 時間：收尾做到一半被中斷（用量上限、你按停）→ 做了的就是做了（白板照 git 講）；下次叫主任，它照白板重新合成問題，舊的那句話照 AC-6 不能再拿來做同一步。
▸ 權限憑證：GitHub 要重新登入、金鑰過期 → 推失敗，照 git 的原文講（不印密碼、token）、停；主任不碰登入。背景服務沒裝 → 重啟那一步照講「沒裝背景服務」。
▸ 輸入畸形：你的原話很長 → 只比對感測器記的前 200 字（跟 `--decide` 一樣，回報講明）。

## 明確不做

- 不按結案（那是你的）；不替別的對話、別的專案收尾，也不轉話給別的對話。
- 不做真的合併、rebase、reset、force push——只走快轉與一般的推。
- 不在你回答之前做任何一步；同一句話不拿來把同一步做第二次。
- 儀表板不加按鈕、不加新的一區；收尾每一步的結果講在對話裡，不寫回規格檔（存檔之後再寫，就是「蓋章之後又改了」）。
- 不去抓 GitHub 上自動測試的結果（這台看不到，照講）。
- 不改 D 要不要再跑的規則（〈D多輪先問人〉照舊）；直接叫 `--checkpoint` 的那條路照舊——收尾一律走 `--wrap stamp`。
