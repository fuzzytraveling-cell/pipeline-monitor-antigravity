## 這是為了解決什麼

人看的字換成英文之後，Claude 那一側還是中文：英文使用者叫不到技能；Claude 轉述的時候可能翻錯（「跑過」轉述成 passed）；
Claude 用英文寫的規格與驗收回報，儀表板讀不懂——讀不懂的時候它不報錯，只是安靜地少畫一格。

## 白話

牆上的公告換成英文了，工班之間傳的紙條還是中文：英文的工頭看不懂，照著轉述給屋主時還可能翻得太好聽；
工頭用英文寫回來的回報，辦公室又看不懂，直接丟進抽屜——沒有人會發現少了一張。

## 驗收條件

**AC-1　英文使用者用英文說，叫得到五支技能；選 plugin 的時候看得懂它做什麼**
> **白話**：門牌要有英文，客人才知道該敲哪一扇門。
> **會發生的情況**：五支技能的說明中英兩段，使用者會說的話兩種都列（「幫我寫規格」／write a spec、「打掃一下」／clean up、「魔鬼教官」／chaos check、「驗收一下」／walk through it、
> 「幫我設定分級」／set up tiers、「這個專案不用分級」／this project doesn't need tiers…）；`argument-hint`、plugin 的說明（`.claude-plugin/plugin.json`）也是中英兩段——
> plugin 說明裡「你說的話的前 200 字」，英文寫 characters、不寫 words（R3）。
> 實際叫一次：開一個英文的新對話說「write a spec for …」，Claude 叫的是 spec 這一支（只試這一支；另外四支看說明裡有沒有英文的觸發句——每支都開新對話試會多用不少，估的）。
> **技術**：技能本文照舊一份中文（你讀得懂、Claude 也讀得懂），只有說明是中英兩段。測試：每一支的說明都有英文的觸發句（P4：必須抓到只有中文的說明；必須放過中英都有的）。

**AC-2　Claude 用使用者講的語言回；講英文的時候，紅線那幾個字照用語對照**
> **白話**：工頭轉述的時候，用的是對照表上的字，不是自己挑好聽的。
> **會發生的情況**：五支技能各加一段：回覆用使用者講的語言；技能裡引號裡的中文是意思，不是要照抄的字；講英文的時候照用語對照（不說 passed、works、all clear、not run…），
> 三條通用判準也有英文那一份。魔鬼教官英文的結論是「didn't match any known failure pattern」，不是 passed、all clear、no problems；
> E 只說走過一遍（固定結尾「This is a walk-through, not an acceptance.」），不說 verified、accepted。
> 實際試一次：英文的對話叫一次魔鬼教官（它最容易講成 passed），看它的回覆與記給儀表板的結論。
> **技術**：技能裡的那張對照表是第二份——跟 lib 的那一份由測試逐字對（P2 的規則：兩份就要有測試真的對兩邊），標 P2。寫規格那一支的最小格式中英各一份，放在一起。

**AC-3　Claude 用英文寫的規格與回報，儀表板與收工 hook 讀得懂；中文的照舊**
> **白話**：辦公室兩種語言的回報都收；收不懂的照實說收不懂，不丟進抽屜。
> **會發生的情況**：上面那張表的前四種，用英文寫各造一份：A 那格、清單、白話、E 那一格、收工 hook 要不要求對清單，跟中文寫的同一份內容一樣（除了字）。
> 同一個專案兩套資料夾都有，兩套都認。認不得的寫法照舊講讀不懂、附開頭的原文，不講成沒有（R1）。
> **技術**：三種狀態的資料夾名、白話那一行的標籤、E 的三種結果，中英並排放在一個地方（跟用語對照同一支），讀的那幾處都從那裡拿——不准再各寫一份正則（P2）。
> P4：E 的 not seen 要比 seen 先比；必須放過 `AC-2 seen: "…was not seen before…"` 這種原文裡剛好有那幾個字的。

**AC-4　技能寫在哪一套資料夾：專案裡已經有哪一套就用哪一套；都沒有，才照使用者講的語言建**
> **白話**：店裡已經用中文標籤的架子，不會因為來了一個英文客人就另開一排英文架。
> **會發生的情況**：你的專案都已經有 `docs/規劃中/`，用英文講也照舊寫進去；全新的專案用英文講，建 `docs/planned/`。
> 搬家（規劃中 → 進行中 → 升級摘要；planned → in-progress → done）照同一套。這個專案自己（CLAUDE.md 那張表、`docsIndex` 測試）照舊中文那一套。
> **技術**：寫規格那一支照它第一步的 `ls` 看；其他幾支照 `--round` 印的路徑。

**AC-5　Claude 讀的字跟著語言設定換：收工 hook、對話開始那一行、Claude 替你跑的指令**
> **白話**：紙條也換成工頭看得懂的語言；紙條上叫屋主說的那句話，也用屋主講的語言。
> **會發生的情況**：設成英文：收工 hook 擋下來的那段、對話開始那一行提醒（叫你說的兩句是 set up tiers／this project doesn't need tiers）、
> `--round`、`--report`、`--decide`、`--spec`、`--suggest`、`--tier-init`／`off`／`review`／`checked`／`later` 印的都是英文，過「儀表板與終端機中英切換」AC-3 那條「一個中文字都不剩」（資料除外）；
> 中文的時候跟改之前一字不差（照那一份 AC-2 的做法）。技能裡照那些指令的字寫的地方——verify 的「它說／你怎麼做」那張表、tier-setup 找「分級」那一段、chaos-check 的分路——兩種都寫上，或改成不靠字面。
> **技術**：`remind.sh` 用 jq 讀同一個設定檔（它本來就靠 jq；沒有 jq 照舊安靜），照舊最多一行、只在對話開始。`gate.mjs` 從入口讀一次。
> 在自己產生的中文句子上切字的地方（`cliReport` 的 `/走了一遍/`）英文要整句寫。

**AC-6　英文的紅線：收工 hook 與 Claude 替你跑的指令也照用語對照，測試釘英文那一份**
> **白話**：紙條上最容易寫得太好聽的那幾句，各考一題。
> **會發生的情況**：gate、rerun、verify 測試現在釘著中文說法的紅線題，英文各補一份：「不用再走」不是「驗收過了」（no need to walk through again ≠ accepted，不准記成 `--clear`）；
> 驗收過了只有使用者能說；D 第二輪以上先問人，不叫 Claude 自己再跑；收工 hook 叫 Claude 停下來先跑那一關，不寫成 failed。
> **技術**：同「儀表板與終端機中英切換」AC-5：「不准」的字只查那一句；每段標它釘的 P 代號。

## 混沌推導

▸ **輸入畸形**：一份規格中英混著寫（資料夾是中文、白話那行寫英文）→ 都認。英文的回報沒照格式（「AC-1 saw it」）→ 照舊講對不上的那幾條、附原文，不講成沒有。
▸ **併發**：同一個專案兩個人，一個講中文、一個講英文 → 第一份規格決定用哪一套資料夾，之後照「已經有哪一套就用哪一套」；兩套都在也都認。
▸ **時間**：plugin 是捷徑指向主資料夾——併進 main，技能與收工 hook 下一個對話就換；儀表板服務要 `--serve-restart` 才認得英文的格式，在那之前英文寫的規格照舊少一格（施作紀錄寫一句）。

## 明確不做

- 不翻技能本文：一份中文就好（你讀得懂、Claude 也讀得懂）；中英兩份的只有說明、`argument-hint`、對照表、寫規格那一支的最小格式。
- **不寫英文 README**：第 3 段要把 README 整份重寫給陌生人看（安裝會變成一句話安裝，只對你成立的那幾行要拿掉），現在翻，第 3 段就要再翻一次；第 3 段寫的時候中英一起寫。
  ROADMAP 第 2 段列了 README——Oscar 10/29 點頭了這一條，結案時把它移到第 3 段那一列。
- 不改這個專案自己的資料夾名與 CLAUDE.md 那張表（照舊中文）。
- 不翻 `docs/` 的規格、教訓、FAILURE-PATTERNS：那是這個專案自己的；英文使用者的專案有自己的，沒有就用三條通用判準（AC-2 的英文那一份）。
- 不改 `hook.sh`、`hooks/hooks.json`；不改技能做什麼、五關怎麼認——只換語言。

## 建議怎麼做

「儀表板與終端機中英切換」結案之後開工，一段做完。用量（估的）：比前一份小——主要是五支技能的說明與對照表、四種格式、收工 hook 與 Claude 跑的那幾個指令的字；
AC-1、AC-2 各要開一個英文的新對話實際試一次。
