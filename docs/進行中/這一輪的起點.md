## 這是為了解決什麼

Claude 收工前先存檔（`git commit`），工具就把「這一輪改過的東西」講成「沒有改動」：分級卡寫「沒有改動」、收工 hook 放行（該擋的 A／C／D／測試檔一個都不要求）、
你自己調高的等級消失；同一個存檔動作，D 魔鬼教官那格卻反過來變成「之後又改了程式檔——要再跑一次」。**一邊說沒動、一邊說又動了，兩邊都不是事實。**

**根源只有一個**：沒有還原點時，「這次改動」的基準是「上一次存檔」（`HEAD`）——存檔一次基準就往前跳一格，這一輪做的事全部落到基準後面去。
這是老毛病 P1（`git diff HEAD` 看不到存檔過的改動）＋ P5（差 0 個檔案，被讀成「沒動過」，其實是「動過的都進去了」）＋ P2（五關 B 已經會翻存檔紀錄補檔案，分級跟收工 hook 沒有）。

**實測（2026-09-22，假專案重現，腳本沒進 repo）**——同一個場景，Claude 什麼都沒再改、只做了 `git commit`：

| | 存檔之前 | 存檔之後 |
|---|---|---|
| 沒章、碰到危險清單、D 說沒問題 | 分級 T2；D 結案；收工 hook 擋（缺 C、測試檔） | 分級「沒有改動」；**D 變「之後又改了程式檔」**；**收工 hook 放行** |
| 有章（章指向存檔之前的版本） | 同上 | 分級 T2、收工 hook 照擋；**D 一樣變假過期** |
| 沒章、只碰程式區（T1）、你說 T2 | 「機器算 T1，你說 T2」；收工 hook 擋（缺 D） | 「沒有改動」；**你說的 T2 不見了**；放行 |

## 白話

- 存檔只是把東西放進保險箱，**不是這件事做完了**。工頭下班前看的是「今天動了什麼」，不是「抽屜裡還有什麼沒收」。
- 一輪從哪裡開始，五關早就有答案（你點頭開工的 A、上次蓋章、Claude 說照哪份規格施工）——這份規格只是讓分級跟收工 hook**也用那個答案**，不再各自拿「上一次存檔」當起點。
- 「這一輪改了什麼」跟「還有什麼沒存」是兩個問題。前者從起點算、含已存檔的；後者照舊，每個檔案標「還沒存」。

## 三個決定（要你點頭）

1. **沒章時「這次改動」的基準 = 這一輪開始那一刻的版本**（不是上一次存檔）。有章時不變，還是比章。
2. **起點怎麼認：跟五關同一個分界**（A、蓋章、規格連結，取最晚的）；**三個都沒有時，新加一條退路：這個對話在這個工作區的第一句話**。
   Oscar 2026-09-21 定的「一輪 = 到下一次 A 或蓋章」不動，只補「兩者都沒有」的那一格（T1 小修的對話就是這種）。
3. **存檔的時間不算改檔時間**——D多輪先問人 AC-9 已經定了，這裡不重寫；這份規格補它做不到的那一半：**存檔過的檔案要留在清單裡**，才有檔案可以看修改時間。

> **技術**：`buildTier` 吃的 `health.list` 改從起點算（AC-2）。`manualTier` 沒章時的過期條件從「`head` 換了」改成「記的時間早於這一輪的起點」（有章時照舊：蓋章之後歸零）。
> `gate.test.mjs` 加一段「存檔之後再問一次 → 還是擋、缺的一樣」，標 **P5**；`tier.test.mjs` 加「存檔之後等級與你說的都在」。

**AC-2　「這次改了哪些檔案」只有一張單子，四處拿同一張** ✅ 對過 2026-09-22
> **白話**：看板、工頭、分級卡、改動體檢，同一時刻對同一個問題只准有一個答案。
> **會發生的情況**：五關 B 的證據、分級的檔案清單、收工 hook 判「碰到什麼」的清單、改動體檢的檔案數——存檔前後、有章沒章，四處講的都是同一份（差一個檔都算錯）。
> **技術**：`changeHealth(cwd, since)` 的 `since` 從「有章比章、沒章比 HEAD」改成「有章比章、沒章比起點的版本、起點問不到才比 HEAD（AC-4）」。
> 決定 `since` 的地方現在有兩處各算一次（`status.mjs` 的 `gatherChange`、`lib/collect.mjs` 的 `buildCard`）——合成一個函式住進 `lib/`，兩邊只呼叫（**P2**）。
> `gitCodeChanges` 裡「翻存檔紀錄補檔案、時間用存檔時間」那條路**拿掉**：起點的 diff 已經含存檔過的檔。`specLink.test.mjs` 那段「存檔時間寫在連結之後兩秒」改釘新算法。

**AC-3　起點怎麼認：A、蓋章、規格連結；都沒有，就是你在這個對話講的第一句話** ✅ 對過 2026-09-22（Oscar 同意三處不一樣：共用資料夾一份分級、規格連結不當起點、起點用這個對話在這裡的第一筆紀錄）
> **白話**：一輪從「你點頭開工」「上次蓋章」或「Claude 說照這份規格做」開始；一件小事沒有這三樣，就從你開口那一刻算。
> **會發生的情況**：T1 小修（沒 A、沒章、沒連結）→ 起點是這個對話在這個工作區的第一句話，存幾次檔都從那裡算。
> 工作區的卡沒有對話代號：蓋章之後只有一個對話在動 → 用它的第一句話；不只一個 → 用**最早開口**的那個對話的第一句話，並明講「含 N 個對話的改動，從最早開口的那個算起」
> （改動只會看起來更大、不會漏；專案卡講的本來就是這個資料夾的事。Oscar 2026-09-22：平常看對話頁，這條少出現，但出現時不退回只看還沒存檔的）。
> **技術**：起點的**時間**沿用 `roundOf`（A／蓋章）與連結時間（`round.link.ts`，施工對話認規格已把它當 git 的起點），只加第四個退路：對話層級（`sessionView`、收工 hook）用這個 `session` 在這個 `cwd` 的第一筆 `UserPromptSubmit`；
> 工作區層級：蓋章之後在這個 `cwd` 動過的對話裡，取**最早**的那筆 `UserPromptSubmit`（只有一個對話時就等於 `specContext` 認的那個）。起點的**版本**：reflog 裡時間早於起點的最新一筆（`git reflog show --date=iso-strict --format='%H %gd' HEAD`；每個 worktree 有自己的 reflog，app 開的 worktree 建立那一刻就有一筆，實測拿得到）。
> 收工 hook 現在拿工作區層級的 `card.tier`——改成用**這個對話**的起點算（`cardFor` 帶 `session`），不然共用工作區時 hook 跟對話頁講兩句話（P2）。

**AC-4　找不到起點的版本、或它已經不在這條分支上 → 明講，退回只看還沒存檔的；不准說「沒有改動」** ✅ 對過 2026-09-22
> **白話**：找不到「當時的版本」就說找不到，不能裝作沒動過。
> **會發生的情況**：reflog 空的、過期、被關掉；或起點之後改寫過歷史（rebase）→ 分級卡與改動體檢寫「找不到這一輪開始時的版本，這裡只看還沒存檔的；存檔過的看不到」；
> 還沒存檔的也沒有 → 寫「還沒存檔的改動：沒有；這一輪存檔過的看不到（找不到起點的版本）」——**不是「沒有改動」那張安全的綠臉**。收工 hook 照這份算（可能放行，但畫面講了為什麼）。
> **技術**：起點的版本跟章用同一個判斷（`checkpointRelation`：gone／off-branch／unknown 都算不能用）。`buildTier` 的 `no-change` 要分兩張臉：「從起點算，真的沒有」vs「退回 HEAD，還沒存檔的沒有」（**P5**：差 0 有兩種意思）。

**AC-5　每個數字旁邊寫「從哪裡算起」** ✅ 對過 2026-09-22
> **白話**：看的人要知道這個數字涵蓋什麼，才知道該不該擔心。
> **會發生的情況**：改動體檢的標題三選一：「蓋章之後的改動」／「這一輪的改動（從 N 分鐘前那一輪開始的版本算起，含已存檔的）」／「還沒存檔的改動（找不到這一輪的起點）」；
> 網頁「未檢查清單」的小標同三種；每個檔案照舊標「還沒存」，所以「這一輪改了 5 個、其中 2 個還沒存」一眼看得出。
> **技術**：終端機 `render()`、網頁 `statChanges`、收工 hook 的理由——三處一份文案模板。時間只准從紀錄（起點事件）或 reflog 來（R3）。

**AC-6　存檔不是改檔：存檔過的檔案，改檔時間看檔案本身** ✅ 對過 2026-09-22
> **白話**：文件放進保險箱的時間，不是寫文件的時間。
> **會發生的情況**：D 說沒問題之後 Claude 只存檔 → 儀表板、終端機、收工 hook 三處 D 都還是結案（這句是 D多輪先問人 AC-9 的，這裡只確認它成立）；B 的「最後一次改檔 N 分鐘前」在存檔之後不會跳成「剛剛」。
> **技術**：存檔過的檔案留在起點的 diff 裡，修改時間 `stat` 檔案（跟還沒存檔的同一種算法）。存檔裡**刪掉**的檔沒有檔案可看 → 沒有時間就沒有，不拿存檔時間頂（跟今天還沒存檔的刪除一樣，沒有時間證據）。

**AC-7　起點那一秒分不出先後的存檔，算進這一輪** ✅ 對過 2026-09-22
> **白話**：分不清是起點前一瞬還是後一瞬存的，就當成這一輪的——改動只會看起來比實際**大**，不會比實際小（小的那一邊才危險）。
> **技術**：起點的版本 = reflog 裡時間**嚴格早於**起點那一秒的最新一筆（感測器的時間只到秒）。B「在動」的證據另有門檻（修改時間 ≥ 起點才算），不會因此誤亮。
> 跟 `roundView` 現在「跟連結同一秒的存檔不算證據」方向相反——那條管的是 B 亮不亮，這條管的是分級；那條路拿掉之後（AC-2）只剩這一條。

**AC-8　有章的專案、零 commit 的專案，什麼都不變** ✅ 對過 2026-09-22
> **白話**：已經蓋過章的，基準還是章；一個版本都沒有的，還是「沒有基準」。
> **會發生的情況**：章能用 → 改動體檢、分級、收工 hook 跟今天一模一樣（實測表第二列的分級與 hook 本來就對）；零 commit → 還是「沒有基準，先 git commit 一次」。
> **技術**：`since = 章能用 ? 章的 commit : 起點的版本 ?? HEAD`；`no-base` 照舊。分級.md AC-2 的括號改成「（有章比章，沒章比這一輪的起點）」，AC-5 的「沒章時存檔之後歸零」改成「沒章時新的一輪才歸零」，五關自動結案.md AC-1 的「沒章比 HEAD」同步——各改一句，不另抄一份規則。

## 混沌推導（只寫有觸發的）

▸ **時間**：三台鐘——感測器只到秒、CLI 記到毫秒、reflog 是秒＋本地時差。全部轉成同一個鐘再比（魔鬼教官 2026-09-16 第四次抓過的坑）；誤差沿用 `gate.mjs` 現有的 2 秒，不新訂門檻。
▸ **併發**：兩個對話同一個工作區 → 工作區的卡從最早開口的算起、明講含 N 個對話（AC-3）；收工 hook 與對話頁按各自的對話算，互不影響。
▸ **權限／失敗**：reflog 讀不到、git 失敗 → AC-4 的臉；收工 hook 一律放行（契約 1 不變），壞掉記 `gate_broken`。
▸ **容量**：reflog 從最新往回讀，讀到第一筆早於起點就停，不讀整份。起點很久以前的 diff 可能很大——章的 diff 一樣會遇到，不另設上限。
▸ **輸入畸形**：reflog 某一行的時間讀不出來 → 跳過那一行（看不懂不等於比較早）；起點事件本身時間讀不出來 → 當成沒有起點（AC-4）。

## 明確不做

- 不改「一輪」的定義（Oscar 2026-09-21：到下一次 A 或蓋章）；只補「兩者都沒有」的退路。
- 不改有章時的基準。章之後又跑了 A，分級仍從章算、五關 B 從 A 算——現況如此，這次不動（要動另開規格）。
- 不拿存檔時間當任何「改檔」的時間（D多輪先問人 AC-9 的決定，這裡不重寫、不推翻）。
- 不做「存檔就自動蓋章」、不把存檔當一輪的分界（`lib/events.mjs` 開頭那段理由還在：D 通常在存檔之前跑）。
- 不擋 commit、不進 CI（ROADMAP 的明確不做）。
- 不回頭重算過去對話的分級。
