# 功能：施工對話認規格 —— 規格在別的對話寫、另開對話施工，儀表板與收工 hook 也要認得那份規格

分級：**預測至少 T2**（會碰到危險清單的 `lib/events.mjs`；另會動 `lib/tier.mjs`、`lib/collect.mjs`、`status.mjs`、`ui/app.js`、`gate.mjs`、`scripts/` 的測試）。
⚠️ `gate.mjs` 不在程式區，T2 只靠 `lib/events.mjs` 撐著；施工時沒動到它的話要照實重算。這一攤要齊：這份規格、C、D、這次要有測試檔。

## 這是為了解決什麼

五關自動結案假設「寫規格跟施工在同一個對話」，但你的做法是一個對話寫規格、點頭後另開對話施工。施工的對話看不到清單、B 不照清單結案、T2 的收工 hook 還叫它重跑 A。

**開工前提**：`docs/進行中/` 已滿（上限 2 份）。app 建議卡實測完搬走、或你決定先把 pipeline-ui 移出，才開得了工。**建議先做這份、再做「D 多輪先問人」**——不然那份的施工對話會被逼重跑 A。

## 驗收條件

**AC-1　Claude 說「照這份規格施工」，儀表板就畫出那份清單**
> **白話**：工班拿著建築師前天畫的圖來施工，看板上照樣貼著那張圖的驗收單，而且寫明是工班說照這張。
> **會發生的情況**：施工對話的 A 顯示「已走過：照別的對話寫的規格 app建議卡（Claude 說的）」加上那份的每條 AC 與勾；B 顯示「清單 4/7 對過」，對完才劃掉（五關 AC-6 照舊）。
> **技術**：新指令 `pipeline-status --spec <規格檔>`，事件 `spec_link`。連結**不是** A 的一次呼叫：不移動一輪的開始、不參加「現在這一關」的排序、不算「你點頭開工」；A 那格固定畫成「已走過」。

**AC-2　連結只算記它的那一個對話，而且跟這一輪一起到期**
> **白話**：工班說照哪張圖，只算他自己那一隊；隔壁隊不會被套上這張單子；換下一件工作，單子就收掉。
> **會發生的情況**：主資料夾同時開兩個對話，甲記了 `--spec`，乙只調一個小地方 → 乙**不會**被要求照甲的清單打勾。兩週後在同一個資料夾開新對話 → 舊連結不算。
> **技術**：CLI 沒有對話代號——讀取端把連結歸給「記它的那一刻，這個工作區正在動的那一個對話」；同時有別的對話在動 → 不歸給任何人，畫面寫「分不出是哪個對話記的」，不擋人。下一次 A 或蓋章之後失效。分級卡、五關、收工 hook 用同一份按對話算的結果（P2）。

**AC-3　第一句話提到規格，只當提示，不算數**
> **白話**：你交代時順口提到一張圖，看板寫「可能是這張」，但不會照它驗收。
> **會發生的情況**：第一句話提到**剛好一份** `docs/規劃中/` 或 `docs/進行中/` 的規格、而 Claude 還沒記 `--spec` → A 寫「從你第一句話看，可能是照 X 施工（Claude 還沒確認）」，**不畫清單、不擋人、不算 A**。
> 要算數，Claude 要跑 `--spec X`；不是的話跑 `--spec 無`，提示就消失。
> **技術**：用感測器記的第一句話（前 200 字）。提到兩份以上 → 不提示。⚠️ 用 app 建議卡「Start」開的對話，說明的開頭通常沒有規格路徑（實測），多半沒有提示——那是照實，不是壞了。
> 例子：必須提示「照 docs/規劃中/app建議卡.md 開工。先讀 docs/升級摘要/pipeline-sensor.md 的 AC」（升級摘要是參考，不算）；必須放過「先讀 docs/進行中/五關自動結案.md 與 docs/規劃中/E自動驗收.md」（兩份）。

**AC-4　`--spec` 只收得下「還沒做完的規格」**
> **白話**：只有等點頭或施工中的圖才能拿來施工；已經結案的圖、筆記、自己剛剛隨手畫的，都不算。
> **會發生的情況**：`--spec docs/升級摘要/…`、`--spec docs/LESSONS.md`、讀不出任何一條 AC 的檔、**這個對話自己剛寫出來的檔** → 回一句白話的錯誤、不記。
> **技術**：只收這個工作區 `docs/規劃中/` 或 `docs/進行中/` 的 `.md`，且 `lib/checklist.mjs` 解析得出 AC；感測器記到這個對話 Write 過同一個路徑 → 拒絕（那是 A 的工作，要跑 A）。

**AC-5　這一輪跑過 A，就不往別處猜；另寫一份新規格，也不換掉施工清單**
> **白話**：建築師在現場畫的圖比轉述的準；工班施工到一半順手畫了下一件的草圖，手上的驗收單不會被換掉。
> **會發生的情況**：
> ① 這一輪有 A、但連不到它寫的檔 → 照舊說「找不到這一輪的規格檔」，不退到第一句話。
> ② 已經連到 app建議卡、這個對話又叫 A 寫了 D多輪 → A 顯示「另寫了一份規格 D多輪（等你點頭）」；施工清單還是 app建議卡、不算你點頭、不重算這一輪（今天這個對話就是這樣）。
> **技術**：有 `spec_link` 且 A 寫的是別份 → 不移動 `roundStartOf`；沒有連結時 A 的行為照舊（五關 AC-4、AC-5）。

**AC-6　規格搬家了也找得到；只在主資料夾找到的，不叫 Claude 去那裡打勾**
> **白話**：圖從「等點頭」的櫃子搬到「施工中」，工班照樣找得到；但圖只在總部、工地沒有，看板只寫「圖在總部」，不叫工班跑去總部塗改。
> **會發生的情況**：記的是 `docs/規劃中/X.md`、開工後搬到 `docs/進行中/X.md` → 照樣讀到。工作區找不到、主資料夾有 → 寫「規格在主資料夾，不在這個工作區（可能還沒併進來）」，不擋人。都找不到 → 「找不到規格檔 X.md」，不寫「沒有清單」（R1）。
> **技術**：路徑相對這個對話的工作區；在工作區的 `規劃中／進行中／升級摘要` 找同名檔，找到就停；工作區裡同名不只一份才說分不出來。

**AC-7　T2 有連到規格，收工 hook 就不叫重跑 A；連不到才告訴 Claude 兩條路**
> **白話**：圖已經有了，工頭不叫建築師重畫；沒說照哪張圖，工頭問一句「照哪張？還是真的要畫新的？」
> **會發生的情況**：有連結 → 不列 A；分級卡寫「規格是別的對話寫的：X（Claude 說的）」。沒連結 → 那一行改成「A 寫規格：這一輪還沒跑。照別的對話寫好的規格施工的話跑 `pipeline-status --spec <規格檔>`；還沒有規格才跑 /pipeline-monitor:spec」。
> **技術**：`gate.mjs` 與 `lib/tier.mjs` 用 AC-2 的同一份結果，另開一個欄位，不借 A 的 `ranAt`。

**AC-8　一份規格分幾批做，只要求這一批的 AC**
> **白話**：一張大圖分好幾週蓋，這週只驗這週蓋的那幾間。
> **會發生的情況**：`--spec docs/進行中/pipeline-ui.md AC-1 AC-2` → 收工 hook 只要求標 AC-1、AC-2；A 仍畫整份，其他條標「不在這一批」。沒給就是整份。
> **技術**：`spec_link` 帶 `acs`；五關 AC-6 的「沒標就擋」只數這幾條。

## 混沌推導（只寫有觸發的）

▸ **容量**：感測器只記第一句話的前 200 字；你先打一行命名、再列兩三份參考，規格路徑就在 200 字之後 → 沒有提示，照實。
▸ **時間**：紀錄超過 90 天被輪替 → 連結沒了 → A 照實「這一輪還沒跑」。
▸ **併發**：AC-2。工作區共用時寧可不歸屬、不擋，也不把清單套到別的對話上。
▸ **輸入畸形**：AC-4；規格檔沒照格式 → `--spec` 拒收（讀不出 AC），不假裝連上。

## 明確不做

- 不讀 Claude Code 的對話紀錄檔找規格；不用檔名相似度猜。
- 不把第一句話認到的當證據（只提示）。
- 不改「同一個對話跑 A、A 寫出的那份」在**沒有連結**時的認法。
- 不自動搬規格檔、不替你打勾、不在儀表板加「指定規格」的按鈕（只有 E 有按鈕）。
