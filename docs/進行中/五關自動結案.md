分級：**預測至少 T2**（會碰到危險清單的 `hooks/hooks.json`、`lib/events.mjs`；另會動 `stages.json`、`lib/collect.mjs`、`lib/tier.mjs`、`status.mjs`、`ui/app.js`、
三支 `skills/*/SKILL.md`、新的收工 hook 一支、`scripts/` 的測試）。所以這一攤要齊三樣：這份規格、D 魔鬼教官、這次要有測試檔。

> 但多了那麼多步驟難免會遺漏，我要讓使用者清楚知道目前做到哪，不用一直往前捲動對話找線索。」

## 這是為了解決什麼

儀表板現在只記「叫過」，結案要人按按鈕，分級只標紅不驅動。結果是三個缺口：B 寫程式從來不亮；D 跑完還是「還沒有人說處理完了」；
分級算出「這次要 D」之後沒有人會去跑，Claude 在對話裡根本不知道這次是 T1 還 T2。Oscar 要的是**看一眼就知道做到哪**。

## 四個決定（2026-09-16 Oscar）

1. **「Claude 說結案」可以**，儀表板明寫是 Claude 說的；只有 E 是「你說」。這是 R2 在這個設計裡的位置：驗屋師傅來過不等於房子修好了，但「師傅說修好了」可以寫，寫清楚是他說的。
2. **收工 hook 做**：Claude 準備收工時，該跑的關沒跑就擋一次，叫它先跑。
3. **每一級會跑哪幾關**照下表；T1 不強制 A；C 在 T1 以上每輪列建議，做不做人決定。
4. **AC 的勾寫在規格檔本身**，由 Claude 編輯檔案，儀表板讀檔案。檔案只有一份，不會兩個地方各說各話（P2）。

| 分級 | 什麼時候 | 會跑 |
|---|---|---|
| T0 | 沒碰程式區 | 只有 B |
| T1 | 碰到程式區 | B → C 列建議 → D → E 你驗收（A 不強制，有就啟動清單） |
| T2 | 碰到危險清單 | A → B → C → D → 這一輪要動到測試檔 → E |

## 驗收條件

**AC-1　分級真的決定會跑哪幾關：該跑的沒跑，Claude 不准收工**
> **白話**：工頭下班前看一眼今天的工單，該驗的沒驗就不准走。
> **會發生的情況**：Claude 寫完程式想收工；這次碰到程式區、而 D 還沒在最後一次改檔之後跑過 → 對話裡出現一句白話的理由
> 「這次改動至少 T1，D 魔鬼教官還沒跑，先跑再收工」，Claude 接著跑 D。T2 還會要求 A 有規格、這一輪動到測試檔。都跑過了就安靜放行。
> **技術**：`hooks/hooks.json` 加 `Stop` → 新的一支 `gate.mjs`（node；一回合一次，不是熱路徑）。「該跑的」照 `stages.json` 的 `tierLevels`（AC-2）。
> 「這次改了什麼」用 git，基準跟儀表板同一份（有章比章、沒章比 HEAD）；「跑過了沒」看這個對話的紀錄，而且要在**最後一次改程式檔之後**
> （時間取兩種證據較新者：感測器的改檔事件、git 說有改動的檔案的修改時間——用 Bash 寫檔會繞過 hook，L8）。
> `stop_hook_active` 為 true 就放行（官方防迴圈）；同一個 prompt 最多擋一次（記號檔）；只在這一回合有改程式檔時才擋，回答問題的回合安靜；
> 任何錯誤一律放行、`exit 0`，不准因為 hook 壞了讓人下不了班。

**AC-2　「該跑的關」是一份清單，住在 `stages.json`，專案可以換**
> **白話**：工單的內容寫在一張紙上，不寫在工頭腦子裡。
> **會發生的情況**：預設 T0 不要求、T1 要求 C 與 D、T2 要求 A、C、D、測試檔；專案的 `.claude/pipeline-stages.json` 可用 `tiers.levels` 覆寫。E 永遠不在清單裡，它是人的。
> **技術**：改 `stages.json` 的 `tierLevels`；`lib/tier.mjs` 的 `requirementStatus` 已支援任意關卡代號。

**AC-3　B 有燈：改檔案就亮，而且印出最後一次改檔的時間**
> **白話**：工班在動就亮燈，還要寫幾點最後一次動。
> **會發生的情況**：這一輪 A 之後有改檔案 → B 顯示「最後一次改檔案 N 分鐘前」並亮燈；改檔案是最新的動作時，B 就是「現在這一關」。
> **技術**：`roundView` 把有 `file` 的事件當 B 的活動。**不用 hook 算檔案數**（CLAUDE.md：檔案數量一律 git），只印時間；「改了什麼」指向未檢查清單那張卡。

**AC-4　A 自動結案：你點頭開工，A 就劃掉**
> **白話**：圖畫好了、你說開工，建築師那關就完成，不用另外按。
> **會發生的情況**：A 跑過之後，第一次改到**程式區**的檔案 → A 變「已走過」；只改 docs/ 不算開工。
> **技術**：`roundView`：A 之後第一筆落在程式區的改檔事件。A 自己寫規格檔的 Write 在 docs/，不算。

**AC-5　A 的清單就是規格檔裡的 AC，勾也打在檔案上**
> **白話**：驗收單就是那張紙，打勾直接打在紙上，看板照著紙畫。
> **會發生的情況**：儀表板 A 底下列出這一輪規格檔的每條 AC（標題＋白話那一行）；Claude 對完清單後在檔案裡標「✅ 對過 <日期>」或「⏳ 待討論：<原因>」；
> 儀表板讀到就畫勾或問號，沒標的就是空的；新加的 AC 往下累積。
> **技術**：`skills/spec/SKILL.md` 的最小格式加上狀態標記的約定（AC 標題行末尾）；讀取端解析，**解析不了就整段原文顯示，不假裝解析成功**（R1）。
> 「這一輪的規格檔是哪一份」：A 那一筆紀錄同一個 `prompt_id` 之後第一個寫到 docs/ 的 `.md`（感測器有 `file` 與 `prompt_id`）；連不到就顯示「找不到這一輪的規格檔」。

**AC-6　B 自動結案：Claude 對完清單**
> **白話**：工班說「圖上每條都對過了」，這關就完成；沒對完的留著，看板寫「a5 待討論」。
> **會發生的情況**：B 之後 Claude 在規格檔標完每條 AC → B 劃掉；有「⏳」的，儀表板顯示「還有 1 條待討論」，B 不劃掉。**沒有 A 的輪次**：C 或 D 開始就算 B 結案。
> **技術**：收工 hook：B 有改動且清單有沒標的 AC → 擋一次「先對清單」。

**AC-7　C 每輪列建議，列出來就算結案**
> **白話**：打掃的人把「可以清的東西」列一張單子給你，做不做你決定；單子交了這關就完成。
> **會發生的情況**：T1 以上收工 hook 叫 Claude 跑 C；C 收尾把「N 條建議」記給儀表板；儀表板 C 顯示「Claude 列了 N 條建議，做不做你決定」，劃掉。
> **技術**：`pipeline-status --report C "N 條建議"`（新指令，`source: claude`，事件 `stage_report`）；`skills/cleanup/SKILL.md` 收尾寫這一句。

**AC-8　D 自動結案：Claude 說沒找到、或找到的處理完了**
> **白話**：驗屋師傅交報告：沒問題，或哪裡有問題；修完再請他看一次，說沒問題了才算完。看板寫「師傅說」。
> **會發生的情況**：D 跑完，收尾記「找到 N 條」或「沒找到」；找到 → D 顯示「Claude 說找到 3 條，還沒處理完」並亮；修完再跑 D →「沒找到」→ D 劃掉，標「Claude 說」。
> **技術**：`skills/chaos-check/SKILL.md` 收尾 `--report D`；D 結案 = 最後一次 D 的報告是「沒找到」，且之後沒有再改程式檔（AC-9）。

**AC-9　結案之後又改了程式，結案要退回**
> **白話**：驗過之後又動了工，驗收作廢，要再驗一次。
> **會發生的情況**：D 說沒找到之後 Claude 又改了程式檔 → D 回到「跑過但過期：之後又改了 N 個檔案」，收工 hook 會再要求 D。
> **技術**：報告時間 vs 最後一次改程式檔的時間（AC-1 同一種算法）；「N 個檔案」用 git，跟還原點那句同一種算法。

**AC-10　只有 E 有按鈕**
> **白話**：按鈕只留在最後一關，提醒你親自走一遍；其他按鈕多了會被忽略跳過。
> **會發生的情況**：儀表板 A 到 D 沒有按鈕；E 顯示「開過瀏覽器（N 個動作）」加一顆「你說驗收過了」。
> **技術**：`ui/app.js`；CLI `--clear` 只准 E，其他關回「這關由 Claude 用 --report 記」。

**AC-11　每一個勾旁邊都寫得出是誰說的**
> **白話**：看板上每個勾旁邊都寫「誰說的」。
> **會發生的情況**：A：你點頭（開工了）；B：Claude 對完清單；C：Claude 列了建議；D：Claude 說沒找到；E：你說驗收過了。
> **技術**：`source` 欄位 `claude`／`human`，文案模板一份，終端機與網頁共用。這是 R2。

**AC-12　儀表板還是只顯示，不反向操作對話**
> **白話**：看板可以叫工頭去看它，不能替工頭下指令。
> **技術**：`/api` 不新增任何寫入端點（E 的 clear 與分級的調高照舊）。收工 hook 是對話這一側的事，它讀儀表板的資料，不由儀表板觸發。

## 混沌推導（只寫有觸發的）

▸ **併發**：兩個對話在同一個工作區 → git 的「這一輪改了什麼」是共用的（畫面已經會講共用）；收工 hook 用自己對話的紀錄判斷跑了沒 → 可能叫錯對話跑 D。擋的理由裡講「這個工作區」，並在畫面標「這個工作區有 2 個對話」。
▸ **時間**：Stop 每一回合都觸發，Claude 中途回答一句也算收工 → 只在這一回合有改程式檔時才擋。
▸ **權限**：hook 讀不到紀錄、git 失敗 → 放行，並記一筆故障（跟感測器 AC-1 同一個檔，只當警告，不蓋畫面）。
▸ **輸入畸形**：規格檔沒照格式 → 清單顯示原文；B 的結案退回「C 或 D 開始」。
▸ **容量**：收工 hook 每回合讀紀錄 → 只讀這個工作區、從最後一次蓋章之後；一秒內。

## 明確不做

- 不做「還在跑嗎」的燈（ROADMAP 的核心原則）。
- 不讓儀表板叫 Claude 做事；收工 hook 是 Claude 這一側自己看紀錄。
- 不擋第二次：同一個 prompt 擋過一次就放行，Claude 不聽就讓它走，儀表板標紅。
- 不接 `SubagentStop`：A／C／D 不是 subagent。
- 不猜規格檔是哪一份：連不到就說找不到。

## 施作順序（四批，每批可以獨立驗）

1. `stages.json` 的清單（AC-2）＋收工 hook（AC-1）＋「放行」的測試：壞掉必須放行。
2. B 的燈與 A 的自動結案（AC-3、4）、按鈕只留 E（AC-10）、誰說的（AC-11）。
3. `--report` 與三支 skill 的收尾（AC-7、8、9）。
4. AC 清單讀檔案與打勾（AC-5、6）。
