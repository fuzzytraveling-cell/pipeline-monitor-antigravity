# 功能：`status` —— 一個指令看完「我在哪、我回得去哪、這次動了多少」

分級：**T0**。程式碼住在 repo 外的姊妹資料夾 **`pipeline-monitor/`**。
TutorPod 這邊只多本檔與 SKILL.md 索引一行。**沒有動到 `src/`、`package.json`、任何既有測試。**

> 這是「產線監視器」的 **① 大腦第一版**，涵蓋 [`pipeline-dashboard.md`](../ROADMAP.md)
> 六個死法裡的 **V1／V2／V3／V4／V6**。
> **完全不需要 hook，也不需要感測器**——純 git ＋ 檔案系統推導。
> （V5 線上落差要連網，另開一份；A–E 五關的時間戳要等 [`pipeline-sensor.md`](pipeline-sensor.md)。）

## 這是為了解決什麼

**「程式碼黑盒子的恐懼」的本體，是不知道自己回得去哪裡。**
一個知道自己回得去的人，才敢動手改東西。

⚠️ **git 沒有解決這件事。** 2026-09-09 實測本專案：兩條正在工作的 worktree 分支
**都沒有遠端**；CI 只在 `push` 到 `main` 與 PR 時跑 ⇒ **那些 commit 一個都沒被檢查過**。
就算全推上去，`git log` 也只說「有這 20 個版本」，**不說哪一個是綠的**。

**git 是保險箱，這一份是保險箱裡的標籤。**

## 驗收條件

**AC-1　還原點必須是真的跑過檢查才蓋的章，不是有存檔就算**
> **白話**：在草稿本上寫完一頁，不代表那一頁是對的。**要真的驗算過**才能折角。
> **會發生的情況**：有 20 個存檔點，畫面只指出**真的跑完四項檢查而且全綠**的那一個。
> **技術**：實際執行 `lint`／`test`／`test:unit`／`build` 取結束狀態，全綠才寫下
> `{commit, 分支, worktree, 時間, 哪四項通過}`。**不得**拿「有 commit」當代理指標（R1）。
> ⚠️ **誰來觸發**：現階段由 `status --checkpoint` 明確觸發（要花數十秒，不能每次都跑）。
> 等 [`pipeline-sensor.md`](pipeline-sensor.md) 做好之後，可以改成「感測器看到四項檢查跑完就自動蓋」——
> **那時才會變成你不用記得的事**。這一份先做手動的。

**AC-2　章只代表蓋章的那一刻——之後動過的東西要一起說，包含還沒存檔的**
> **白話**：折角折在「當時那一頁」。你後來又改了三段，折角不會跟著更新。
> 而且**桌上還沒放進保險箱的那疊紙，火災時一樣會燒掉**。
> **會發生的情況**：三行永遠一起出現，不准只出現第一行：
> ```
> 🟢 最後一次四項檢查全綠：3f2da6c（2 小時前）
> ⚠️ 之後有 6 個檔案被改過，這 6 個沒有被檢查過
> ⚠️ 其中 3 個還沒存進保險箱（最舊的改於 1 小時前）
> ```
> **技術**：錨點用 **commit SHA，不要用時間**（時鐘會被調整，commit 不會）。
> 未 commit 的部分要單獨算——**那是 git 也救不回來的**。

**AC-3　要告訴你怎麼回去，而且「會失去什麼」要講在指令前面**
> **白話**：告訴你回得去卻不告訴你怎麼回去，等於沒說。
> 但回去會丟掉還沒存的東西，**這句話必須在指令前面，不是後面**。
> **會發生的情況**：
> ```
> ⚠️ 回去會丟掉你還沒存的 3 個檔案。想留著先打：
>      git stash push -u -m 我的備份
>    確定要回去：
>      git reset --hard 3f2da6c
> ```
> **技術**：指令要能直接複製貼上執行。**R3**——壞掉時要給一條真的做得到的下一步。

**AC-4　從來沒蓋過章的時候，要說「還不知道」，不能說「你沒有能動的版本」**
> **白話**：剛裝好，它還沒看過你驗算任何一頁。那叫「還不知道」，
> **不叫「你沒有一頁是對的」**——後者會嚇到人，而且是假的。
> **會發生的情況**：顯示「還沒有還原點。跑一次 `status --checkpoint` 就會建立第一個」。
> **技術**：章不存在 ≠ 沒有綠過。**A1（已發生 6 次）**＋ **B2 空狀態**。

**AC-5　不准說「確定能動」，只能說「四項檢查全綠」**
> **白話**：**檢查全綠不等於功能正確。** 本專案 v4.15.4 就發生過——
> `commitLesson` 整堂課靜默消失、畫面照跳「Saved!」，**而測試全部是綠的**。
> **會發生的情況**：永遠寫「最後一次四項檢查全綠」，**永遠不准寫「確定能動」**。
> **技術**：**A2（已發生 4 次）**。想要更強的保證要另一種章——「我親自開來用過」（人蓋的），
> 對應五關的 E，**這一份不做**，但版面預留得下第二種章。

**AC-6　蓋章失敗必須大聲——這一條跟感測器刻意相反**
> **白話**：監視器壞掉可以安靜（你不會因此受傷）；
> 但**「我以為我有退路，其實沒有」會在你最需要的時候害到你**。
> **會發生的情況**：寫不進去就當場說章沒蓋成功，不要默默跳過。
> **技術**：與 `pipeline-sensor.md` 的 AC-2（靜默失敗）**故意相反**，判準是 **A9 不對稱代價**。

**AC-7　改動體檢只報數字，不下判斷——而且要拿這個專案自己的歷史當比例尺**
> **白話**：「你改了 12 個檔案」是事實；「你改太多了」是我編的。
> ⚠️ **實測**：這個專案近 30 次改動，**中位數 5 個檔案、最多 18 個**——
> 所以 12 個在這裡**很正常**。我如果自己訂一個門檻，第一天就會開始亂叫，
> 而**一個會亂叫的工具，你三天後就不看了**。
> **會發生的情況**：
> ```
> 這次改動：8 個檔案，+320 −180 行
>            （這個專案平常 5 個檔案，最多到過 18 個）
> 新增相依：0 個
> ```
> 沒有紅字、沒有驚嘆號、沒有「建議你」。**數字跟比例尺放一起，判斷留給你。**
> **技術**：`git diff --stat` 一次呼叫拿到檔案數與增減行數；比例尺從 `git log` 算。
> 新增相依從 `package.json` 的 diff 認。涵蓋 **V2／V3／V6**。

**AC-8　測試「被改」才值得說一句，測試「新增」不是**
> **白話**：寫新功能順便補一個新測試，**那是好事，不該被警告**。
> 值得說一句的是另一種：**原本就存在的測試被動過**——
> 那有可能是程式沒過測試，於是把測試改成配合程式。
> **會發生的情況**：只有在**既有測試檔被修改**時才多印一行事實：
> `⚠️ 這次動到 2 個既有的測試檔`。新增測試檔完全不提。
> **技術**：`git diff --diff-filter=M --name-only` 只取「修改」不取「新增」。
> 涵蓋 **V4**。⚠️ 這一條是為了**不亂叫**而存在的——見 AC-7 的理由。

**AC-9　你要打得出來，這個工具才存在**
> **白話**：一個要你記住「`node ../pipeline-monitor/status.mjs`」才能用的東西，
> 你三天後就不會用了。
> **會發生的情況**：在任何專案資料夾裡打一個短指令就會動，
> 而且**第一次安裝時它自己告訴你那個指令是什麼**。
> **技術**：提供一個安裝步驟（`npm link` 或 shell alias 擇一，B 決定）。
> ⚠️ **不得**要求在 TutorPod 的 `package.json` 加 script——那會動到 TutorPod。

**AC-10　不是 git 專案、或一個 commit 都還沒有，也不能當機**
> **白話**：這是要給任何專案裝的工具，不能假設別人跟你一樣。
> **會發生的情況**：全新的空資料夾、還沒 `git init`、或 detached HEAD →
> 說「這裡看起來不是 git 專案」然後正常結束，**不是拋一堆紅字**。
> **技術**：detached HEAD、零 commit、shallow clone、非 git 目錄一律走 AC-4 的
> 「還不知道」路徑。涵蓋 **AC-8 of `pipeline-sensor.md`**（可攜性）的同一個立場。

## 混沌推導

▸ **時間**：時鐘被調整 → 錨點一律用 commit SHA，時間只用來顯示「多久以前」。
▸ **併發**：三個 worktree 各有各的 HEAD 與分支 → **章必須記下分支與 worktree**，
　在 A 蓋的章不得拿去 B 顯示（顯示錯的比不顯示更糟）。
▸ **權限**：章寫不進去 → AC-6（大聲失敗）。
▸ **輸入畸形**：detached HEAD、零 commit、非 git 目錄、`package.json` 不存在 → AC-10。
▸ **容量**：`git log` 在很大的 repo 上會慢 → 比例尺只取最近 N 次改動，不掃全歷史。

> **網路**未觸發（完全不連 GitHub，只讀本機 git）——這也是 V5 要另開一份的原因。

## 明確不做

- **不去讀 GitHub Actions 的結果。** 實測：CI 只在 `main` 與 PR 上跑，
  你正在工作的分支根本不會有結果——**去讀只會拿到「沒有資料」，然後很想解讀成「沒過」**（A1）。
- **不自動幫你回去、不自動 commit、不自動 push。** 只顯示指令，**按下去的是你**。
- **不自己編任何「太多／太大／太久」的門檻**（AC-7）。
- **不做 V5 線上版本落差**——要連網，混沌推導完全不同，另開一份。
- **不做 A–E 五關的時間戳**——那要感測器，見 [`pipeline-sensor.md`](pipeline-sensor.md)。
- **不做「我親自驗過」的人工章**——留給 E，但版面預留。
- **不進 CI、不擋 commit。** 它是給人看的，不是關卡。
- **不動 TutorPod 的 `package.json`、`src/`、任何既有測試。**
- **不重複造保險箱**——備份是 git 的事，這一份只做標籤。

### 施作時抓到的六個 bug（都已修，值得記）

⚠️ **前三個都是本專案 FAILURE-PATTERNS 的形狀，發生在這支工具自己身上。**

1. **🔴 `import.meta.url === \`file://${process.argv[1]}\`` —— 路徑有空白就永遠 false。**
   使用者路徑是「TutorPod AI」，所以第一次執行**零輸出、零錯誤、離開碼 0**。
   前者是百分號編碼（`%20`），後者不是。**這就是 R1 的形狀：沒壞掉的樣子，但什麼都沒發生。**
   → 改用 `fileURLToPath()` 比對真實路徑。
2. **🔴 `git diff` 看不到還沒被追蹤的新檔案** —— 實測 4 個檔案被報成 2 個。
   **AI 生成最常見的產物就是新檔案**，而漏掉它們會讓改動**看起來比實際小**——
   錯的方向剛好是危險的那一邊。→ 補 `git ls-files --others --exclude-standard`。
3. **🟡 相依偵測靠 diff 的文字比對** —— 假設 `package.json` 一行一個相依。
   壓成一行就**安靜地認不到**。→ 改成解析兩個版本的 JSON 取鍵的差集。
4. **🟡 `--git-common-dir` 在一般 repo 回相對路徑 `.git`**（只有 worktree 回絕對路徑），
   算出來的專案名變成 `.`。→ 先解析成絕對路徑。
5. **🟡 只有 2–3 個 commit 時算出來的「平常改幾個檔案」是雜訊** ——
   卻長得像有依據的基準。→ 樣本 <5 不給比例尺。
6. **🟡 零 commit 的 repo 分支顯示成 `null`** —— 程式的內部值漏到畫面上，
   而讀的人不是工程師。→ 用 `symbolic-ref` 備援，再退回「(還沒有分支)」。
