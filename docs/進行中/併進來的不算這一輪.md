## 這是為了解決什麼

把 main 的新東西拿進這條分支之後，別的對話寫的檔被算成「這個對話這一輪改的」：收工 hook 叫你決定 D 要不要再跑、分級可能被拉高、C 和 D 會去看別的對話的程式。

## 白話

你把隔壁工班已經驗過的幾面牆一起搬進你的工地，監工不該把它們記成你這一輪砌的、再叫你請驗屋師傅重看一次。
可是你自己動過的牆——就算隔壁也動過——照樣記你的；還沒抹完、還沒登記的牆也照記。分不出是誰砌的，就當成你的：多驗一次不會出事，漏驗會。

## 驗收條件

**AC-1　從 main 快轉或合併進來、這個對話沒動過的檔，不算這一輪改的** ✅ 對過 2026-11-03
> **白話**：搬進來的牆不記到你頭上。
> **會發生的情況**：在對話的資料夾跟上 main——快轉（`git merge main`、`git pull`、app 的「跟上 main」）或真的合併（有沒有衝突都一樣）——之後，
> 終端機與儀表板的「這一輪的改動」、分級、五關的 B、收工 hook 都不把 main 帶進來的檔算進去。上面那次實測照這一條：這一輪 0 個檔、分級「沒有改動」、B 不亮。
> **技術**：新的判斷只寫一份（`lib/origin.mjs`），讀這個資料夾自己的移動紀錄（`git rev-parse --git-path logs/HEAD` 那一份，每一行有前後版本），只看這一輪的基準（起點那一刻的版本，或章）之後：
> 說明是「merge …: Fast-forward」「pull…: Fast-forward」→ 前後兩個版本之間改到的檔是「併進來的」；說明是「merge …: Merge made by …」「commit (merge): …」「pull…: Merge made by …」
> → 那個合併存檔帶進來、內容跟另一邊一模一樣的檔是「併進來的」。帶進來的那一邊要在 main 的歷史上（本機的 main／master，或上一次抓到的 origin 那一條）才算——
> 從別條分支（例如還沒結案的另一個對話）併進來的照算，那些可能還沒人檢查過。`changeHealth` 的清單拿掉這些；分級、收工 hook、roundView、`--round`、改動體檢都吃拿掉之後的同一份（P2）。

**AC-2　這個對話自己動過的檔，就算 main 也動過，照樣算** ✅ 對過 2026-11-03
> **白話**：你砌過的牆，隔壁也動過，還是記你的。
> **會發生的情況**：這個對話改了 `lib/a.mjs`（存了檔），main 也改了它；併進來之後 `lib/a.mjs` 照樣在這一輪的清單裡、分級照算。合併時自己解衝突（結果跟兩邊都不一樣）的檔也照算。
> **技術**：「自己動過的」＝ 基準之後每一筆**不是**「併進來」的移動（commit、amend、cherry-pick、rebase、reset、讀不懂的說明，一律當自己的）改到的檔 ∪ 合併存檔裡跟每一邊都不一樣的檔
> ∪ 感測器記到這個對話這一輪改過的檔。拿掉的只有「併進來的」減掉「自己動過的」。

**AC-3　還沒存檔的、還沒被 git 追蹤的新檔，一律照算** ✅ 對過 2026-11-03
> **白話**：還沒抹完、還沒登記的牆，照記你的。
> **會發生的情況**：併完 main 之後又改了 `lib/a.mjs` 沒存、新開了 `lib/b.mjs` 沒加進 git——兩個都在這一輪的清單裡。
> 合併到一半（有衝突、那個合併還沒存）的時候，main 帶進來的東西都還沒存，也照算；那個合併存好之後才拿掉。
> **技術**：「自己動過的」再加上還沒存的（`git diff HEAD`）與還沒追蹤的（`git ls-files --others --exclude-standard`）——P1、L2：`git diff` 看不到新檔。

**AC-4　分不出來就照算，不猜** ✅ 對過 2026-11-03
> **白話**：搞不清楚哪面牆是誰砌的，就當成你的。
> **會發生的情況**：移動紀錄讀不到、被清掉、中間斷了一截（前一筆的「後」對不上下一筆的「前」）、用 rebase 把自己的存檔搬到 main 後面、從別條分支併進來、問 git 失敗——
> 都照今天的算法全部算進來，畫面也不講「從 main 併進來 N 個」（那句只在算得出來的時候講）。
> **技術**：判斷回「算得出來：哪幾個檔、幾次存檔」或「分不出來」；分不出來不拿掉任何檔。斷掉的那一截算自己的。

**AC-5　拿掉了幾個照實講，不讓「這一輪沒動」看起來像「資料夾沒變」** ✅ 對過 2026-11-03
> **白話**：監工本子上要寫「隔壁搬進來 22 面牆，不算你的」，不能只寫「你這一輪沒砌牆」，讓人以為工地跟早上一模一樣。
> **會發生的情況**：終端機「這一輪的改動」與儀表板的改動卡多一句「另外 22 個檔是從 main 併進來的（別的對話改的），不算這一輪」；這一輪自己一個檔都沒有時，
> 不講「現在的檔案跟這一輪開始時一模一樣」，講「這一輪自己沒有改動；另外 22 個檔是從 main 併進來的」。蓋章之後才併進來的，章那一段也講：這些檔在這個資料夾還沒跑過檢查。
> 收工 hook 擋人時，括號裡多半句「不含從 main 併進來的 N 個檔」。
> **技術**：句子只寫在 `lib/scope.mjs` 一份，終端機、伺服器、收工 hook 都叫它（P2；〈終端機與網頁說同一句〉）。「回去會丟掉 N 次存檔」照舊算全部——回去真的會丟掉併進來的那些。

**AC-6　D 之後才併 main，不再被當成「D 之後又改了程式」** ✅ 對過 2026-11-03
> **白話**：驗屋師傅看完之後，隔壁搬進來的牆不算你又動工；你自己又砌了才算。
> **會發生的情況**：那兩次的情形——D 跑完之後才併 main——收工 hook 不擋、五關 D 那一格、分級卡、白板不寫「要不要再跑由你決定」；
> `pipeline-status --round D` 的「第一次之後改了哪些檔」不列 main 帶進來的，另外一行「另外 N 個是從 main 併進來的，不用看」。
> D 之後你自己又改了程式（含 AC-2 那種兩邊都動過、被合併改寫的檔），照舊問。
> **技術**：roundView 的「最後一次改檔」只吃拿掉之後那一份的修改時間（感測器記過、這個對話改過的檔照吃）；`--round` 的 `roundFiles` 用 AC-1 同一個判斷，基準換成第一輪那一刻的版本。

**AC-7　C、D 看的範圍與危險清單那一題，也不含併進來的** ✅ 對過 2026-11-03
> **白話**：清潔工不去掃隔壁的工地；新加的牆危不危險，問砌它的那個工班。
> **會發生的情況**：`--round C`／`--round D` 第一輪印的「這一輪的範圍」不列 main 帶進來的檔（另外一行講幾個）；
> main 帶進來一支危險清單定好之後才新加的程式檔，收工 hook 不在這個對話問「要不要加進危險清單」——那一題在寫它的對話問過了；main 碰到危險清單上的檔，這個對話的分級不因此變最高那一級。
> **技術**：這幾處本來就吃同一份清單（`printScope`、`buildTier` 的 hits、`staleOf`），拿掉之後自動跟著；測試各釘一個例子，以後誰另算一份就紅（P2）。

**AC-8　改動體檢的數字也照拿掉之後算** ✅ 對過 2026-11-03
> **白話**：本子上的數字（幾面牆、多幾塊磚少幾塊、動到幾個舊的檢查、幾次存檔加起來）都只算你的。
> **會發生的情況**：實測那一次的「+877 −32 行」「這裡是 6 次存檔加起來的」「動到 1 個既有的測試檔」都不再出現。
> **技術**：行數用 `git diff --numstat` 只加總留下的檔；幾次存檔只數這個資料夾這一輪自己存的（不數併進來的、不數合併那一個存檔）；既有測試、新相依吃同一份清單
> （`package.json` 兩邊都動過就照算——寧可多算）。

**AC-9　沒有併過 main 的資料夾，一切照舊、不多問 git** ✅ 對過 2026-11-03
> **白話**：沒搬牆進來的工地，本子一個字都不變。
> **會發生的情況**：這一輪沒有快轉或合併進來的資料夾，終端機、儀表板、收工 hook 一字不差；儀表板刷新不因此多問 git（〈儀表板刷新少等git〉）。
> **技術**：移動紀錄裡沒有「併進來」那幾種說明 → 直接回原來的清單，一個 diff 都不多跑。現有測試一個字不改照綠。

## 混沌推導

▸ 併發：兩個對話共用一個資料夾 → 移動紀錄是資料夾的，分不出哪個對話存的 → 一律當「自己的」（跟今天共用時一樣，畫面照講含幾個對話）。
▸ 時間：移動紀錄與感測器都只到秒；跟起點同一秒的移動算起點之後（跟 `versionAt` 同一條）→ 那一秒併進來的照樣拿掉、那一秒自己存的照樣算。
▸ 輸入畸形：移動紀錄有一行讀不懂 → 那一筆當自己的（AC-4）。分支名、檔名有空白或中文 → 照 `lib/git.mjs` 的規矩（不轉義、不配對搬家）。
▸ 網路：完全不連 GitHub。「在不在 main 的歷史上」只看本機知道的 main 與上一次抓到的 origin——本機還不知道的照算（寧可多算）。
▸ 容量：一輪裡併了很多次 main → 每次一個 diff，只看基準之後的那幾筆。

## 明確不做

- 不改「這一輪從哪裡算起」：起點、章、換人那一套照舊。
- 不分「兩邊都改過的檔」裡哪幾行是誰的——整個檔照算。
- 不認 rebase 搬過去的、從別條分支併進來的（照算，AC-4）。
- 不改還原點與「回去」：回去會丟掉的存檔、檔案照舊算全部。
- 不去 GitHub 抓最新的（不 fetch）。
- 不碰危險清單上的檔。
- 主任動手收尾是另一份：〈主任動手收尾〉。
