## 這是什麼

一句話：**讓「這次改動跑到哪一步了」這件事，不必靠記憶、也不必往上捲對話。**

Oscar 的原話是「都用對話呈現我有時會亂掉」、「比較不容易陷入代碼黑盒子」。

### 架構就三塊，順序不能顛倒

```
  ② 感測器  ──→  ① 大腦  ──→  ③ 畫面
  （記下發生      （把紀錄讀成      （看板）
    了什麼）        一句人話）
```

沿用你自己的蓋房子比喻：

| | 是什麼 | 蓋房子對應 |
|---|---|---|
| **②** | 每次跑指令自動記一行 | **工地各處的攝影機**——只負責錄，不負責判斷 |
| **①** | 把紀錄 + 檔案狀態算成結論 | **把錄影帶讀成一句話的工頭**：「做到第三層，鋼筋還沒驗」 |
| **③** | 網頁看板 | **工地大門口那塊看板** |

**為什麼順序不能顛倒**：沒有 ②，① 只能說「不知道」；沒有 ①，③ 就只是一堆生資料。
反過來說——**①② 做完之後，③ 幾乎只剩畫畫**，因為要顯示的每一個字都已經算好了。

## Q1：①②③ 到底是什麼（白話 + 舉例）

### ② 感測器 —— 自動記下「誰在什麼時候跑了什麼」

**現在的問題**：你跑完 `/chaos-check`，這件事只存在於對話裡。關掉視窗就沒了，
明天早上你不會記得昨天那次到底跑了沒。

**做完之後**：每次一送出指令，系統自動在一個檔案裡追加一行：

```
2026-09-08 16:20  /chaos-check  在 agent-dashboard-planning 這個分支
2026-09-08 16:47  /cleanup      在 agent-dashboard-planning 這個分支
```

**你不用做任何事**，它自己會記。這叫 hook（掛鉤）——Claude Code 提供的機制，
每次發生事情就主動通知外面。

⚠️ **它只記「跑過」，不記「通過」**——這是刻意的，因為「通過」它無從得知。

### ① 大腦 —— 把上面那堆變成一句人話

**現在的問題**：你要知道現況，得自己跑 `npm test`、`git status`，
然後在腦子裡拼起來。

**做完之後**，一個指令印出全部：

```
▸ 這次在做：pipeline-dashboard（2 小時前開工）
▸ 分級：T1  →  要跑 現有 CI ＋ /chaos-check
▸ 測試：16:18 全綠  ·  ⚠️ 之後有 3 個檔案被改過
▸ D 魔鬼教官：16:20 跑過  ·  ⚠️ 之後有 3 個檔案被改過
▸ C 打掃：沒跑過
▸ ⚠️ 6 個檔案還沒 commit（最舊的改於 1 小時前）
```

**注意每一行後面那個「之後有 3 個檔案被改過」——這是整個設計最重要的一句話。**

因為 16:20 檢查過的那份程式碼，17:30 已經不是同一份了。
只印「16:20 跑過」會讓你以為安全，**那就是說謊**。

### ③ 畫面 —— 同一份資料，換個長相

一個瀏覽器分頁，長得像這樣（草稿）：

```
┌─ pipeline-dashboard ────────── 最後動作 3 分鐘前 ─┐
│  A 規格   ⏸ 16:02 跑過（2 小時前）               │
│  B 程式   ●  就是你正在講話的這個對話              │
│  C 打掃   ⚪ 沒跑過                                │
│  D 教官   ⏸ 16:20 跑過  ⚠️ 之後有 3 個檔案被改過  │
│  E 驗收   ⚪ 沒跑過                                │
│  ────────────────────────────────────────────    │
│  ⚠️ 6 個檔案沒 commit                             │
└──────────────────────────────────────────────────┘

⏸ 等你點頭：docs/規劃中/ 有 1 份規格在等審
```

## Q2：五個 agent 真的做得出來嗎？做得出來，但**其中一個刻意不做**

> 現在 A／C／D／E 都是 plugin 帶的 skill，B 是主對話本人：見[通用三關](升級摘要/通用三關.md)、[E自動驗收](升級摘要/E自動驗收.md)。

### 做成真的 agent：可以，而且值得

| 關 | 做成獨立 agent？ | 為什麼 |
|---|---|---|
| **A 規格** | ✅ 適合 | 產出有邊界（一份文件），跑完就停 |
| **B 程式** | ❌ **刻意不做** | **B 就是你在對話的那一個。** 把它關進獨立 agent＝把自己關進黑盒子——**正好是你想避免的那件事** |
| **C 打掃** | ✅ 適合 | 產出有邊界（一份刪除清單） |
| **D 教官** | ✅ **最適合** | 它是**全新的腦袋**，沒寫過那些程式碼，所以不會替自己說話。這是優點不是限制 |
| **E 驗收** | 🟡 做得出來，但最難 | 要真的開瀏覽器點按鈕 |

**所以是「四個 agent + 一個你」，不是五個 agent。** 我認為這樣更好，
而且它讓 Q3 的資料模型變得非常乾淨（見下）。

### 怎麼做到「裝到任何專案都能用」：做成 Claude Code plugin

**這是我從 CCAM 身上找到最有用的一件事**（不是它的架構，是它的包裝方式）。
它把功能拆成 14 個 plugin，每個 plugin 的資料夾長這樣——**我確認過真的可以這樣包**：

```
產線監視器/
├── .claude-plugin/plugin.json   ← 身分證
├── hooks/hooks.json             ← ② 感測器住這裡
└── skills/                      ← A／C／D／E 的通用版住這裡（做成 skill，不是 agent）
```

**一次安裝，那個專案就同時拿到「五關流程」和「監視它的儀表板」。**
新專案不必再貼任何東西——這正好呼應 TutorPod 那條「最後一次貼代碼」的教訓。

⚠️ **但流程本身要能換。** TutorPod 的五關（含它的 FAILURE-PATTERNS）是為這個專案長出來的，
硬套到別的專案上會變成儀式。**plugin 要能設定關卡的名字與數量**，
不然它就只是「TutorPod 專用」披了一件可攜的外衣。這是整個產品最大的設計風險，
先記下來，不在這份文件裡解決。

## Q3：以「對話」為單位 —— 你這個直覺是對的，而且它解掉了我上一版的難題

你說「我們通常是用對話為單位去建立新功能或除錯」。**對，而且這比我上一版的想法好。**

上一版我說「CCAM 幫不上忙，因為你沒有 subagent」。你的回答是「那就把它們做成 agent」——
**這一翻轉，問題就反過來解決了**：

```
一次對話  =  一個工作項  =  走一遍 A → E
     │
     ├── 對話本身          就是 B
     └── A / C / D / E     是在這個對話裡叫的 skill（你打的或 Claude 叫的），感測器記到那一次呼叫
```

**這就是你要的監視系統的骨架**：一次對話一張卡，卡上五行，每行一個時間戳。

### 你提到的三件事，難度天差地別

| 你想要的 | 做得到嗎 | 說明 |
|---|---|---|
| **跑到哪一步** | ✅ 容易 | 就是上面那張卡 |
| **哪邊還沒跑** | ✅ **最容易，也最有價值** | 「沒有紀錄」＝「沒跑過」，這個推論不會錯 |
| **提醒 commit 沒** | ✅ 容易 | 純粹查 `git status`，零說謊風險 |
| ~~還在跑嗎~~ | ❌ **辦不到，也不要做** | 見下 |

⚠️ **最後一行是唯一不能妥協的地方。**

「它還在跑嗎」沒有誠實的答案。對話當掉、視窗關掉、我停下來——沒有人會來熄燈。
CCAM 也遇到同一個問題，它的答案是一個叫 `DASHBOARD_STALE_MINUTES` 的設定，
**預設 180 分鐘**才放棄——也就是**一盞說謊的燈最長可以亮三個小時**。

一個 989 commit 的成熟專案，最後也只能猜。**所以我們不猜，只印時間戳：**

| ❌ 會說謊 | ✅ 不會說謊 |
|---|---|
| `B 🟡 工作中…` | `B 最後動作 16:20（12 分鐘前）` |
| `C ⏳ 執行中` | `C 沒跑過` |
| `全部正常 ✅` | `測試 16:18 全綠 · 之後有 3 個檔案被改過` |

右邊每一格都是檔案上真的有的東西。**卡住的時候你自己看得出來**
（顯示 16:20、現在 17:30 → 不對勁），而「工作中」什麼都沒告訴你。

## Q4：本機 Python 還是網頁？—— 這題的前提要先拆掉

**「本機 vs 網頁」不是真正的選擇題，因為網頁也是跑在你自己電腦上的。**
（真的放到雲端反而更糟：它看不到你電腦裡的檔案，資料還得離開你的機器。）

真正有三個軸，分開看：

| 軸 | 答案 |
|---|---|
| **在哪跑** | 都是本機。沒有第二個選項 |
| **資料怎麼來** | hook **用推的**，不是定時去問。所以**兩種做法一樣即時**（不到一秒） |
| **長什麼樣** | 終端機 vs 瀏覽器分頁 ← **只有這個要選** |

### 即時性：一樣快，這題不用選

hook 是事件驅動的——事情一發生就推出來。無論你最後畫在終端機還是瀏覽器，
延遲都在一秒內。**「哪個比較即時」在這個架構下不成立。**

### 我建議：**瀏覽器**

| | 瀏覽器 | 終端機 |
|---|---|---|
| 你原本要的 GUI | ✅ | ❌ |
| 放第二個螢幕一直開著 | ✅ | 🟡 |
| 同時看多個專案／worktree | ✅ 一頁排開 | ❌ 擠 |
| **會不會跟你搶終端機** | ✅ 不會 | ❌ **你的終端機正在跑 Claude** |

最後一行是關鍵：你的終端機已經被 Claude 佔著了。

### 語言：hook 那一段**不要用任何語言**

這點值得單獨講。CCAM 的 hook 是**一行 shell**，沒有 Python 也沒有 Node：

```
jq -r '{session_id, stop_reason, timestamp: now|todate}' | curl -s -X POST … || true
```

**最不能壞的那一段，就該是沒有東西可以壞的那一段。**
（結尾那個 `|| true` 是說：就算失敗也絕不拖累 Claude。這個要照抄。）

至於讀取端（①）和網頁（③）：**我建議 Node，不是 Python。**
不是因為 Python 不好，是因為你整個世界已經是 Node，
而且未來要發佈給別人裝的時候，**一個 runtime 比兩個好**。
你偏好 Python 的話也完全做得出來，只是這個理由要成立才值得。

## Q6：CCAM 只偷這些

你說得對，不用它的架構。**確認過真的有用的只有三樣**：

| 偷什麼 | 為什麼 |
|---|---|
| **① hook 的做法** | 事件用推的，不是輪詢。而且 hook 是 shell 一行，零相依 |
| **② plugin 的包裝格式** | 一個資料夾同時裝 skills + hooks，一次安裝，任何專案可用。**這是 Q2 的答案** |
| **③ 安全預設值** | 綁 `127.0.0.1` 不對外、same-origin 檢查、DNS-rebinding 防護。它出過一次「預設對整個區網開放」的漏洞並修掉了，直接抄結論 |

**明確不偷**：它的 SQLite（issue #315：把整份檔案內容鏡射進 DB，有人的 DB 長到 **2 GB**）、
它的 `working` 狀態燈（見 Q3）、token 成本分析（跟「跑到哪」無關）、
以及那 1472 個檔案 / 14 個 plugin / 66 個 skill / Electron / Prometheus。

## 📡 感測器目錄與功能地圖（2026-09-08 討論）

Oscar：「感測器能不能多幾個」「我習慣做之前把架構都想好，但順序可以有先後」。
以下是**完整架構**，分期在最後。

### 四種資料來源（不是只有 hook）

```
 ① hook 事件      誰在什麼時候呼叫了什麼        ← 已實測
 ② transcript     token／context％／對話標題    ← 已實測
 ③ git            commit／merge／push 三階梯    ← 已實測
 ④ 檔案系統       規劃中／進行中／升級摘要       ← 本來就會
        ↓
    ① 大腦：把四種來源**交叉比對**
        ↓
    ③ 畫面
```

**交叉比對才是價值所在。** 單看「D 在 16:20 跑過」沒有用；
`16:20 的事件` × `檔案改動時間` = **「這個結論過期了沒」**——那才是要顯示的東西。

### 已實測可行的欄位

| 來源 | 拿得到什麼 | 狀態 |
|---|---|---|
| `UserPromptSubmit` | `prompt`（你打的全文）、**`session_title`**（對話標題） | ✅ 實測 |
| `Pre/PostToolUse` | `tool_name`、`tool_input`、`session_id`、`cwd`、`prompt_id`、`permission_mode` | ✅ 實測 |
| transcript 的 `usage` | `input` / `output` / `cache_read` / `thinking_tokens` | ✅ 實測 |
| transcript 加總 | **context 用量**（實測算出 184k，Oscar 截圖顯示 180.7k／1M，量級與比例對得上） | ✅ 實測 |
| git | 未 commit 檔數、未 merge commit 數、未 push commit 數 | ✅ 實測 |

⚠️ **`session_title` 是意外收穫**——它直接回答「每個對話在處理什麼」，不必自己猜。
本對話實測值：`Agent dashboard 規劃與審查`。

### ❌ 查證過但拿不到的

**方案額度（5 小時 72%／每週 34%，Oscar 截圖那個）在本機檔案裡找不到。**
搜過 transcript，沒有任何 rate limit 欄位——那是伺服器端的資訊。

⚠️ 我**只能說「本機檔案裡找不到」，不能說「做不到」**——我沒有查過有沒有別的管道（R2）。
**context 用量（失憶危機）拿得到，方案額度拿不到，兩者不要混為一談。**

### 功能地圖：按「會不會說謊」分四級

這是唯一該用來排優先序的軸——**不是按好不好做**。

#### 🟢 第一級：純事實，讀了就對，不可能說謊

| 功能 | 來源 |
|---|---|
| **commit／merge／push 三階梯**（Oscar 截圖那張） | git |
| 這個專案現在有幾個對話 | 數 transcript 檔 |
| `規劃中/` 有幾份規格等你點頭、最舊的多久 | 檔案系統 |
| `進行中/` 有幾個（**上限 2，`npm test` 會擋**） | 檔案系統 |
| 目前分支、HEAD | git |

**三階梯照 Oscar 的比喻直接畫**（草稿本→正本→寄公司存檔）：

```
① commit  ⚠️ 2 個檔案還沒存（最舊的改於 1 小時前）
② merge   ✅ 已併進 main
③ push    ⚠️ 這條分支還沒有遠端
```

#### 🟡 第二級：帶時間戳的事件——可能漏，但不會錯

| 功能 | 來源 |
|---|---|
| A／C／D／E 各自**最後一次**被呼叫的時間與參數 | hook |
| 每個對話的**標題**與**最後一則訊息** | hook |
| 每個對話最後一個動作的時間 | hook |
| 這次動過哪些檔案 | hook（Edit／Write 的 `tool_input`） |
| **這個對話在 auto 模式**（不問你就直接動手） | hook 的 `permission_mode` |

#### 🟠 第三級：算得出來，但**一定要配時間戳**，否則會過期騙人

| 功能 | 為什麼危險 |
|---|---|
| **失憶危機**（context ％） | 算出來的那一刻就開始過期 |
| token 消耗／花費 | 同上 |
| 測試綠不綠 | **16:18 全綠**不代表現在綠 → 必須併「之後改了幾個檔案」 |

**失憶危機的正確長相**（這是 Oscar 特別點名的）：

```
⚠️ 這個對話快沒記憶了：182k / 1M（18%）· 3 分鐘前量的
   建議先 commit 再繼續，被壓縮之後我可能忘記剛剛講好的事
```

⚠️ 「被壓縮」是 Claude Code 自動整理對話、把舊內容摘要掉的動作。
**做過的事不會消失，但講好的細節可能會。** 所以警示要綁「先 commit」這個具體下一步（R3）。

⚠️ **我沒有查證有沒有「壓縮發生時」的 hook**（CCAM 的文件列了 8 種，裡面沒有）。
所以目前只做「快滿了」的預警，**不宣稱做得到「剛剛被壓縮了」的事後通知**。

#### 🔴 第四級：**不要做**——這些一定會說謊

| Oscar 提到的 | 為什麼不能做 | 誠實的替代品 |
|---|---|---|
| **「整體進度 ％」** | **分母不存在。** 「87%」是憑空捏造的——沒有人知道剩下多少工作。這是整份清單裡最危險的一項，因為它看起來最像儀表板該有的東西 | **改成數數量**：`五關裡有 3 關留下紀錄`、`AC 8 條打勾 5 條`。數量是事實，百分比是猜測 |
| 「還在跑嗎」的燈 | 見前面 Q3 | 最後動作時間 |
| 「E ✅ 通過」 | 只知道瀏覽器被開過 | `開瀏覽器跑過一輪（12 個動作）` |
| 「打掃通過」 | `success:true` 只代表檔案讀進來了 | `/cleanup 16:47 被呼叫過` |

> 🔑 **判準一句話：這個數字的分母，是查得到的事實，還是我編的？**
> 「2 個檔案沒 commit」的分母是實際檔案；「進度 87%」的分母不存在。

### 三個 Oscar 沒提、但我認為值得做的

1. **跨對話衝突警示**：`⚠️ 你有 3 個對話開著，其中 2 個都動到 studentModel.js`。
   純檔案事實，而且以同時開好幾個 worktree 的用法，**這是最可能真的救到你一次的功能**。
2. **等你點頭的隊列**：`規劃中/ 有 2 份規格等審，最舊的 3 天前`——你原本的痛點。
3. **auto 模式提醒**：`這個對話在 auto 模式`。非工程背景的人最該知道的一件事，
   而它現在完全不可見。

## 🧨 Vibe coder 的死法：這個工具真正該對付的東西（2026-09-09）

Oscar：「我開發這五個 agent 就是為了緩解對程式碼黑盒子的恐懼，讓 vibe coder
寫出來的東西地基更穩，不要老是被傳統工程師嘲笑。」

### 先說一個不客氣的判斷

**那個嘲笑有時候是對的，有時候不是。** 決定一份程式碼會不會爛掉的，
從來不是作者的學歷，是這四件事：

| | | vibe coding 的體質 |
|---|---|---|
| **①** | 能不能安全地**回到上一個能動的版本** | 🔴 **結構性地差**——生成很快、改動很大，等發現不對時已經疊了十層 |
| **②** | 一次改動能不能**被審查**（夠小、有邊界） | 🔴 **結構性地差**——問一句話回來改 12 個檔案是常態 |
| **③** | 壞掉的時候**會不會大聲** | 🟢 **可以做得比人好**——規則寫一次，AI 每次都照做；人會忘 |
| **④** | 決定有沒有**留下理由** | 🟢 **可以做得比人好**——同上 |

⚠️ **TutorPod 的產線目前火力全開在 ③ 和 ④**（三條紅線、FAILURE-PATTERNS、
刻意的決定清單、LESSONS）——**而那兩項本來就是 vibe coding 的強項。**

**① 和 ② 幾乎沒有任何機械支援，而那兩項才是結構性的弱點。**
⇒ **儀表板真正的優先序應該從這裡來，不是從「有哪些資料可以顯示」來。**

### 六個具體死法（依「vibe coder 有多不可能自己發現」排序）

| | 死法 | 為什麼 vibe coder 抓不到 | 儀表板能給的事實 |
|---|---|---|---|
| **V1** | **「我回不去了」** | 一路改到爆炸，才發現不知道哪個版本還能動。**這就是「黑盒子恐懼」的本體** | **最後一次「四項檢查全綠 ＋ 已 commit」是哪一個 commit、多久以前**。那是你的還原點 |
| **V2** | **改動範圍失控** | 問一個小問題，AI 改了 12 個檔案。他無法判斷這正不正常 | 這一輪動了幾個檔案、幾行。**異常大就標出來** |
| **V3** | **有東西被安靜刪掉** | AI 重寫整個檔案時會靜默丟掉功能。他沒讀過原檔，看不出少了什麼 | **淨減行數**。`X.js −180 行` 值得問一句 |
| **V4** | **測試被改成配合實作** | 他讓 AI 寫測試，AI 寫出「測試自己」的測試。全綠，但什麼都沒保證 | **同一輪裡測試檔和被測檔一起被改** = 警訊 |
| **V5** | **線上跑的不是這一份** | 「改好了但線上沒變」。已寫進 `CLAUDE.md`，但**沒有機械檢查** | 本地版本 vs 線上版本 |
| **V6** | **相依越裝越多** | 每個 `npm install` 都是永久債務，而當下都只花三秒 | 這次改動新增了幾個相依 |

⚠️ **V1 是這整份文件裡最重要的一條，而我和 Oscar 前面都沒想到。**
它不是「錦上添花的功能」——**它是恐懼本身的解藥**。
而且它 100% 由事實推導（git ＋ 檢查結果），零說謊風險。

**V1 的長相：**

```
🟢 最後一個確定能動的版本：3f2da6c（2 小時前）
   四項檢查全綠 · 已 commit · 要回去打 git reset --hard 3f2da6c
```

⚠️ **一定要附「怎麼回去」那一行**（R3：壞掉時要給一條真的做得到的下一步）。
一個知道自己回得去的人，才敢動手改東西——**這比任何一個進度條都更能解除恐懼。**

### 六個死法各自住在哪（2026-09-09 盤點）

Oscar：「六個死法目前只做 V1 嗎？其他怎麼辦？」——重新盤過，**它們不是六個專案。**

| 死法 | 需要什麼才做得出來 | 住在哪 |
|---|---|---|
| **V1** 還原點 | **一個「蓋章」機制**——六個裡**唯一要新建東西**的 | 獨立工作項 ✅ [`restore-point.md`](升級摘要/pipeline-status.md) |
| **V2** 改動範圍 | 只要 `git diff --stat` | **① 大腦的一行** |
| **V3** 淨減行數 | 只要 `git diff --stat`（同一次呼叫） | **① 大腦的一行** |
| **V4** 測試與實作同時改 | 只要 `git diff --name-only` | **① 大腦的一行** |
| **V6** 新增相依 | 只要 `git diff package.json` | **① 大腦的一行** |
| **V5** 線上版本落差 | **要連網**去讀線上的版本號 | 獨立工作項（混沌推導完全不同） |

**⇒ 六個裡有四個是同一支程式多印四行，不是四個專案。**
拆成四個工作項只會把同一份 git 讀取邏輯寫四遍。

### 🔑 這件事改了順序：① 可以在 ② 之前做

原本排的是 `② 感測器 → ① 大腦`。但盤完發現——

**① 不需要 hook 也能跑，而且那樣就已經解掉六個死法裡的五個：**

| ① 單獨就給得出來 | 靠什麼 |
|---|---|
| 還原點（V1） | git ＋ 蓋章 |
| 這次改動多大、淨減幾行、測試有沒有被一起改、新增幾個相依 | git |
| 這次是 T0／T1／T2 | 專案的 `.claude/pipeline-stages.json`（見[分級](升級摘要/分級.md)） |
| 幾個檔案還沒 commit | git |
| `規劃中/` 有幾份等你點頭 | 檔案系統 |
| **這個對話快沒記憶了**（context ％） | transcript，**已實測，不需要 hook** |

**② 感測器加上去之後才多出來的，只有 A–E 五關的時間戳。**

⚠️ 那確實是 Oscar 最初要的東西（「監測五個 agent」），所以 ② 不能砍。
但**「讓 vibe coding 地基變穩」這件事，主要是 ① 在做，不是 ②。**

### 對階段 ② 的影響：只多一條

上面六條大多是**畫面**（③）與**判讀**（①）的事。
但 **V2／V3／V4 需要「這一輪動了哪些檔案」，而這件事只有當下記得下來**——
事後從 git 看不出「這一輪」的邊界（一個 commit 可能包含好幾輪對話）。

⇒ **感測器要多記一件事：每一輪動過的檔案路徑**（只記路徑，不記內容）。
**記錄層漏掉的東西補不回來**，所以這一條要現在加，不能等。→ 見規格 AC-10。

### ✅ 階段 0：已實測（2026-09-08）—— 結論比預期好

原本的疑問是「hook 看不看得到 `/chaos-check` 這串字」。**答案是看得到，但不是用我預期的方式。**

#### 發現 1：斜線指令 = `Skill` 工具呼叫

> ⚠️ **2026-09-15 更正**：這只對 **Claude 自己去叫**的情況成立。**你自己打**的斜線指令會被展開成訊息，不經過 Skill 工具，
> 感測器只看到訊息開頭那串字——讀取端已經改成兩種都認（[`LESSONS.md`](LESSONS.md) L19）。

`/spec`、`/cleanup`、`/chaos-check` 不是以「一段文字」的形式出現，
而是變成一個叫 `Skill` 的**工具呼叫**。實測掛 `PreToolUse` / `PostToolUse` 認 `Skill`，收到：

```json
{
  "hook_event_name": "PreToolUse",
  "tool_name":  "Skill",
  "tool_input": { "skill": "cleanup", "args": "本次 diff 只有 docs/…" },
  "session_id": "e6373866-…",
  "cwd":        "…/worktrees/agent-dashboard-planning-aca5b3",
  "prompt_id":  "b65743cd-…"
}
```

**`tool_input.skill` 就是指令名。** 而且 `args` 連參數都給了——
以後畫面上可以直接顯示「A 規格：在寫『修掉 logToSheet 的假綠勾』」，不只是「A 跑過了」。

#### 發現 2：四個欄位剛好對上四個需求

| 欄位 | 解決什麼 |
|---|---|
| `session_id` | **對話身分**——Q3 說的「以對話為單位」，系統直接給 |
| `cwd` | **哪個 worktree**——「顯示錯的比不顯示更糟」這題，機械解決 |
| `prompt_id` | **同一輪**——你送一次訊息之後發生的所有事情可以群組起來 |
| `PreToolUse` + `PostToolUse` | **開始與結束兩個時間點**——可以算真實耗時 |

#### 發現 3：hook 中途裝就生效，不必重開對話

實測：寫進 `.claude/settings.local.json` 之後，**下一個動作立刻就被記錄到**。
（`.claude/*` 已經在 `.gitignore` 裡，所以這個檔案不會進版控，零 git 噪音。）

#### 🚨 發現 4：payload 裡有一個陷阱，一定要記下來

`PostToolUse` 的回傳裡有這兩個欄位：

```json
"tool_response": { "success": true, "commandName": "cleanup" },
"duration_ms": 8
```

**`success: true` 不是「打掃通過了」，是「skill 檔讀進來了」。**
`duration_ms: 8` 也不是打掃花了 8 毫秒，是**載入指令檔**花了 8 毫秒。

⚠️ **這正是 R1 說的代理指標**，而且它長得非常像可以直接顯示的東西。
把它畫成「C 打掃 ✅ 通過」就是這個專案最經典的假綠勾——
**跟 `logToSheet` 那個「請求送出去了就顯示 Logged ✓」是同一種錯。**

**規則：`success` 與 `duration_ms` 一律不進畫面。** 能顯示的只有
「`/cleanup` 在 16:47 被呼叫過」以及「之後有幾個檔案被改過」。

#### 對計畫的影響

- ✅ **② 感測器確定做得出來**，而且比原本設想的乾淨（認工具名，不必解析文字）
- ✅ **不需要先把 A/C/D 改成 agent**——`Skill` 這條路現在就通了。
  改成 agent 仍然值得（Q2 的理由不變），但**不再是感測器的前提**，可以往後排

| **公開哪個 repo** | 另開一個新的公開 repo，歷史從零開始；這個 repo 留私人，發版時用腳本把要給人的檔案複製過去，推上去由 Oscar 按 | 2026-09-10 紀錄被推上 GitHub 過（LESSONS L12），本機歷史已經找不到，但看不到 GitHub 那邊有沒有留著；開發筆記留在私人這邊；別人只拿到發過的版本 |

| **支援哪些電腦** | 第一版只寫 Mac。Linux 照實寫「自動測試在 Linux 上跑得過，沒人實際用過」；Windows 先不支援 | Windows 的 hook 要靠 Git Bash、通常沒有 jq；背景服務只有 Mac 的 launchd |
| **預設全記** | 照舊；但安裝**之前**先把「會記什麼」講給對方聽，對方說好才裝 | 記的是使用者打的字。在別人的電腦上，這件事要在裝之前講，不是裝完才在畫面上看到 |

### 為什麼地基要先修

現在紀錄跟還原點住在「程式的資料夾」旁邊。在自己的電腦上沒事；但別人從 marketplace 或官方目錄裝的時候，
程式是**一個版本一個資料夾**，更新之後舊的會被清掉（[Claude Code 官方文件](https://code.claude.com/docs/en/plugins/loading.md)）——
紀錄跟著程式住，就會跟著舊版本一起消失。畫面不會報錯，只是紀錄越來越少：R1 的形狀。

⚠️ **要在任何別人裝之前搬好**：那時候要搬的只有這台電腦的紀錄，搬的時候有人看著；晚一點做，就變成在別人的電腦上沒人看著地搬。

### 順序（每段一份規格，做完就可以停）

| 段 | 做什麼 |
|---|---|
| **1 地基** | 紀錄與還原點搬到固定的家，不再跟程式住在一起 |
| **2 雙語** | 中英一鍵切換（範圍見上）。可能拆成兩份規格：先儀表板與終端機，再技能、README 與寫給 AI 的句子 |
| **3 公開＋一句話安裝** | 新 repo、MIT、給陌生人與給 AI 看的 README（使用者把網址貼給自己的 AI 說「幫我裝」）、安裝前的檢查（缺 git／node／jq 講缺什麼、怎麼裝）、拆乾淨、技能裡只對 Oscar 成立的話清掉；新裝的人第一次看到哪一種語言，由替人裝的那個 AI 切（它知道對方講哪種話，「從來沒選過＝中文」只對 Oscar 這台成立）。驗收：一個不是 Oscar 的人照 README 裝起來——「我這台跑得起來」不算（R2）。結案就是 **v1.0.0** |
| **4 marketplace＋官方目錄** | 程式資料夾跟著版本換的時候，儀表板服務要跟著換；拆掉之後不留一個一直重啟的服務；送審由 Oscar 按 |
| **5 非 Claude（能做就做）** | git 那一半（還原點、改動體檢、分級、儀表板）本來就不靠 Claude；技能是通用格式，Codex、Antigravity 都讀得懂；感測器只有 Codex、Copilot CLI 有機會（它們認得 Claude 的 plugin 格式），要有人實際裝了才算數 |

**雙語排在公開之前**：公開那天英文使用者看到的就是英文；第 3 段找人試裝時兩種語言一起驗。

**不支援、要照實寫的**：Cowork、claude.ai 網頁對話、雲端的 Claude Code 對話——hook 跑在雲端那台機器上，這台的儀表板看不到。
