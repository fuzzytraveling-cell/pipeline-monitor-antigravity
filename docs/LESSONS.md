> 每一條都是**真的踩到過**的，不是假想。門檻是能回答

> ⚠️ 這份會一直長。找東西**先搜關鍵字**，不要從頭讀。

## L1　`import.meta.url` 是編碼過的，`process.argv[1]` 不是

**2026-09-09 · status.mjs · 症狀：零輸出、零錯誤、離開碼 0**

判斷「這支檔案是不是被直接執行」時寫成：

```js
if (import.meta.url === `file://${process.argv[1]}`)   // ❌
```

使用者的路徑是 `/Users/…/TutorPod AI/…`——**有一個空白**。
`import.meta.url` 會把它編成 `%20`，`argv[1]` 不會。兩邊永遠不相等，
於是 `main()` 從來沒被呼叫過，而程式**安靜地正常結束**。

```js
if (fileURLToPath(import.meta.url) === process.argv[1])  // ✅
```

**下次什麼情況會再犯**：任何比對 `file://` URL 與檔案路徑的地方。
路徑有空白、中文、`#`、`?` 都會踩到，而且**症狀永遠是「什麼都沒發生」**——
不是錯誤，所以你會先去懷疑別的地方。

⚠️ 這是 R1 的形狀，發生在一個專門用來抓 R1 的工具身上。

## L2　`git diff` 看不到還沒被追蹤的新檔案　`已發生 3 次`

**2026-09-09 改動計數 · 2026-09-10 還原點比對**

`git diff --name-only` 只列**已被 git 追蹤**的檔案。新建的檔案完全不在裡面。

第一次：實際改了 4 個檔案，畫面說 **2 個**。
第二次：印出「之後有 **2** 個檔案被改過 / 其中 **3** 個還沒存進保險箱」——
**3 大於 2，算術對不起來。**

```sh
git diff --name-only            # 只有已追蹤的
git ls-files --others --exclude-standard   # 這個才是新檔案
```

**下次什麼情況會再犯**：任何「數這次動了幾個檔案」的地方。
⚠️ 而且**漏掉的方向固定是讓改動看起來比較小**——那是危險的那一邊，
因為它讓人以為安全。**AI 生成最常見的產物就是新檔案。**

⚠️ 另外：**一個算術對不起來的儀表板，使用者不會再信它第二次。**
`3 > 2` 一眼就看得出來，而那一眼會毀掉整個工具的可信度。

## L3　感測器有一個「開始的日期」，而畫面說了謊

**2026-09-10 · 五關顯示**

`/spec` 那天稍早**真的跑過**，但感測器是之後才裝的。
畫面理直氣壯寫著 **「A 沒跑過」**。

那是 **R1**：把「沒問到」編碼成「答案是沒有」。

修法不是加註解，是改文案：**「沒有紀錄」**，並固定附一句
「感測器從 X 才開始記，在那之前發生的事情它一輩子都不會知道」。

**下次什麼情況會再犯**：任何「從紀錄推論事實」的地方。
**紀錄的起點不等於世界的起點。** 保留期限（三個月）到期丟掉的資料同理——
問到更早的期間要回答「超過保留期限」，不是「沒跑過」。

## L4　`--git-common-dir` 在一般 repo 回相對路徑，worktree 才回絕對路徑

**2026-09-09 · 專案名稱顯示成 `.`**

```
一般 repo   → .git                     （相對！）
worktree    → /abs/path/to/repo/.git   （絕對）
```

直接拿去 `basename(dirname(...))` 在一般 repo 會得到 `.`。
先判斷是不是 `/` 開頭，不是就跟 `--show-toplevel` 接起來。

**下次什麼情況會再犯**：任何拿 git 的路徑輸出去算東西的地方。
⚠️ 這也是為什麼要用它——**它是唯一能讓三個 worktree 認出「我們是同一個專案」的東西。**

## L5　靠 diff 的文字排版判斷語意，會安靜地失效

**2026-09-09 · 相依偵測**

原本用 `^\+\s*"[^"]+":\s*"[\^~]?\d` 去 diff 裡撈新增的相依。
那**假設 `package.json` 是一行一個相依**。壓成一行的就完全撈不到——
而且是安靜地撈不到，回報「新增 0 個」。

改成**解析兩個版本的 JSON、取鍵的差集**。精確，而且跟排版無關。

**下次什麼情況會再犯**：任何用正則去讀結構化資料的地方。
**有 parser 就用 parser。**

## L6　樣本太少的統計，長得跟有依據的基準一模一樣

**2026-09-09 · 改動規模比例尺**

只有 2 個 commit 的時候，「這個專案平常 5 個檔案，最多到過 5 個」照樣印出來。
數字是真的，但**它什麼都沒告訴你**，卻長得像一個可以拿來比較的基準。

現在樣本 < 5 就不給比例尺。

**下次什麼情況會再犯**：任何從歷史算平均／中位數的地方。
**寧可不給，也不要給一個看起來有依據的雜訊**——這是 R3。

## L7　`null` 漏到畫面上

**2026-09-09 · 零 commit 的 repo 顯示 `━━ empty · null ━━`**

一個 commit 都沒有時 `git rev-parse --abbrev-ref HEAD` 會失敗，
我們的 `git()` 回 `null`，然後那個 `null` 直接被印出來。

`symbolic-ref --short HEAD` 在零 commit 時仍然答得出來，拿它當備援，
再退回 `(還沒有分支)`。

**下次什麼情況會再犯**：任何把 `git()` 的回傳值直接放進字串的地方。
⚠️ **讀的人不是工程師**——`null` 對他來說不是「查不到」，是一個看不懂的錯誤。

## L8　用 Bash 寫檔案會完全繞過 hook

**2026-09-10 · AC-10 的盲區**

hook 的 matcher 只認 `Edit`／`Write`／`NotebookEdit`。
用 Bash heredoc、`sed`、`python` 寫檔案**一筆都不會被記到**。

所以定了一條規則：**檔案數量一律由 git 算，不准用 hook 的紀錄算。**
hook 的檔案紀錄只用來做 git 做不到的那一件事：**把檔案連回「當初說了什麼」**。

**下次什麼情況會再犯**：任何想從 hook 紀錄推論「總共動了什麼」的地方。
**hook 看得到的是它被掛上的那幾個工具，不是全世界。**

## L9　同一份文件抄第二次，就是第二個真相來源

**2026-09-10 · 決定不建 FAILURE-PATTERNS.md**

盤點時發現想寫進去的東西，`CLAUDE.md`（紅線）、本檔（實例）、
規格的 AC 三個地方都已經有了。再開一份就是第三次抄寫。

**判準**：建新文件之前先問——
**「它有沒有獨佔的內容？」** 和 **「它過期的時候，什麼東西會變紅？」**
兩題都答不出來就不要建。

⚠️ 什麼時候才該建 `FAILURE-PATTERNS.md`：**同一類錯誤犯第二次**的時候
（L2 已經達標），而且**要連「把它推到眼前」的機制一起建**。
一份沒有觸發機制的模式清單，是一個沒人會打開的檔案。

## L10　檢查要抓「意圖」，不要抓「字面」——否則 CI 會變成狼來了　`已發生 3 次`

**2026-09-10 · CI 的「不准依賴 TutorPod」規則 · 同一支檢查連續誤報兩次**

`CLAUDE.md` 寫了「不准依賴 TutorPod」，於是 CI 加了一條 grep。
**第一次跑就 4 個誤報，全部是註解**——而且是「解釋為什麼這樣做」的註解，
正是 `CLAUDE.md` 自己要求要寫的那種。

> 註解**提到** TutorPod，跟程式碼**依賴** TutorPod，是兩件事。
> 一條會為了正當的東西變紅的檢查，第三次之後就沒有人看了——**那時它等於不存在。**

修法是把註解行排除，不是把註解刪掉。

### 第二次（同一天，推上 GitHub 之後）

排除註解之後又紅了，這次抓到的是**測試的標題字串**：

```js
check('認得出實際有的那幾支(不是寫死 TutorPod 的四項)', …)   // 這不是相依
```

⚠️ **兩次誤報都是我「修好」之後才發生的**——因為我一直在修「排除哪些東西」，
而**規則本身從頭到尾就是錯的**。「不准提到 TutorPod」不是我要的規則；
我要的是**「不准相依 TutorPod」**——import 它、或寫死一條指向它的路徑。

真正的修法有兩層：
1. **規則改成抓路徑形狀**（`from '…/ai-english-course/…'`、`"…/TutorPod …/…"`），
   不是抓那個字。
2. **檢查搬進 `npm test`，不留在 CI 的 YAML 裡**——
   寫在 YAML 裡的檢查只有 CI 會跑，**它第一次紅一定是在你人已經走了之後**。

⚠️ 而且這支檢查自己有反向測試（`一行假的 import 會被抓到`），
確認它不是一個永遠綠的裝飾品。

**下次什麼情況會再犯**：任何用 grep／正則去執行一條「規則」的地方。
先問兩題：
- **這條檢查抓到的東西，跟我真正想禁止的事情是同一件嗎？**
- **它紅的時候，是不是在我還能立刻修的地方紅？**

⚠️ 這跟 `status.mjs` 不准自己編門檻是同一個道理——
**會亂叫的工具沒有用，不管它叫得多有道理。**
CI 為了正當的理由紅第三次，你就會開始無視它，那時它等於不存在。

## L11　「沒有基準就拿自己當基準」，永遠回報「沒有變化」

**2026-09-10 · 相依偵測 · 測試抓到的（手動測試兩天沒抓到）**

```js
const depsBefore = since ? readDeps(git(['show', `${since}:package.json`])) : depsNow;  // ❌
```

沒有還原點的時候 `depsBefore === depsNow`，差集永遠是空集合。
**新增的相依一輩子不會被報出來**——而畫面上「新增相依：0 個」
跟「真的沒有新增相依」長得**一模一樣**。

正確的基準是 `HEAD`（＝還沒 commit 的東西），不是工作區自己：

```js
const depsBefore = readDeps(git(['show', `${since ?? 'HEAD'}:package.json`]));  // ✅
```

**下次什麼情況會再犯**：任何「跟之前比」的功能，在**「之前」不存在**的時候。
先問：**基準缺席的時候，我拿什麼當基準？** 拿自己當基準＝永遠沒有差異＝
一句永遠成立的假話。這是 R1 的另一個身體。

⚠️ **這一條是這個專案第一個「只有測試抓得到」的 bug。**
它不會當機、不會報錯、畫面看起來完全正常——我手動測了兩天都沒發現。

## L12　寫出資料的程式碼、跟 `.gitignore` 那一行，是同一個決定的兩半

**2026-09-10 · 感測器紀錄被 commit 並推上 GitHub**

`.gitignore` 寫了 `checkpoints/`，**漏了 `logs/`**。
而 `logs/` 裡是使用者打的**每一則訊息前 200 字、對話標題、專案路徑**。
推上 GitHub 之後才發現。

⚠️ **這種錯沒有任何徵兆**：git 不抱怨、測試不紅、功能完全正常。
跟 L1（路徑有空白就靜默失效）、L11（拿自己當基準）是同一族——
**都是「看起來一切正常」的失敗**。

**修法不是「下次小心」**，是 `scripts/privacy.test.mjs`：
維護一份「程式自己會寫出來的資料夾」清單，斷言它們
**既沒有被追蹤、也確實有寫進 `.gitignore`**。

**下次什麼情況會再犯**：任何新增「會寫檔到專案資料夾」的功能時。
⚠️ 加了會寫檔的程式碼，就要同步加進 `MUST_NEVER_BE_TRACKED` 那份清單——
**只做前一半，私人資料就上去了。**

> 這跟 `CLAUDE.md` 的「新增 docs 檔必須同步改索引」是同一個形狀：
> **兩個動作其實是一個決定，而工具只會提醒你做了一半的那一種。**

## L10 的第三次（2026-09-10 · AC-8 的百分比檢查）

「畫面不准出現百分比」的檢查掃到了 CSS 的 `width: 100%`、`border-radius: 50%`、
漸層的 `transparent 70%`——**那些是版面長度，不是給人看的進度。**

⚠️ **同一個毛病第三次。** 前兩次是註解、是測試標題，這次是 CSS 長度。
每一次我都在修「要排除什麼」，而根因一直是**規則描述的東西不是我要禁止的東西**。

正確的規則是：**「輸出到畫面的字串裡有百分比」**，不是「檔案裡有 `%` 這個字元」。
修正後的檢查只看字串字面量與樣板字串，而且附了四條反向測試：

```
✓ 會抓到 `完成 87%` 這種字串
✓ 會抓到樣板字串算出來的百分比
✓ 不會誤殺 width: 100%
✓ 不會誤殺漸層的 70%
```

⚠️ **反向測試是這一條真正的解法。** 一個檢查如果沒有人證明過它「抓得到真的、
放得過假的」，它就只是一個會週期性亂叫的東西。

**下次什麼情況會再犯**：任何時候寫一條「不准出現 X」的檢查。
先寫兩個例子:**一個必須被抓到、一個必須被放過**，寫不出來就表示規則還沒想清楚。

## L13　「掛著」不等於「活著」——絕對路徑會靜默失效

**2026-09-10 · 把 pipeline-monitor 資料夾從 TutorPod 底下搬到桌面**

`--on` 把 hook 的**絕對路徑**寫進被監看專案的 `.claude/settings.local.json`：

```
sh "/Users/…/TutorPod AI v4/pipeline-monitor/hook.sh"
```

資料夾一搬，那個路徑就指向一個不存在的檔案。
而 `hook.sh` **刻意設計成永不打擾 Claude**（AC-2，失敗一律 `exit 0`）——

⇒ **紀錄完全靜默地停止增加。設定看起來一切正常。**

⚠️ 這是這個專案最痛恨的失敗形狀，而且是**它自己的安全設計造成的**：
「絕不打擾使用者」跟「壞掉要有人知道」在這裡打架，而我只做了前者。

**修法**：`mountState()` 回三態 `off` / `ok` / `broken`，
`broken` = 設定裡有我們的 hook，但它指向的檔案不存在。
終端機與網頁都要明講「**紀錄已經停了，而且不會有任何徵兆**」並給修法。

**下次什麼情況會再犯**：任何把絕對路徑寫進別人設定檔的地方。
先問：**這條路徑失效的時候，誰會知道？**
答案是「沒有人」的話，就要另外做一個知道的人。

⚠️ 附帶一提，這也是 L12（`.gitignore` 漏一行）的同一族：
**設定寫對了 ≠ 它真的在做事。** 兩件事都要有人檢查。

## L2 的第三次（2026-09-11 · 同一個畫面三種問法）

Oscar 在 TutorPod 上重現：`git add` 過的改動顯示「沒有改動」，同一畫面又寫「你有 2 個檔案還沒存進保險箱」；
新資料夾放 3 個新檔，「回去會丟掉 1 個」；只刪不加顯示「+0 −0 行」。

三個都是同一件事：**「改動」在同一個畫面上被問了三次，用三種 git 指令，各有各的盲點**——
沒帶 HEAD 的 `git diff` 看不到 add 過的；`git status --porcelain` 把整個資料夾算一行；
讀 `--shortstat` 的規則假設一定有「insertion」。

⚠️ 前兩次修的都是「補上漏掉的那一種」，這次才看清楚形狀：**每多一種問法就多一種盲點，
而且兩個數字會在同一個畫面上互相拆穿。** 修法不是再補一種，是**基準只決定一次**
（有章比章、沒章比 HEAD）、「還沒存進保險箱」只有一份算法（`uncommitted()`，網頁也用它），
然後用測試釘「同一畫面的兩個數字必須相等」。

這條升格成老毛病 [P1／P2](FAILURE-PATTERNS.md)。

**下次什麼情況會再犯**：畫面上任何兩個「看起來應該相等」的數字。先問它們是不是同一個查詢算出來的。

## L14　「回去」的指令，要先看章跟現在的 commit 是什麼關係

**2026-09-11 · 主資料夾的還原點指著清歷史之前的版本**

09/10 清掉被 commit 的對話紀錄時歷史被改寫，章記的 SHA 從此不在 main 上。
但那個 commit 物件還在倉庫裡，`git diff <章>` 照樣算得出「之後改了 28 個檔案」——
**畫面看起來完全正常**，而它給的 `git reset --hard` 會把人帶回清理前那條歷史，
連被清掉的紀錄一起帶回來。整整一天都這樣顯示。

同一天 Oscar 在 TutorPod 上重現另一半：章之後又 commit 了 2 次，畫面只給 `reset --hard`，
照做之後那 2 次就從分支上消失。

兩件事同一個根：**AC-3 只把「還沒 commit 的檔案」當成回去會丟的東西，從沒問過章的版本跟 HEAD 的關係。**

修法：`checkpointRelation()` 先問 git 兩件事（還在這條分支的歷史上嗎？之後有幾個 commit？），
四種答案刻意分開——`ok`／`off-branch`／`gone`／`unknown`——**只有 `ok` 才准給回去的指令**，
而且章不能用時，改動體檢的基準也退回 HEAD，並在畫面上講明。
有存檔要丟時，先給 `git branch 備份-…` 再給 reset，跟 stash 那段同一個節奏；
網頁版把備份跟 reset 用 `&&` 串成一條，備份沒成功就走不到 reset。
`describeCheckpoint()` 抽成純函式，測試釘住「章不能用時輸出裡不准有 `reset --hard`」。

**下次什麼情況會再犯**：任何把「一個舊的 SHA」印成指令的地方。先問：**這個 SHA 跟現在的 HEAD 是什麼關係？**
`git diff` 對任何存在的 SHA 都算得出數字，它不會替你檢查那個 SHA 還在不在路上。

## L9 的第二次（2026-09-11 · 「專案名 → 檔名」三處各算一次）

hook.sh 用 `tr -c 'A-Za-z0-9._-' '_'` 把專案名洗過再存檔（`TutorPod_AI_v4.jsonl`）；
讀取端拿原名去找（`TutorPod AI v4.jsonl`）；還原點的檔名又是第三種規則（另一個 regex，會把連續的字元併成一個底線）。
三處各自「合理」，合起來的結果是：**資料夾名有空白或中文的專案，感測器明明在記，畫面永遠說「還沒有紀錄」**；
中文名的專案在網頁上會變成兩張卡。

L9 講的是文件抄第二次就是第二個真相來源。這次是程式碼——而且是**兩種語言**（sh 與 node）
對同一件事各寫一次，沒有任何東西逼它們一致。再加一層：BSD 的 `tr` 在 UTF-8 locale 下把中文當一個字，
在 C locale 下當三個位元組——**同一行指令在不同環境給不同答案**，而 hook 跑在哪種 locale 我們管不到。

修法：hook.sh 那行加 `LC_ALL=C`，讓答案不隨環境變；JS 端一個 `safeName()` **逐位元組**照同一條規則翻譯；
讀紀錄、寫章、`--clear` 都走它。但翻譯終究是兩份，所以真正的解法是那條測試：**真的跑一次 hook.sh**，
餵一個有空白和中文的名字，斷言 hook 寫出的檔名 = `safeName()` 算出的檔名。改任何一邊，它會紅。

**下次什麼情況會再犯**：hook.sh 與 status.mjs 要對同一件事有共識的任何地方。
兩種語言各寫一次的規則，一定要有一條「真的跑兩邊」的測試釘住。

## L16　「沒有東西要做」不等於「做完了」——空的分支一格燈都不該亮

## L18　測試裡的「現在」只准取一次

**2026-09-15 · `scripts/sensor.test.mjs` · 症狀：整套 `npm test` 偶爾紅，單獨跑永遠綠**

```js
const t = (n) => new Date(Date.now() + n * 1000).toISOString();   // ❌ 每次呼叫都問一次「現在」
```

造事件時呼叫一次 `t(2)`，斷言時再呼叫一次 `t(2)`。兩次 `Date.now()` 隔著幾毫秒——
機器一忙（整套測試同時在跑 git）就跨過一個毫秒，兩個字串對不起來。
同一支測試單獨跑三次全綠，整套跑就紅，**看起來像是別的改動弄壞的**（這次就是在做另一個功能時撞到）。

```js
const base = Date.now();                                          // ✅ 「現在」取一次
const t = (n) => new Date(base + n * 1000).toISOString();
```

**下次什麼情況會再犯**：任何在測試裡呼叫 `Date.now()`／`new Date()` 兩次、然後期待兩邊相等的地方。

後來：Oscar 決定接，只講到對話層級——卡上標「這個對話後來叫過收回（理由：…），分不出是不是這一張」，不配對、不自動收（app 建議卡 AC-7）。

## L23　兩個分頁就讓儀表板卡死：每次都整頁重算的伺服器，碰上不等上一次回來的輪詢

## L11 的第二次（2026-09-22 · 沒章時拿「上一次存檔」當基準，存一次檔就歸零）

**2026-09-21 在「施工對話認規格」那個施工對話實測到 · 規格：這一輪的起點**

沒有還原點的工作區，「這次改動」比的是上一次存檔（`git diff HEAD`）。Claude 收工前先 commit，
基準就往前跳到剛存好的那一版——**拿剛存好的版本跟現在比，就是拿自己跟自己比**，差 0 個檔案。
於是分級說「沒有改動」、收工 hook 放行（這一輪碰了危險清單，C 沒跑、D 過期，一樣放行）、你調高的等級也跟著消失。
同一個存檔動作，五關的 D 反而變成「之後又改了程式檔——要再跑一次」：B 為了不丟證據會翻存檔紀錄，**把存檔的時間當成改檔的時間**。
一邊說沒動、一邊說又動了，兩邊都不是事實。

跟 L11 同一個身體：基準缺席（沒章）時拿了一個會**被我正在量的那個動作自己移動**的東西當基準。
L11 是「拿自己當基準」；這次是「拿上一次存檔當基準」——存檔一次，它就變成自己。

修法：沒章時，基準是**這一輪開始那一刻** HEAD 指的版本（reflog 查得到；app 開 worktree 那一刻就有一筆）。
⚠️ 後來（2026-10-02）：「app 開 worktree 那一刻就有一筆」不成立了——10/1 起 app 開的資料夾沒有這一筆，reflog 查不到時改看感測器記的版本號（L31）。
「這一輪」跟五關同一個分界（A、蓋章），都沒有就是這個對話在這個資料夾的第一筆紀錄（通常是第一句話）；存幾次檔都從那裡算。
存檔過的檔案留在清單裡，改檔時間看檔案本身，不拿存檔時間頂。找不到那一刻的版本就照實說「存檔過的看不到」，
那個 0 不准畫成「沒有改動」（老毛病 P5）。

另外一個差點漏掉的：規格連結（`--spec`）**不能**當起點——Claude 常在收工時才照收工 hook 的建議記連結，
比施工晚；拿它當起點，施工的存檔又全落到起點前面，換一個洞而已。

**下次什麼情況會再犯**：任何「跟之前比」的功能，先問：**這個「之前」會不會被使用者（或 Claude）正常做事的某個動作移動？**
存檔、切分支、重新整理、重新載入都算。會的話，它不是基準，是現在的另一個名字。
還有：測試把劇本寫在「幾分鐘前」、repo 卻是測試當下才建的——時間線不可能發生，新的起點邏輯會安靜地走退路，
測試照樣綠、測的卻不是真的會走的那條路。測試用的 repo 預設改成一小時前建好。

## L21 的第二次（2026-09-22 · 紀錄裡記的規格路徑，開工一搬家就指著空位置）

**2026-09-22 在「這一輪的起點」那個施工對話實測到 · 規格：規格搬家**

L21 是程式標頭抄了規格的路徑；這次是**紀錄**記了規格的路徑。感測器記下 A 那次寫檔的位置、A 收尾 `--report` 記下相對路徑，
兩個都是**記的那一刻**的位置。而工作項的狀態就是路徑：你點頭、Claude 照 CLAUDE.md 把規格搬到進行中，那個位置就空了。

而再跑一次 A 只會開新的一輪。

修法：兩條路都走同一個找規格檔的函式，記的位置搬走了就在規劃中／進行中／升級摘要找同名檔；同名不只一份不猜；
找到的跟記的不一樣就講一句「規格搬到了」。「對完清單的時間」新舊兩個路徑都認（搬家前打的勾記在舊路徑上）；

同一件事還有幾條路也一起接上：記在主資料夾、記在工作區外、對話待在子資料夾、對話的資料夾已經不在——都照記的地方找，不拿同名的另一份頂替。

**下次什麼情況會再犯**：任何拿**以前記下來的路徑**去讀 docs/ 底下工作項的時候——紀錄、結論、連結、任何存起來的東西。

## L25　拿「別的事也會造成」的證據，當「這件事發生了」：檔案的修改時間不是打勾的時間，同名的檔不是同一份

**2026-09-22 · 規格搬家（規格原本就這樣寫，魔鬼教官第一輪抓到）· 症狀：D 說找到問題，畫面卻畫成「已走過」；B 拿上一輪那份規格的舊勾結案**

兩件事是同一個錯：

- **修改時間**。規格寫「對完清單的時間改看規格檔本身的修改時間」，理由是用 Bash 打的勾感測器看不到，檔案看得到。
  但檔案被改的理由不只打勾：照 CLAUDE.md 往下追加施作紀錄、git checkout／stash 改寫檔案，都會改到它。
  B 的結案時間就跳到「追加紀錄的那一刻」，變成這一輪的最後一步，D 的「找到問題」跟著被畫成已走過，對話列寫「這一輪走到 B 寫程式（處理完了）」。
- **同名**。記的位置不在了，就在三個資料夾找同名檔，找到一份就當成搬家後的那一份。
  但名字會被重用：上一輪做完的同名規格就躺在升級摘要，全部打勾。新的那份一改名，B 就拿舊勾結案；舊的那份有沒標的條目時，收工 hook 還叫 Claude 去已結案的規格補勾。

修法：打勾的時間改回看感測器記到的改檔（新舊兩個路徑都認），用 Bash 打的勾看不到就退回最後一次改程式的時間——**寧可早，不可晚**。
同名檔多一道證據：這一輪 A 寫的檔，修改時間不可能早於這一次 A；比它還舊的同名檔就是別份，照實講「不是這一輪寫的那份」，不畫它的清單。

**下次什麼情況會再犯**：任何拿一個檔案的屬性（修改時間、名字、大小、在不在）當「某個動作發生了」的證據的時候。
先問：**還有哪些別的事，也會留下一模一樣的證據？** 答得出來，這個證據就只能當「可能」，要嘛再找第二個證據，要嘛照實講分不出來。
這是 R2 的形狀（「跑過」講成「通過」）：證據能證明的只有「檔案被改過」「有一份同名的」，不是「勾是這時候打的」「就是那一份」。

## L28　只綁 127.0.0.1，不等於只有「儀表板這一頁」連得到

**2026-09-24 · `server.mjs` · 程式整理那個對話讀程式時查到 · 實測：帶著假的網址連進來，照樣回整份資料**

README 與 server.mjs 開頭都把「只綁 127.0.0.1、不給對外的開關」當成安全的全部。它只擋得住**別台電腦**，
擋不住**你電腦上的瀏覽器替別的網站連進來**——三條路：

1. **網址**：惡意網頁把自己的網址暫時指到 127.0.0.1（DNS 重新綁定），瀏覽器就當它是同一個網站，讀得到 `/api/status`：
   所有專案的路徑、分支、你打過的字。伺服器不看連進來用的網址（Host），照給。
2. **按鈕**：同源檢查只看是不是 localhost、不看埠。同一台電腦上的開發伺服器頁面也按得到「你說驗收過了」——那句話只准你說。
3. **框架**：沒有防框架的標頭，別的網頁可以把儀表板框起來，騙你點按鈕。

有沒有真的被這樣用過，紀錄裡看不出來。修法：網址不是 127.0.0.1／localhost 一律 403；Origin 要一字不差是 `http://<Host>`；
每個回覆都帶 `X-Frame-Options: DENY` 與 `frame-ancestors 'none'`。`scripts/ui.test.mjs` 標 P3 的那一段釘住，換回舊的 server.mjs 會紅 9 條。

**下次什麼情況會再犯**：任何「只在本機跑」的伺服器。綁定位址只回答「誰連得進來」，不回答「是誰叫瀏覽器連的」——
要另外看 Host（用哪個網址連進來）與 Origin（哪一頁送的）。

## L30　換掉一個大家都在 append 的檔：「換之前看一眼」擋不住還在路上的那一行

**2026-09-24 · `lib/events.mjs` 的 90 天清理 · 還沒真的發生過（第一次清在 12/9 左右），魔鬼教官兩個 agent 跟我各自重現**

清理照規格做：寫暫存檔，換上去之前再看一眼原檔變長了沒，變長就這次不換。規格還寫「你按的按鈕是一口氣寫完的，沒有空檔」。
實際上暫存檔 fsync 的那幾毫秒（macOS 上 node 的 fsync 是整顆磁碟的 flush），別的程式的 append 被磁碟擋著；
放行的時候清理已經看完那一眼、正要換檔——那一筆寫進被換掉的那一份，就沒了。按鈕、`--report` 一樣會中。
hook.sh 本來就有同一種空檔：shell 先打開檔案、jq 算完才寫。兩種都是「先打開、看完那一眼之後才寫」。

修法：換上去之後舊的那一份先不放，把讀的那一刻之後多出來的整行補到新檔，停 50 毫秒再補一次。密集寫入的實驗從每次丟 25～30 行變成 0。

**下次什麼情況會再犯**：任何「把一個別人會 append 的檔整份換掉」的地方。先問：**寫的人是不是「打開」跟「寫」分兩步？中間會不會被卡住？**
會的話，換之前看幾眼都擋不住還在路上的那一行——要在換完之後把它撈回來，或乾脆不換（分冊：舊的整冊收起來、讀的時候幾冊一起讀）。
規格寫「這一種不會」之前，先真的撞一次。

## L32　「每一關最後一筆」把同時成立的好幾筆吃成一筆：一次 A 寫兩份規格，畫面只掛一份還說「全部」

**2026-10-02 · 同一次查到的 · 規格：多份規格與新資料夾的起點**

TutorPod「接著處理語音練習斷線的後續待辦」叫一次 A 寫了兩份規格（語音斷線 10 條、報告時間 5 條），Claude 收尾兩份都用 `--report A` 記了。

根源：結論的取法是「每一關最後一筆」（`reportsIn`），A 寫了哪份也只認一份（`specOfRun`）。兩筆結論不是「後一筆更正前一筆」，是同時成立的兩件事。
「全部 5 條」更糟：它不只少了 10 條，還**宣稱完整**——看的人沒有理由懷疑。

修法：A 寫了哪幾份看那次 A 之後的每一筆結論（一筆裡一行一個也認）加上感測器記到的寫檔，同檔名算一份；
每一份各一張清單，條數只加讀得到的，「全部 N 條」只在一份的時候出現；收工 hook、E 都照每一份要。

**下次什麼情況會再犯**：任何「取最後一筆」「取第一個找得到的」的地方。先問：**後面那一筆是更正前面那一筆，還是另一件同時成立的事？**
是後者的話，取一筆就是丟資料；畫面上任何「全部」「共」的字，都要先問它的分母是不是真的全部（R3）。

魔鬼教官第一輪（派 3 個 agent）在修法裡又抓到同一個形狀兩次：分級卡的 A 那一行照舊取最後一筆結論（同一頁一邊說 2 份、一邊只講一份）；
A 結論的說明一整行當一條路徑——Claude 把兩份寫在同一行，又只認得一份。修一個「只取一筆」的地方，要把**所有**讀同一份紀錄的地方一起找出來。

## L35　「判斷之後才新加的」拿存檔時間猜：判斷過的新檔，一存檔又變成沒人判斷過

**2026-10-06 · 危險清單會過期（v0.20.0，剛結案） · 寫下一份規格（收工hook問危險清單）時，照真的順序走一遍才抓到**

`--tier-checked` 只記了判斷的時間。「之後才新加的」= 那之後的存檔新增了哪些＋修改時間比較晚的還沒存檔的新檔。
最常見的順序是：Claude 新增一個檔 → 你判斷「不危險」→ Claude 存檔。存檔那一刻，這個檔在 git 眼裡才「新增」——
晚於判斷時間，於是分級卡與 `--tier-review` 又寫「危不危險還沒有人判斷」。這是假話，而且收工 hook 一旦會為它擋，每存一次檔就再擋你一次。
D 兩輪都沒抓到；測試釘了「判斷之後還沒存檔的不再問」，沒釘「判斷 → 存檔」——真的會發生的下一步。

修法：判斷那一刻記下快照（那時的版本＋那時還沒存檔的程式檔）；「之後才新加的」= 不在快照裡的。git 說的「清單定好那一次」也照那個版本比。不再拿時間猜。
跟 L11 第二次同一個身體（存檔的時間被當成改檔的時間）——進了老毛病 [P9](FAILURE-PATTERNS.md)。

## L36　問的是一部分，記的是一整份：收工 hook 只列這一輪碰到的新檔，`--tier-checked` 卻把整份清單記成判斷過了

**2026-10-06 · 收工hook問危險清單 · 魔鬼教官第一輪抓到（還沒上線）**

`--tier-checked` 從第一天就是「整份清單判斷過了」：原本只有「幫我看危險清單」一條路，那條路先跑 `--tier-review` 列整個專案，問的跟記的是同一份。

存檔與蓋章卡要分「還沒 commit 的」跟「已經 commit 的」：還沒 commit 的問 `git status --porcelain`，改過的問 `git diff --name-only`、`ls-files`，
已經 commit 的 = 改過的扣掉還沒 commit 的。試了一個叫 `a b.txt` 的檔：`git status` 印成 `"a b.txt"`（帶引號，`core.quotepath=false` 也一樣），
`diff`、`ls-files` 印成 `a b.txt`——扣不掉，這個還沒 commit 的檔會同時被列成「已經 commit、還沒蓋章」。舊的卡片早就有同一個洞：
這種檔永遠標不到「還沒存」，只是那時候沒人看得出來。另外，改名 `add` 過之後，`git status` 只算一筆、只給新路徑；改動清單是 `--no-renames`，新舊兩個都列。
修法：`git status` 加 `-z`（不加引號、不跳脫，改名寫成新舊兩段），改名的舊路徑也算還沒 commit。`diff`、`ls-files` 也會替雙引號、反斜線、tab 這種字元加引號——
一開始覺得太少見、只記在這裡沒修，魔鬼教官第一輪照樣抓出來，Oscar 說修掉：那兩題的檔名先把引號拿掉、換回真的檔名再比（`unquotePath`）。

**下次什麼情況會再犯**：任何拿兩種 git 問法的結果互相比對、扣減、找交集的地方。先問：**兩邊印出來的路徑，是同一種寫法嗎？** 拿有空白、有中文、改過名的檔各試一次。

## L45　一句永遠掛著的警告，讀起來就是現況

**2026-10-29 · Oscar 看 AI Automation Suite 的對話頁 · 症狀：都 commit 了，他以為還有東西沒 commit、說「都存了」的三階梯算錯**

還原點卡那一行「⚠️ 回去會丟掉還沒存（commit）的東西」是 10/27 刻意留在外面的：會害你丟東西的話不收起來。可是它不看狀態，永遠掛著。
旁邊那張卡大字寫「23 個檔案」（其實是蓋章之後改過的），兩句一起讀，就成了「還有 23 個沒 commit」。當場查 git：那個資料夾和主資料夾都是 0 個。
寫的人心裡是「萬一有，回去就沒了」，讀的人看到的是「現在有」。
修法：照實際講。有幾個講幾個，問不到講問不到；一個都沒有，就只講「現在沒有還沒 commit 的檔案」，不掛 ⚠️。

**下次什麼情況會再犯**：任何寫死的提醒、警告、說明，放在會變的數字旁邊。先問：**狀態是「沒有」的時候，這句話讀起來會不會像「有」？** 會的話，就讓它跟著狀態變。

## L46　測試只在沒有捷徑的資料夾跑過：主資料夾一搬家，蓋章就被「問不到」擋下來

**2026-10-29 · 紀錄搬到固定的家上線之後第一次蓋章 · 症狀：主資料夾 `--checkpoint` 跑測試，privacy.test 紅兩條「logs/、checkpoints/ 有寫進 .gitignore」，不蓋章**

## L47　規格從別的分支快轉進來：`--spec` 把它認成「這個對話自己寫的」，後來記得上是巧合

**發生了什麼**：2026-10-29 照建議卡施工「儀表板與終端機中英切換」，卡片叫我把寫規格那條分支快轉併進自己的資料夾（不動 main）再記 `--spec`。
`--spec` 回「看起來是這個對話自己寫的」——判斷「這個工作區只有這個對話在用、main 上沒有這份」把它認成新寫出來的。
收工 hook 要 A 時再跑一次，這次收了：背景的魔鬼教官 agent 也在這個資料夾留了紀錄，「只有這個對話」不成立了。記下來的那句是真的，能不能記上靠的是巧合。

**下次什麼情況會再犯**：寫規格的對話跟施工的對話不在同一個資料夾、規格還沒併進 main 就開工（照卡片快轉規格分支）。
**怎麼避免**：開工前先把規格併進 main；或修那一條判斷（例如規格也在別的分支上，就不算這個對話新寫的）——還沒決定要不要修。

## L48　中英兩欄並排的寫法，兩欄都會算：從條件裡搬出來的那一行，另一種語言用不到也照樣算

**發生了什麼**：中英切換把每一句寫成 `zhEn(中文, English)`。JavaScript 兩個參數都先算好才挑——
建議卡「你那時說：「…」」那一句改寫時，我把只有「有你說的話」才算的那一段搬到條件外面先算好，沒有話的卡整頁就壞（舊的測試當場抓到）。
同一次另一個形狀：英文的「過了多久」要放進句子中間，只好由每一種狀態自己帶，E 那一支漏了（魔鬼教官抓到，老毛病 P2）。

**下次什麼情況會再犯**：把既有的句子改成兩欄並排、而原本的句子裡有「條件成立才算」的那一段；或某個語言的詞序跟另一個不一樣、得把同一件事放到兩個地方。
**怎麼避免**：搬出條件的那一行照樣留在條件裡算（`said ? … : ''`）；英文另外放的那一份，每一種狀態都要有測試考它（`scripts/lang.test.mjs`）。
