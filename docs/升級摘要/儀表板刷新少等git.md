# 功能：儀表板刷新一次不要等將近 10 秒——少等 git，但畫面上每個數字照舊

分級：**預測至少 T1**（會動到程式區的 `lib/git.mjs`、`lib/origin.mjs`、`lib/tier.mjs`、`lib/collect.mjs`，另加測試）。
**刻意不碰**危險清單上的 `lib/paths.mjs`、`lib/mount.mjs`——兩支裡也有叫 git 的地方，但 2026-10-25 量的那一次刷新一次都沒走到它們。
寫程式時要是發現非碰不可，就是 T2，要先回來講。

> 2026-10-25 量測（只量不改，各跑 5 次取中位數，5 個專案、40 張卡）：一次刷新 **9.9 秒**，其中 **98%** 花在呼叫 git，**844 次**。
> 原因有兩個：① Mac 的 `/usr/bin/git` 是轉介程式，每呼叫一次要先多花約 7 毫秒去找真正的 git（光問版本：9.8 毫秒 對 2.7 毫秒）；
> ② 同一次刷新裡有 **185 次**是重複的問題（例如「這個資料夾有哪些還沒存的改動」，每個資料夾問 3 次）。
> 不改程式、只讓 PATH 先找到真正的 git：9.9 秒 → **3.8 秒**；那次刷新問過的 601 個不同問題，兩邊答案一字不差（路徑有空白的 96 個當時沒比到）。
> 讀了 `CLAUDE.md`、`docs/FAILURE-PATTERNS.md`（P1、P2、P5、P8）、`.claude/pipeline-stages.json`、`server.mjs` 的共用那段、`lib/git.mjs`、`lib/collect.mjs`。

## 這是為了解決什麼

儀表板每 5 秒要一次資料，伺服器算一次卻要將近 10 秒；專案和資料夾越多越慢（10/06 量到 3.9 秒、23 張卡）。畫面永遠在等，看起來像斷線。

## 驗收條件

**AC-1　每一個 git 問題，直接問真正的 git，答案跟以前一字不差** ✅ 對過 2026-10-26
> **白話**：以前每次打電話都先打總機，總機再幫你轉分機；現在直接撥分機。接電話的是同一個人，講的話一樣。
> **會發生的情況**：儀表板、終端機、收工 hook 看到的每個數字、每句話都跟以前一樣，只是快了。
> **技術**：真正的 git 的位置，在**這個程式啟動時找一次**（例如 `git --exec-path` 旁邊的那一支，或 `xcrun -f git`）；`lib/git.mjs` 的 `git()`／`gitExit()`／`dirtyPaths()`、
> `lib/origin.mjs` 兩處、`lib/tier.mjs` 的 `gitOut` 與 `ls-files` 都改成用它（集中在 `lib/git.mjs` 一個地方，P2）。
> 驗法：把一次刷新問過的**每一個**問題（這次含路徑有空白的、用 `-C` 的）兩支各問一次比答案；不同的就照實記下來，不准折成「大致一樣」。

**AC-2　找不到真正的 git、或它中途不見了，就照以前的方式問——不准把「這次沒問到」變成「沒有」** ✅ 對過 2026-10-26
> **白話**：分機打不通，就回去打總機；不能因為分機沒人接，就在畫面上寫「沒有改動」。
> **會發生的情況**：不是 Mac、沒裝開發工具、更新開發工具時那支檔案暫時不在 → 畫面跟現在一模一樣（只是慢）。
> **技術**：找不到 → 用 `'git'`。找到的那支在呼叫時回「檔案不存在」→ 那一次立刻改問 `'git'`，之後重新找一次。只有「跑不起來」才退回；
> git 自己回答「不是」（離開碼 1）、或回錯誤，**不准**退回再問一次去湊答案。「位置」這個記憶只活到程式結束；重啟服務（`--serve-restart`）就重新找。

**AC-3　同一次刷新裡，同一個問題只問 git 一次** ✅ 對過 2026-10-26（只包 collectAll；cardFor 照 AC-6 不包，Oscar 定的）
> **白話**：一次點名裡，同一個人被問三次「你到了沒」，問一次就夠了。下一次點名一定重新問。
> **會發生的情況**：一次刷新呼叫 git 的次數變少（量了才寫多少，R3）；畫面上的數字不變。
> **技術**：只在一次 `collectAll()`（和 `cardFor()`）裡共用。完全相同的「問題＋資料夾」才算同一題——`-C 路徑` 跟 `cwd` 兩種寫法不合併也沒關係（只是省得少，不會錯）。
> 輸出的樣子要分開記：`git()` 會切掉前後空白，`dirtyPaths()` 要原文（P1：切掉第一個空白，第一個檔案就標不到）；`gitExit()` 記的是離開碼。

**AC-4　刷新一結束，記下來的答案就全部丟掉；下一次刷新一定重新問** ✅ 對過 2026-10-26
> **白話**：點名表點完就撕掉，不留到下一堂課。
> **會發生的情況**：你在別的對話存了一個檔，下一次刷新（5 秒內）畫面就看得到，跟現在一樣快。
> **技術**：記憶跟著那一次呼叫的生命走（傳進去的物件、或呼叫結束時清空），不放在模組的全域變數裡讓它活過一次刷新；
> 例外丟出來也要清空。`server.mjs` 那 4 秒「好幾個分頁共用同一份」照舊，不改、不延長。
> 測試：兩次 `collectAll()` 中間做一次存檔，第二次一定看到新的版本；第一次的答案不准漏到第二次。

**AC-5　問失敗的不共用：同一次刷新裡再問到，就再問一次** ✅ 對過 2026-10-26
> **白話**：點名時那個人剛好在廁所沒回答，下一個老師問的時候要再叫一次，不能直接抄「缺席」。
> **會發生的情況**：git 剛好被別的對話鎖住、暫時答不出來 → 後面同一題照舊重新問；問到了就照實講，問不到才照現在的方式說「問不到」。
> **技術**：只記成功的答案（`git()`／`dirtyPaths()` 回 null 的不記；`gitExit()` 只記 0 和 1——那是 git 的回答；其他離開碼和跑不起來都不記）。

**AC-6　收工 hook、終端機、感測器的行為不變** ✅ 對過 2026-10-26
> **會發生的情況**：收工 hook 擋不擋、終端機每一行字，改前改後一樣（只是 AC-1 讓它們也變快）。`hook.sh` 一個字不改。
> AC-3、AC-4 的「同一輪只問一次」只用在儀表板的那一次整理；終端機、收工 hook 要的話另外講，這一份不做。

**AC-7　改完再量一次，照同一個方法，數字寫在施作紀錄** ✅ 對過 2026-10-26
> **會發生的情況**：用 2026-10-25 那一支計時腳本的方法，各跑 5 次取中位數，寫「改前／只做 AC-1／兩個都做」的秒數與 git 呼叫次數，以及那時有幾個專案、幾張卡。
> 不定「要快到幾秒」的目標——那是編的門檻（CLAUDE.md：不自己編門檻）。合併、`--serve-restart` 之後，再看一次常駐服務的回應時間。

## 混沌推導

▸ **併發**：一次刷新途中，別的對話剛好存檔 → 以前同一題問三次，可能拿到前後不一樣的答案（同一頁兩個數字對不上，P2）；改了之後同一頁用同一份答案，反而一致。下一次刷新照樣看到新的。
▸ **時間**：開發工具更新、真正的 git 換了位置 → AC-2，呼叫失敗就退回、重新找；不會因此一直「問不到」。
▸ **權限**：真正的 git 那支檔案存在但執行不了 → 跟「不存在」一樣退回 `'git'`。
▸ **容量**：記憶只活一次刷新，大小就是那一次的問題數；`ls-files` 這種大輸出照現在的上限，不另外存。
▸ **測試換電腦**（P8）：GitHub 的機器不是 Mac、沒有轉介程式——測試不准假設一定找得到「另一支」git；找不到時要走 AC-2 那條路，照樣綠。

## 明確不做

- **不做跨刷新的快取**（例如「git 沒變就用上一次的答案」）——那要講清楚什麼時候過期，講錯一次畫面就說謊。
- 不改 `lib/paths.mjs`、`lib/mount.mjs`（危險清單；這次刷新沒走到）、不改 `hook.sh`（sh，另一條路）。
- 不減少任何一個要問的問題、不拿掉任何畫面上的數字或句子——只合併**一模一樣**的重複。
- 不改畫面每 5 秒要一次的間隔、不改伺服器 4 秒的共用。
- 不把一張張卡改成同時問（平行）——那是另一件事，量完這次再說。
