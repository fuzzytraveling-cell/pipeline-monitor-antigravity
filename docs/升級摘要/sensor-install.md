# 功能：`--install` —— 把感測器裝到一個新專案

分級：小。**還沒開工。**

## 這是為了解決什麼

現在要讓一個新專案有五關時間戳，得**手動編輯**那個專案的
`.claude/settings.local.json`。第二個專案就會卡在這裡。

## 大致的樣子

```sh
cd ~/some-other-project
pipeline-status --install     # 把 4 個 hook 裝進 .claude/settings.local.json
pipeline-status --uninstall   # 拆掉
```

## 動手前一定要想清楚的（尚未寫成 AC）

- ⚠️ **那個檔案可能已經有別人的 hook。** 必須**合併**，不是覆蓋。
  弄丟使用者原本的 hook 是不可接受的失敗。
- ⚠️ **`.claude/` 在別的專案不一定有 gitignore。** 裝之前要檢查，
  如果沒有就明白告訴他「這個檔案會被 commit 進去」——**不要默默裝下去**。
- 已經裝過了要說「已經裝好了」，不要裝第二份。
- 裝完要**驗證它真的會動**（例如提示使用者跑一個指令看看有沒有紀錄），
  不是印一句「安裝成功」就算——那是 R1 的假成功。

### 2026-09-10　完成（`--on` / `--off`）

`lib/mount.mjs` ＋ `scripts/mount.test.mjs`（20 項）。

規格裡列的三個坑，全部處理並用測試釘住：

| 坑 | 怎麼處理的 | 測試 |
|---|---|---|
| ① 那個檔案可能已經有別人的 hook | **合併不覆蓋**。動手前先備份。`--off` 只拆掉指向 `pipeline-monitor` 的那幾筆 | ✅ 別人的 hook／`otherSetting`／`permissions` 都原封不動 |
| ② `.claude/` 不一定 gitignore | 裝完**明講**「這個檔案會被 commit 上去」，並給要加的那一行 | ✅ |
| ③ 不准假成功 | 明講「我只能確認設定寫進去了，**不能確認它真的會動**」，並給驗證方法 | ✅ 文案被測試釘住 |

額外處理：設定檔**壞掉時停手**（硬寫下去會蓋掉使用者原本的設定），重複掛不會愈加愈多。

⚠️ **原本規格想用「同意單」的做法**（在專案裡放一個空檔案，plugin 全域裝一次）。
那個做法更安全，但**前提是要有 plugin**，而 plugin 還沒做。
等 plugin 做出來，這一支可以簡化成「建一個空檔案」——那時再回來改。
