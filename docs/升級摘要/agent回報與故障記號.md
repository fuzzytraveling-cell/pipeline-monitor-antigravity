## 驗收條件

### 一、不是你打的話，不算你說的

**AC-1　子 agent 的回報不算你說的話** ✅ 對過 2026-10-05
> **白話**：外包的回報不是工頭的話。
> **會發生的情況**：照 bd87046e 那段的順序（你說話 → 擋 → agent 回報 → 收工）：收工 hook 只擋一次；「N 則訊息」不數它；它不會被當成「D／E 之後你說的原話」——Claude 拿它代記，畫面照今天的規矩說沒對到你的原話。
> **技術**：認得的系統訊息加 `<agent-message`。回合起點、訊息數、第一句話、D／E 之後你說的話照舊只走 `saidByHuman`（P7）。測試標 P7，用真紀錄的開頭形狀（不抄內容）。

**AC-2　沒見過的系統格式，不猜成你說的，而且要講出來** ✅ 對過 2026-10-05
> **白話**：對講機出現沒聽過的聲音，不當成工頭，也不裝沒聽到。
> **會發生的情況**：哪天又多一種 `<某某>` 開頭的訊息：不算你說的話；那個對話頁與 `pipeline-status` 寫「這個對話有 N 則開頭是 `<某某>` 的訊息，我認不出是誰送的（可能是系統，也可能是你打的字剛好這樣開頭），沒算成你說的話——把這句給 Claude 看，它會判斷該算誰的」。不上每一頁的橫條。
> 那段時間 Claude 代記「不用再跑／驗收過了」不算數時，講「只有 N 則認不出是誰送的訊息，沒當成你的原話」，不講「紀錄裡沒有你說的話」。（魔鬼教官第一輪改的：原本寫「不是你打的」——只講得出「認不出」，講不出「不是你」。）
> 你貼的（`<pasted_content`）、用 `!` 跑的（`<bash-input>`／`<bash-stdout>`／`<bash-stderr>`）、9/11 以前被系統在前面加了一段的（`<system-reminder`，P7 第一條）照舊算你開口，畫面、訊息數跟今天一樣
> （`!` 跑的照舊不當原話；`<system-reminder` 那種這次起也不當原話——截到 200 字只剩系統的字）。
> **技術**：`<` 開頭分三種：認得的系統訊息（不算、不出聲）、認得的你的動作（算）、沒見過的（不算、要出聲）。收工 hook 碰到沒見過的，兩種讀法各算一次、任何一種要擋就擋：
> 當成系統的（回合從你最後一句開始、擋過的不再擋）、當成你說的（回合從那則開始、之後改了程式才擋）。所以那則之後沒改程式就不擋，改了才再擋一次，不會少擋；
> 整個對話只有沒見過的，不准當成「沒記到你說的話」放行。句子 lib 裡寫一份（P2）。
> （魔鬼教官第一輪改的：原本「改了沒」與「擋過哪幾種」各取一邊，湊出兩種讀法都不成立的第三種回合——每來一則就把擋過的整張清單再擋一次，連沒改程式的回合也擋。）

### 二、壞了，畫面講對

**AC-3　還在壞的時候，終端機和儀表板每一頁都講，一字不差** ✅ 對過 2026-10-05
> **白話**：攝影機沒電，辦公室的螢幕跟你手上的終端機都要亮同一盞燈。
> **會發生的情況**：jq 不在、新專案一筆紀錄都沒有：`pipeline-status` 不再寫「要開新的對話才會開始記」「分不出來」，改講故障；儀表板每一頁上方一條同一句。全新電腦、一張專案卡都沒有時照樣出現。
> 只有收工 hook 的故障、或感測器已經好了的，「分不出來」與「開新的對話」照舊講（那時它們是真的）。
> 時好時壞的也照舊講，另外附一句「這台電腦的感測器時好時壞，開了也不一定記得到」——最後一筆故障之後明明又記到了，講「現在記不到」是假的（魔鬼教官第一輪改的）。
> **技術**：`readEvents` 在 `no-file` 時也讀 `_sensor.jsonl`；故障全機一份，只當警告，不蓋任何專案的紀錄（誠實修補 D2）。整段句子由 lib 一個函式算，終端機印它、伺服器把算好的放進一欄（沒故障給空的）、畫面只畫；
> 畫面看不到那一欄 → 講「儀表板的服務還在跑舊的程式，故障看不到——跑 `pipeline-status --serve-restart`」，不當成沒故障（L20）。測試拿同一份假紀錄比兩邊，標 P2。

**AC-4　講對是誰壞了、壞了的後果、怎麼修；不印程式的錯誤原文** ✅ 對過 2026-10-05
> **白話**：攝影機沒電跟大門鎖壞了是兩件事——一個是沒拍到，一個是沒鎖門就放人走。
> **會發生的情況**：今天全部講成「感測器回報過 N 次故障」。改成：
> 感測器（jq 不存在）→「那段期間沒記到」，修法「裝 jq；已經裝了還出現，是 Claude Code 跑 hook 時找不到它——把這句給 Claude 看」。
> 收工 hook 找不到 node →「那段期間收工 hook 沒檢查就放行了」，修法「裝 node；已經裝了還出現，把這句給 Claude 看」。
> 收工 hook 自己出錯 → 後果同上，修法「把這句給 Claude 看（原因在 `logs/_sensor.jsonl`）」——錯誤原文不上畫面。
> 時間或內容看不懂的記號 → 只在 `pipeline-status` 附「另有 N 筆看不懂的故障記號」，不亮燈、不上橫條。
> **技術**：照 `event` 分，不認得的 `event` 算看不懂的那種。`gate.mjs` 記故障時加上那次的資料夾。

**AC-5　還在壞、時好時壞、已經好了，分開講** ✅ 對過 2026-10-05
> **白話**：「現在停電」「這週一直跳電」「昨天停過一小時、已復電」是三盞不同的燈。
> **會發生的情況**（只看 90 天內的記號）：
> 還在壞＝最後一筆故障之後，感測器一筆都沒記到 → 紅燈「從 Y 之後就沒記到」，Y 是最後一筆正常紀錄的時間（不是最近一次故障——jq 不在時每個動作都會留一筆，那個時間永遠是剛剛）；
> 次數只數這一段（壞過、好了、又壞的，不把前一段算進來）。
> 時好時壞＝故障出現過不只一段，中間夾著有記到的 → 黃燈「有些對話記得到、有些記不到，最近一次記不到是 X 前」，附修法。
> 已經好了＝只有一段故障，之後都記到了 → 不上橫條；只在「這一輪」碰到那段期間的對話頁與那個工作區的 `pipeline-status`，放在五關旁：「感測器在 X 到 Y 記不到，那段時間跑的關這裡看不到——『還沒跑』可能是沒記到」。
> 「這一輪從哪開始」是感測器第一筆記到的（不是 A、不是章）時，那一刻不一定是真的開始：在故障期間開始的對話，第一筆被記到的就在修好之後——
> 對話頁看轉錄檔建立的時間；拿不到就照「故障結束到這一輪起點之間，感測器一筆都沒記到」當成碰得到。你在故障開始之前就結案的對話不講。（魔鬼教官第一輪改的。）
> 收工 hook 的寫「之後跑過、沒再記到出錯」，不寫「恢復了」；之後只有別的資料夾跑過，就講「出錯的那個資料夾之後有沒有跑過看不到」（黃燈）——
> 心跳只留最後一次，講不出「還沒跑過」，只講得出「看不到」（施工時改的，原本寫「之後還沒跑過」）。
> **技術**：「感測器記到」只算有 `hook` 欄位的紀錄——`--report`、按鈕、收工 hook 寫的都不算（jq 不在照樣寫得進去）；感測器那一行的「最後一筆來自這裡的紀錄」也照這條算，不然同一畫面兩句打架。
> 看別的專案的紀錄不經 `readEvents`（會順手清檔）；只有真的有感測器故障時才去讀。收工 hook 看心跳的時間晚於故障、而且同一個資料夾；收工 hook 找不到 node 好了的那一句講「最近一次與次數」，不講「X 到 Y 之間」（心跳只留最後一次，分不出各是哪一段）。
> 測試：jq 不在時只按結案、只記 `--report`，照樣紅燈。

**AC-6　外掛的捷徑壞了：照畫面那句修法做一次，就修好；`--on` 不准回「本來就在記錄中」**（查證時順手查到、同一行字；不要就刪這條） ✅ 對過 2026-10-05
> **白話**：螢幕叫你按的鈕，按了要真的有用，按完不准回你「一切正常」。
> **會發生的情況**：今天網頁叫你跑 `--on`，照做印「✅ 這個專案本來就在記錄中」，感測器其實是壞的；終端機叫你跑 `--install`，可是 `--install` 看到捷徑還在就拒絕。
> 改成：網頁、終端機、`--on` 同一句「把資料夾放回原位；或在它現在的資料夾裡跑 `node status.mjs --install`」，而且照做真的修好——在暫存資料夾做一個壞掉的捷徑，照那句做一次，感測器那一行變成已掛上。
> （施工時改的：原本寫 `pipeline-status --install`，但那個簡寫多半也指著搬走前的位置，一樣跑不起來。捷徑指的資料夾還在、但不是完整的 pipeline-monitor（讀不到它的設定、或少了 hook.sh）的，

## 混沌推導
▸ 輸入畸形：你打的第一個字剛好是 `<`（貼 HTML 而 app 沒包成 `<pasted_content>`）→ 當成沒見過的：不算你說的、那個對話頁講出來（講「認不出」，不講「不是你」）；
  收工 hook 只有在那則之後又改了程式才會再擋一次，不會少擋。
▸ 時間：舊紀錄照新規則重讀——bd87046e 的「N 則訊息」少 3 則；9/11 那 3 筆 `<system-reminder>` 開頭的照舊算你的，訊息數不准變。以前若有代記對到的是 agent 回報，會變成「沒對到你的原話」，這是對的；查過那個對話沒有代記。
▸ 容量：jq 不在時，你每說一句話、每次叫 skill、改檔、開瀏覽器都多一行記號，檔案會一直長；畫面只講次數與時間，不逐筆列。
▸ 併發：故障記號全機一份（jq 不在時連是哪個專案都問不到），所以感測器的句子只講「這台電腦」，不講「這個專案」。

## 明確不做
- 不改 `hook.sh`、`gate.sh`：感測器照舊全部照記，分辨只在讀的那一端（刻意的決定）。jq 在、但 jq 程式本身跑失敗時不留記號——等真的碰到。
- 不是 `<` 開頭的新系統字照舊算成你說的、畫面不講——看到一種加一種（用量上限那句英文早就認得）。
- 捷徑指向的資料夾還在、但裡面少了 `hook.sh` 的情況不處理。
- 不做安裝時的環境體檢、不做防撞埠；不清 `_sensor.jsonl`、不動 90 天清理。
- 不做「skill 看的範圍跟收工 hook 不一樣」（另一輪，T1）、「危險清單會隨新檔過期」（你還沒決定要不要寫規格）；不改分級規則，不加任何「太多／太久」的門檻。
