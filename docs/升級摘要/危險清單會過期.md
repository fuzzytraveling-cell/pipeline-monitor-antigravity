## 這是為了解決什麼

危險清單是某一天拍的照片：之後才新加的程式檔、改了名的危險檔，分級永遠不會算成最高那一級，畫面卻不講——看起來像清單還是完整的（R1）。

**實測（唯讀，git 說的）**：TutorPod 清單 9/15 定，之後新加、現在還在的程式檔 2 個（`src/utils/liveModelChoice.js`、`src/utils/reportTime.js`）。
pipeline-monitor 自己的清單 9/16 定（9/23 那次存檔改的不是危險清單），之後新加的程式區檔 10 個，含收工 hook 本身（`gate.mjs`、`gate.sh`）與寫還原點的 `lib/checkpoint.mjs`。
Forma Pro 9/15 之後沒有新加。三個專案的清單現在都沒有已經不在的檔。

## 白話
- 危險清單像倉庫的「易碎品清單」：是盤點那天點的。之後新進來的箱子不在上面，搬的人就照一般貨搬——新箱子進來，要有人問一句「這個易碎嗎？」。
- 清單上的箱子換了標籤（改名），舊標籤找不到、新標籤又不在清單上——清單等於少了一項，沒人知道。

## 驗收條件

**AC-1　這一輪碰到「清單定好之後才新加的程式檔」，分級卡講出來** ✅ 對過 2026-10-05
> **白話**：新進來、沒人問過易不易碎的箱子，搬之前提一句。
> **會發生的情況**：這一輪改了 `src/utils/reportTime.js`（9/15 之後才新加、不在清單上）：對話頁與 `pipeline-status` 的分級卡在等級底下寫「這一輪碰到 1 個危險清單定好（20 天前，git 說的）之後才新加的程式檔：src/utils/reportTime.js——清單不可能考慮過它，危不危險還沒有人判斷；如果是危險的，這次其實是 T2。要判斷就跟 Claude 說『幫我看危險清單』」。
> 等級照舊，不自動升。只講這一輪碰到的；這一輪沒碰到就不講。
> **技術**：「清單定好」＝ git 說危險清單那一段最後一次變的那次存檔（設定檔別的地方變不算）與人記的判斷時間（AC-3）取較晚的。「之後才新加」＝那之後的存檔新增的（`--diff-filter=A --no-renames`，現在還在）＋還沒追蹤的新檔；在程式區、不在危險清單。
> 還沒存檔的新檔沒有存檔時間：修改時間比那一刻早的不算（那時已經在了）；add 過還沒存檔的（`git mv` 改名來的）再看資料夾的時間——改名不改檔案的修改時間（施工時加的）。
> 句子只在 lib 寫一份，終端機與網頁照印（P2）；等級的名字從設定讀（程式碼不寫 T0／T1／T2）。

**AC-2　危險清單裡已經不在的檔，分級卡講出來** ✅ 對過 2026-10-05
> **白話**：清單上的標籤找不到箱子了，要講。
> **會發生的情況**：危險清單上的 `src/utils/cloudBackup.js` 被改名：分級卡寫「危險清單裡有 1 個已經不在了：src/utils/cloudBackup.js——改了名或搬了家的話，新的名字不在清單上，碰到它也不會是 T2。跟 Claude 說『幫我看危險清單』」。一直講到清單改好。
> **技術**：清單裡每一條（檔，或 `/` 結尾的資料夾）在這個工作區找不到就算。分級算得出來的時候講。

**AC-3　判斷過了要記得下來，之後只問新的** ✅ 對過 2026-10-05
> **白話**：問過、答過「這箱不易碎」，就不要每次搬都再問。
> **會發生的情況**：你說「reportTime 只是排時間，不危險」→ Claude 跑 `pipeline-status --tier-checked "你的原話"`：設定檔記下判斷的時間與你的原話；之後 AC-1 只講這一刻之後才新加的。沒附原話不收。
> `pipeline-status --tier-review` 列出整個專案（不只這一輪）清單定好之後新加的程式檔、清單裡已經不在的檔，給判斷用。
> **技術**：`tiers.checked = { at, said, by }`；其他鍵原封不動。在對話裡跑的（環境帶著對話代號）標 Claude 代記——附的話是 Claude 打的，列出來時不准講成「使用者說」（魔鬼教官第一輪加的，老毛病 P7）。

**AC-4　分不出來就說分不出來** ✅ 對過 2026-10-05
> **白話**：清單是哪天點的沒記下來，就不說「這些是新的」，也不說「沒有新的」。
> **會發生的情況**：設定檔沒進版控、也沒記過判斷時間（或 git 問不到），這一輪又碰到不在清單上的程式檔：寫「危險清單沒記下是什麼時候定的，這一輪碰到的程式檔裡哪些是之後才新加的，這裡分不出來——判斷一次（『幫我看危險清單』）就分得出來」。
> **技術**：問不到 → null，不當成「沒有新檔」（R1）。

**AC-5　「幫我看危險清單」照同一套做** ✅ 對過 2026-10-05
> **會發生的情況**：tier-setup skill 多一段：先跑 `--tier-review`，每個檔用原本的三個問題問你、附一句為什麼；你說加才加、說刪才刪；最後照你的原話跑 `--tier-checked`。第一次設定分級寫完清單之後也跑一次。

## 混沌推導
▸ 時間：rebase、cherry-pick 讓舊檔的「新增」存檔變新 → 多問一次，不會少問。
▸ 時間：設定檔改的是三級定義或關卡、不是危險清單 → 不算「清單定好」（pipeline-monitor 9/23 那次就是）。
▸ 容量：這一輪碰到很多新檔 → 列前幾個＋「等 N 個」。
▸ 輸入畸形：`checked` 寫壞（不是時間）→ 當成沒記過，退回 git；不准當成「剛判斷過」。

## 明確不做
- 不自動把新檔加進危險清單、不自動升級（工具不猜危險清單，CLAUDE.md 刻意的決定）。
- 不讓收工 hook 為這件事擋人或叫 Claude 去問——先只在分級卡講；要不要擋，Oscar 回來決定。
- 抓不到「定清單時就漏挑的檔」（reportDelivery.js 那種）——那是人的判斷；也不改「名字像會存東西」那條提醒的字表。
- 不碰 `hook.sh`、`remind.sh`、`lib/events.mjs`。
