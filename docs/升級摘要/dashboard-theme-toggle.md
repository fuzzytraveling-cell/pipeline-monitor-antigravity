**AC-4　「自動切換」依今日真實日出日落時間離線自動換班，跨過日出或日落不用重整** ✅ 對過 2026-11-24
> **白話**：不是寫死「早上 6 點晚上 6 點」假裝看太陽，而是真的照今天台北（或本機時區）的天文日出日落時間換班，開著一整天傍晚太陽下山會自己切夜班。
> **會發生的情況**：選「自動切換」時，儀表板完全離線用瀏覽器本機時區對應的代表座標與今日日期，以天文公式算出今天的日出與日落時刻：日出 ≤ 現在 < 日落 → 白天工班，其餘 → 夜間工班；滑鼠移到「自動切換」按鈕上，提示看得到今天算出的日出與日落時刻、採用的時區與目前生效風格（例如「自動切換（Asia/Taipei：今日日出 06:16、日落 17:04，目前：白天工班）」）；分頁久開跨過日出、日落或午夜，以及筆電休眠醒來切回分頁時，會自動重算並切換，不必手動重整。
> **技術**：於 `ui/app.js` 實作純函式（方便測試注入日期、時區與座標）：內建精簡 IANA 時區→經緯度對照表（含 `Asia/Taipei` 與全球主要時區）＋標準 NOAA 太陽位置公式；結合既有計時器（每分鐘檢查一次，跨日重算）與 `visibilitychange` 事件更新 `data-theme`。

**AC-5　查不到日出日落座標、極晝極夜或存不了偏好時誠實講明，不編時間也不漏程式內部值** ✅ 對過 2026-11-24
> **白話**：算不出日出日落就直說算不到，絕不偷塞一組假時間裝成真的，也不能把 `NaN` 或 `undefined` 印給人看（R1、R3）。

> **技術**：所有 `localStorage` 讀寫與時區查詢皆包 `try/catch`；日出日落計算函式明確處理 `cosH > 1`（極夜）與 `cosH < -1`（極晝）；測試覆蓋未知時區、極晝、極夜、無痕寫入失敗四種情境，確認零 `NaN`／`undefined`／`null`。

## 混沌推導

▸ **時間**：分頁開一整天跨過日出／日落／跨午夜、或筆電休眠醒來 → 自動模式每分鐘與 `visibilitychange` 重算今日日出日落並即時切換（AC-4），且沿用 `--t` 連續時鐘不讓動畫跳回起點；斷線變灰在兩套風格都清晰可辨（AC-8）。
▸ **權限／環境**：無痕視窗或瀏覽器停用 `localStorage` → 捕捉例外不當機，當次照常切換並於提示明講只留到關分頁前（AC-5）；不呼叫瀏覽器定位 API 避免被拒或彈權限視窗。
▸ **輸入畸形**：`localStorage` 存了舊值或被改壞的不認得字串 → 視為未設定退回預設（自動切換）不當機；瀏覽器回傳未知或空時區 → 誠實退回系統深淺色並明講（AC-5）；高緯度極晝極夜 → 明確處理不漏 `NaN`（AC-5）。
▸ **併發**：同時開多個儀表板分頁 → 透過 `storage` 事件即時同步模式與生效風格（AC-6）；正於分級表單打理由時剛好日落自動換班 → 只改 `data-theme` 不重載、不洗掉表單輸入（AC-6）。
▸ **網路**：完全離線運作，不連外部 API、不載外部字型或套件，斷網時三模式與日出日落計算照常運作。

- **不改任何後端資料判斷、感測器、收工門禁、分級邏輯、CLI 指令與終端機文案**：不碰 `lib/`、`server.mjs`、`status.mjs` 及任何危險清單檔案（維持 T1）。
- **不做第三套主題、不提供自訂色票或自訂日出日落手動輸入框**。
- **不把風格選擇搬進 `~/.pipeline-monitor-agy/` 設定檔或新增 `/api/theme`**：風格僅影響瀏覽器畫面，記在瀏覽器本地即可（不影響終端機或 AI 對話）。
