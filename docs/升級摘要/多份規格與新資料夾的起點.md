## 這是為了解決什麼

監視器看到的比實際少，卻講得像看到了全部：一個對話寫了兩份規格，畫面只掛最後回報的那一份、寫「全部 5 條」；
app 新開的資料夾少了一筆 git 紀錄，一存檔，這一輪改過的東西就從分級和收工 hook 眼前消失（L11 換一條路回來）。

**實測（2026-10-02，真的紀錄，唯讀）**

| 對話（TutorPod） | 實際 | 監視器說 |
|---|---|---|
| 接著處理語音練習斷線的後續待辦 | 一次 A 寫了 2 份：live-disconnect-honest 10 條、report-row-time 5 條（用 `lib/checklist.mjs` 讀檔數的） | A、B 都只畫 report-row-time，「全部 5 條」；收工 hook 只要那 5 條 |
| 同一個對話 | 還沒存過檔（48 筆紀錄的版本號都是 2822eb5） | 「找不到這一輪開始時的版本，存檔過的算不進來」——這時數字其實完整 |
| 學生練習時偶發連線錯誤（10/1 開、10/2 存檔） | 存了 15 個檔，5 個在程式區 | 分級「看不全」——那時收工的話，收工 hook 放行 |

找不到的原因：9/22 app 開的資料夾，git 在開資料夾那一刻記了一筆（這一輪的起點就靠它）；10/1、10/2 app 開的兩個一筆都沒有，第一次存檔才有。app 改了做法，程式沒跟上。

## 驗收條件

### 一、一輪寫了幾份規格

**AC-1　一次 A 寫了幾份規格，A 那格就畫幾份** ✅ 對過 2026-10-05
> **白話**：看板掛的圖，要跟建築師交出來的一樣多。
> **會發生的情況**：上面那個對話：A 那格寫「寫了 2 份規格」，兩份各一個清單；搬到進行中之後照樣找得到。只寫一份的對話，畫面跟今天一字不差。
> **技術**：這一輪的規格＝那次 A 之後、下一次 A 之前：(a) 同一個對話記的**每一筆** `--report A`（說明裡每一行是 `.md` 路徑的都算；今天 `reportsIn` 只留最後一筆）
> ＋(b) 同一個 prompt 寫到 `docs/規劃中`、`docs/進行中` 的每一份 `.md`；兩條都沒有才照今天的規則（同一個 prompt 第一份寫到 `docs/` 的 `.md`）。
> 每一份都走 `locateSpec`，找到同一個檔的算一份。`skills/spec/SKILL.md` 第 6 步改成「寫了幾份就記幾次」。

**AC-2　條數是每一份加起來的；只算一份的數字不准長得像全部** ✅ 對過 2026-10-05
> **白話**：「全部 5 條」只能在真的只有 5 條的時候講。
> **會發生的情況**：每一份的清單標題寫那一份的條數（「report-row-time：0/5 對過」）；B 那格與總結寫「2 份規格共 15 條，還有 15 條沒對」。
> **技術**：「全部 N 條」只在一份規格時出現；終端機、網頁、收工 hook 的字一份（P2）。

**AC-3　收工 hook、終端機要的是每一份的清單** ✅ 對過 2026-10-05
> **白話**：工頭收工前要點的是兩張圖的每一項。
> **會發生的情況**：Claude 只對完 report-row-time 的 5 條就想收工 → 收工 hook 擋，分份列出 live-disconnect-honest 還沒標的條目；兩份都標完（✅ 或 ⏳）才不再要求。`pipeline-status` 同樣分份列。
> **技術**：`gate.mjs` 現在拿第一個讀得出的清單（`view.find(...)`），改成這一輪的每一份。

**AC-4　E 要驗的也是每一份；兩份的 AC-1 分得開** ✅ 對過 2026-10-05
> **白話**：兩張圖都有「第 1 項」，驗收時要講是哪張圖的第 1 項。
> **會發生的情況**：`--round E` 分份列要驗的條目；兩份以上時回報每一行前面加規格名（`report-row-time AC-1 看到了：「…」`），E 那格寫「15 條裡…」。
> 只寫「AC-1 看到了」沒寫哪一份 → 不猜，不算進任何一份的結果，照原文列出來（R1）。只有一份規格的照今天的格式。
> **技術**：`lib/verify.mjs` 的 `parseWalk`／`walkSummary` 認規格名；`skills/verify/SKILL.md` 寫這個格式。

**AC-5　讀不到的那一份不准安靜消失，也不准編條數** ✅ 對過 2026-10-05
> **白話**：有一張圖找不到，要說找不到，不能當作只交了一張。
> **會發生的情況**：記過的一份被刪了、只在主資料夾、同名兩份 → 那一份照今天單份時的說法列一行，條數不算進總數，總數旁邊寫「另有 1 份讀不到，條數不在裡面」。
> **技術**：每一份各有自己的 `place`；總數只加讀得到的（R3）。

**AC-6　這一輪還動了另一份規格檔、沒記到是誰寫的 → A 那格講一句** ✅ 對過 2026-10-05
> **白話**：看板上沒掛、工地裡卻多了一張圖，要提醒一句。
> **會發生的情況**：Claude 寫了兩份只記了一份（或用指令寫的，感測器看不到）→ git 看到 `docs/規劃中` 多了一份 → A 那格寫「這一輪還動了 X.md，沒記到它是不是這一輪的規格」。不擋收工（分不出是不是這一輪要做的）。
> **技術**：這一輪的改動清單（`changeFacts` 那一份，含新檔）裡 `docs/規劃中|進行中` 的 `.md`，扣掉這一輪認到的規格。

**AC-7　連著一份規格又連另一份：講清楚舊的換掉了** ✅ 對過 2026-10-05
> **白話**：施工對話（`--spec`）一次只照一份，第二份會蓋掉第一份——蓋掉可以，安靜蓋掉不行。
> **會發生的情況**：先 `--spec A.md` 再 `--spec B.md` → 終端機寫「原本照 A.md，換成照 B.md——之後只對 B 的清單」；A 那格多一行「原本照 A.md，後來換成 B.md」。
> **技術**：`doSpec` 記之前看這個對話這一輪的連結。

### 二、app 新開的資料夾

**AC-8　git 查不到這一輪開始時的版本，就用感測器在那一刻記下的版本** ✅ 對過 2026-10-05
> **白話**：登記簿查不到，就看自己監視器拍到的那一格。
> **會發生的情況**：「接著處理語音練習斷線的後續待辦」那一頁：未檢查清單的小標從「還沒存檔（commit）的改動／找不到這一輪開始時的版本，存檔過的算不進來」
> 變成「這一輪改過的檔案（含已存檔的）／從叫 A 寫規格（…前）那一刻的版本算起，含已存檔的」；分級卡不再寫「只算還沒存檔的…實際可能更高」。
> **技術**：感測器每一筆都記 `head`。起點那一筆（A、第一句話或第一筆紀錄）的版本號認得出來（`git rev-parse --verify`）、而且還在這條分支上（跟章同一個判斷 `checkpointRelation`）→ 當基準。
> git 查得到的照舊用 git，算法一個字不改；只有 git 回「沒有紀錄」或「紀錄比起點晚才開始」才走這一條。`lib/origin.mjs` 開頭與 LESSONS 裡「app 開 worktree 那一刻就有一筆」的說法要改。

**AC-9　存檔之後，分級和收工 hook 照樣算得到這一輪的改動** ✅ 對過 2026-10-05
> **白話**：圖紙收進保險箱，工頭該攔的還是攔——新開的資料夾也一樣。
> **會發生的情況**：「學生練習時偶發連線錯誤」那一頁：分級從「看不全」變成 T1（程式區 5 個檔）。沒章、改到程式區、存檔後才收工的對話 → 收工 hook 照樣要 D。
> **技術**：測試做一個沒有 git 移動紀錄的工作區（跟 app 開的一樣），存檔之後收工 hook 照樣擋；拿改之前的程式跑要紅。標 P1、P5。

**AC-10　兩邊都查不到 → 跟今天一樣講「看不全」，不拿別的版本頂替** ✅ 對過 2026-10-05
> **白話**：兩本簿子都沒有，就說不知道，不挑一個差不多的。
> **會發生的情況**：起點那一筆沒記到版本號（舊紀錄、當時 git 讀不到）、版本號撞名認不出來、那個版本已經不在這條分支上（rebase、reset）→ 畫面跟今天一字不差。
> **技術**：不往前後找「最接近的一筆」——那是猜（R1）。

**AC-11　「這一輪中間動過」也看感測器** ✅ 對過 2026-10-05
> **白話**：中間切過分支、存過檔又切回來，算出 0 個檔時要講「看不全」，不畫「沒有改動」（P5 的第二個身體）。
> **會發生的情況**：走 AC-8 那條路的資料夾，git 的紀錄或感測器任何一邊看到起點之後版本號換過 → 0 的時候講「看不全」。
> **技術**：`moved`＝git 紀錄裡起點之後指到過別的版本，或感測器起點之後任何一筆的版本號跟基準不同。

## 混沌推導（只寫有觸發的）

▸ **併發**：兩個對話共用一個資料夾、各自叫 A → 只認同一個對話記的 `--report A`（紀錄帶 `by_session`）；沒有對話代號的舊紀錄照今天一樣認。
▸ **時間**：感測器的版本號是那一刻讀的，不用跟任何鐘比，避開「同一秒分不出先後」。`--report`（毫秒）跟 A（秒）比先後照今天換同一個鐘。
▸ **輸入畸形**：一筆 `--report A` 寫兩行路徑 → 兩份；不是 `.md` → 不算規格；同一份記兩次（規劃中、搬到進行中各一次）→ 一份；版本號是空的 → 當成沒記到（AC-10）。
▸ **容量**：多一份規格多讀一個檔；版本號多問一次 git。不另設上限。

## 明確不做

- **不支援施工對話同時照兩份規格**（`--spec` 一次一份；AC-7 只讓「換掉」看得見）。等真的碰到再說。
- 不改「一輪」的定義（A 或蓋章）；一次 A 寫幾份都是同一輪。
- git 查得到起點時的算法一個字不改（同一秒往大的那邊倒、資料夾剛建好那一秒）。
- 不動感測器：`hook.sh` 一行不改——版本號本來就記了。
- 換人（新對話接手舊資料夾）照舊靠 git 的紀錄：10/2 實測換人那一筆還在。app 哪天連那一筆都不留，另開。
- 三階梯「併進 main」那格在這種資料夾會說「分不出來」——那是實話（證據本來就在 git 的紀錄裡），這次不動。
- 不替 app 補 git 紀錄、不改使用者的 git 設定。
- AC-6 那種沒記到的規格不擋收工。
