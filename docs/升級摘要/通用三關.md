# 功能：通用三關 —— plugin 帶 A 寫規格／C 打掃／D 魔鬼教官，任何專案都叫得到

> 2026-09-15 開工。對應 [`../ROADMAP.md`](../ROADMAP.md)「怎麼做到裝到任何專案都能用」那段，
> 以及 [`../升級摘要/plugin.md`](../升級摘要/plugin.md)「刻意不做」裡留下的那一條（「另開規格」——就是這份）。
>
> ROADMAP 明講的最大設計風險：**TutorPod 的五關是為那個專案長出來的，硬套到別的專案會變成儀式。**
> 所以這份規格的每一條都在回答同一個問題：**通用版跟 TutorPod 版差在哪、專案專屬的東西從哪裡來。**

## 這是為了解決什麼

儀表板已經會在任何專案顯示五關，但 A／C／D 三關在 TutorPod 以外的專案永遠是「找不到 /spec 這個指令」——
那三支指令是 TutorPod 自己的 `.claude/commands/*.md`，別的專案沒有。
感測器裝到第二個專案（Forma Pro）之後，五關裡有三關**永遠不會有紀錄**，監視器只剩 B 與 E 在動。

## 白話

- plugin 除了感測器，再帶三支指令：`/pipeline-monitor:spec`、`/pipeline-monitor:cleanup`、`/pipeline-monitor:chaos-check`。
  裝一次，每個專案都叫得到。
- 它們是 TutorPod 那三支的**通用版**：做同一種事，但**不知道你這個專案的任何事**。
  它像一個新來的人：第一件事是讀那個專案自己的手冊，不是憑印象。手冊沒有的，說「手冊沒有」，不准編。
- 專案自己有同名指令（TutorPod 的 `/spec`）時兩個並存，使用者叫哪個就跑哪個；感測器把兩種名字都算成同一關。

## 通用版跟 TutorPod 版差在哪（這份規格的核心）

| | TutorPod 版 | 通用版 |
|---|---|---|
| 住在哪 | 那個專案的 `.claude/commands/{spec,cleanup,chaos-check}.md` | plugin 的 `skills/<名字>/SKILL.md`，裝一次每個專案都有 |
| 怎麼叫 | `/spec` | `/pipeline-monitor:spec`（專案自己有 `/spec` 時兩個並存） |
| 感測器記成 | `skill: "spec"` | `skill: "pipeline-monitor:spec"`；讀取端兩種名字都算 A |
| 已知死法（D 的判準） | 寫死在指令裡：模式編號、「A1 已發生 6 次」、哪個資料夾覆蓋最稀 | 從那個專案的 `docs/FAILURE-PATTERNS.md` 讀；沒有就只對三條通用判準，**而且結論裡要說是這樣** |
| 教訓全文 | 寫死 `docs/references/LESSONS.md` | 專案有 `docs/LESSONS.md`（或 `docs/references/LESSONS.md`）才讀 |
| 規格的格式 | 寫死 `docs/SPEC-TEMPLATE.md`（含 TutorPod 的六大物理極限與例子） | 專案有 `docs/SPEC-TEMPLATE.md` 就照它；沒有就用 skill 內建的最小格式。六個問題只留**問法**，例子要從這個專案自己的邊界推 |
| 分級 | 寫死 `node scripts/tier.mjs --files` | 讀 `.claude/pipeline-stages.json` 的 `tiers`；沒設定就寫「還沒設定分級」，不准寫 T0 |
| 文件索引 | 寫死 `docs/SKILL.md` 那棵樹 | 專案有列 docs/ 檔案的索引（`CLAUDE.md`、`docs/SKILL.md`、README）才加一行；找不到就明說「沒有更新索引」 |
| 要跑的檢查（C） | 寫死 `npm run lint && npm test && npm run test:unit && npm run build` | 從 `package.json` 的 scripts 認：lint／test／test:unit／build 有哪些跑哪些——跟 `pipeline-status --checkpoint` 同一條規則 |
| 測試檔（C 唯讀） | 寫死 `tests/**`、`scripts/*.test.mjs`、`vitest.config.js` | 路徑含 test／spec／`__tests__` 的，加測試設定檔 |
| 刻意的決定（C 不准順手修） | 寫死 `CLAUDE.md` 的〈刻意的決定〉 | 專案的 `CLAUDE.md` 裡任何寫著「刻意」「不是 bug」「不要順手修」的段落；沒有就沒有 |
| 用語與比喻 | 老師、學生、講義、上課 | 「使用者」；比喻用**這個專案的使用者的世界**，從 README／CLAUDE.md 看它是給誰用的 |
| 三條紅線 | TutorPod 自己那三條 | 專案有自己的清單就用專案的；沒有就用本專案 `CLAUDE.md` 的 R1（沒問到≠沒有）、R2（跑過≠通過）、R3（不編數字） |

**兩條原則，三支 skill 共用：**

1. **專案專屬的東西一律從那個專案自己的檔案讀。** 存在才讀，不存在就退回通用判準，並且**在回覆裡說用的是哪一套**——
   不准把「這個專案沒有清單」講成「這個專案沒有已知死法」（R1）。
2. **TutorPod 版裡只有「做法」可以搬，「事實」不能搬。** 做法：一頁、AC 白話在前、報告門檻、證明得出來才刪。
   事實：某模式發生過幾次、哪個資料夾覆蓋最稀、某個服務冷啟動幾秒——那些是 TutorPod 量出來的，
   搬過來就是替別的專案編數字（R3）。

## 驗收條件

**AC-1　裝了 plugin 就有：叫得到、記得到、算同一關**
> **白話**：以前每個專案要自己貼三支指令檔；現在裝一次 plugin 就有。
> **會發生的情況**：任何裝了 plugin 的專案，打 `/pipeline-monitor:spec` 有反應；
> 感測器記到 `skill: "pipeline-monitor:spec"`；五關的 A 亮起來。
> **技術**：`skills/spec`、`skills/cleanup`、`skills/chaos-check` 各一個 `SKILL.md`（frontmatter 有 `name` 與 `description`）。
> `lib/events.mjs` 的 `matcherOf` 已經認 `<plugin>:<skill>` 這種後綴，不動。

**AC-2　專案專屬的東西一律從那個專案自己的檔案讀，讀不到要說**
> **白話**：新來的人先讀手冊。手冊沒有的，說「手冊沒有」，不要說「沒有這回事」。
> **會發生的情況**：在有 `docs/FAILURE-PATTERNS.md` 的專案，D 用它的編號與次數；
> 在沒有的專案，D 只對三條通用判準，**並且結論裡明說**。A 與 C 同理（格式、分級、檢查指令、刻意的決定）。
> **技術**：三支 `SKILL.md` 各有一張「要知道的／去哪讀／沒有的話」表。

**AC-3　不寫死任何 TutorPod 的路徑或詞**
> **白話**：通用版裡不該出現另一個專案的門牌號碼。
> **會發生的情況**：`npm test` 有一支測試掃三個 `SKILL.md`，出現**指向** TutorPod／ai-english-course 的路徑就紅；
> **提到**「TutorPod 版」這個詞不算違規（跟 `scripts/independence.test.mjs` 同一個判準：提到沒關係，指向才有關係）。
> **技術**：`scripts/skills.test.mjs`，含反向測試（一條假路徑必須被抓到、一句提到必須被放過）——老毛病 P4。
> 詞（老師、學生、某個服務的名字）靠人看，測試不釘：釘字面會變成狼來了（L10）。

**AC-4　三支各自說清楚產出什麼、不產出什麼**
> **白話**：每一關的邊界寫在它自己的第一段，叫它的人不用猜它會不會動到別的東西。
> **會發生的情況**：
> A 只產一份 `docs/規劃中/<slug>.md` 與回覆裡的 AC 清單，然後停下；不寫程式、不改既有檔案（唯一例外：索引那一行）。
> C 只做證明得出來是死的刪除，其餘進「只建議、沒動手」清單；測試檔唯讀；不改控制流、不抽模組。
> D 只找問題，**不動任何檔案**；不宣稱通過。
> **技術**：三支 `SKILL.md` 的第一節都叫「產出什麼、不產出什麼」。

**AC-5　D 守 R2：結論永遠是「找過」，不是「通過」**
> **白話**：驗屋師傅來過，不等於房子沒問題。
> **會發生的情況**：D 一條都沒找到時寫「這次的改動我沒對到任何已知死法」＋「這是找過，不是通過」；
> 找到的每一條都有具體觸發條件、使用者看得到的症狀，上限 8 條。
> **技術**：D 還要看**新檔案**——`git diff` 看不到還沒被 git 追蹤的檔案（老毛病 P1，本專案自己犯過三次），
> `SKILL.md` 明寫 `git ls-files --others --exclude-standard`。拿不到改動（不是 git 專案、指令失敗）要說「拿不到」，不是「沒有改動」。

**AC-6　五關 A／C／D 在別的專案從「找不到這個指令」變成「這一輪還沒跑」**
> **白話**：儀表板要看得見 plugin 帶來的指令。
> **會發生的情況**：在 Forma Pro 跑 `pipeline-status`，A／C／D 三行變成「這一輪還沒跑」；網頁版同理。
> **技術**：`lib/skills.mjs` 已經會找 `~/.claude/skills/<plugin>/skills/<skill>/SKILL.md`，不用改；
> 測試用假 home 放一個指向這個 repo 的捷徑，斷言找得到。
> ⚠️ 這台機器的捷徑指向**主資料夾**（main）：這條分支合併之前，真的 Claude Code 與主資料夾的 `status.mjs` 都看不到這三支——
> 驗證只能用臨時 HOME 指向這條分支，施作紀錄要照實寫。

**AC-7　同名指令並存，寫進 README**
> **白話**：TutorPod 自己的 `/spec` 還在，不會被蓋掉，也不會被拆掉。
> **會發生的情況**：README 的 plugin 那段說明兩個名字、叫哪個就跑哪個、感測器兩種名字都算同一關。
> **技術**：文件；`matcherOf` 不動。

**AC-8　流程要能換：plugin 帶的是「預設的三關」，不是「唯一的三關」**
> **白話**：專案可以把關卡換掉，這三支指令不會因此壞掉，也不會硬把自己算成關卡。
> **會發生的情況**：專案用 `.claude/pipeline-stages.json` 換關卡（改名、加關、減關）時，三支指令照樣叫得到，
> 但只有名字對得上 `skill` 的才算關卡；內建 `stages.json` 裡每一個有 `skill` 的關，plugin 都要帶對應的 `SKILL.md`。
> **技術**：關卡清單只住 `stages.json`；`skills/` 的資料夾名跟 `stages.json` 的 `skill` 名一致，測試對兩邊（老毛病 P2）。

## 混沌推導（只寫有觸發的）

▸ **輸入畸形**：專案的 `docs/FAILURE-PATTERNS.md` 存在但沒有觸發表、格式跟預期不同 → 當文字通讀，不假設格式。
▸ **權限／環境**：不是 git 專案、git 指令失敗 → D 說「拿不到改動」；沒有 `package.json` 或沒有任何檢查腳本 →
　C 明說「沒有東西能證明我沒弄壞」，只做靜態證明得出來的那幾種。
▸ **併發／並存**：同名指令並存時 Claude 可能自己挑一個 → description 寫明「使用者叫哪個就跑哪個」；感測器兩種都算。
▸ **時間**：捷徑指向主資料夾 → 合併前 Claude Code 看不到這三支（AC-6）。

## 刻意不做

- **不做成 subagent（`context: fork`）。** ROADMAP 說 D 最適合做成「全新的腦袋」，但感測器現在只認主對話裡的 Skill 呼叫（已實測），
  `SubagentStop` 沒接；先讓三支在主對話裡跑通、被記到，再考慮 fork。而且 Oscar 要看得到過程——跟 B 不關進黑盒子是同一個理由。
- **不動 TutorPod 的三支。** 它們留著，並存；TutorPod 要不要改用 plugin 版是它自己的決定，在它的 repo 做。
- **不把 TutorPod 的 FAILURE-PATTERNS 搬進 plugin。** 那是它的死法清單，搬過來就是替別的專案編事實。
- **不做 E 驗收的 skill、不做 `/pipeline-monitor:status`。** 另開。
- **不做「找不到指令時提示裝 plugin」的文案。** 三處畫面（終端機、`collect`、網頁）要一起改，另開。
