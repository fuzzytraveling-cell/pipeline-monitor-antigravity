分級：**預測至少 T1**（會碰到程式區的 `status.mjs`（`--round`）、`skills/chaos-check/SKILL.md`、`skills/cleanup/SKILL.md`，與 `scripts/` 的測試；沒碰到危險清單）。

> 2026-10-05 用 `/pipeline-monitor:spec` 寫的，跟「危險清單會過期」同一次 A；Oscar 事先授權同上（規格清單不等點頭、D 第二三輪接著跑）。
> 讀了：`CLAUDE.md`、`docs/FAILURE-PATTERNS.md`（P1、P2、P4）、`skills/chaos-check/SKILL.md`、`skills/cleanup/SKILL.md`、`lib/scope.mjs`、`status.mjs` 的 `doRound`／`roundFiles`、`gate.mjs` 講範圍那句。

## 這是為了解決什麼

收工 hook 跟儀表板講「這一輪的改動，含已存檔的」；D 第一輪跟 C 卻自己用 `git diff HEAD` 拿改動——這一輪中途存過檔，它們只看得到還沒存檔的那一半，照樣回報「跑過」（R2）。
同一件事兩處各算一次（老毛病 P2），程式裡修好的「這一輪的起點」（P1 那一條），skill 的字沒跟上。
查證時量的：紀錄裡 58 次叫 C／D，21 次叫的時候這個資料夾的版本已經跟對話開始時不同——原因混著存檔、換人接手、同一個對話做好幾件事，只能說明「一輪中間存過檔」很常見，不能說這 21 次都看漏了。

## 白話
- 工頭的點收單寫「這一輪施工的全部」，驗屋師傅（D）跟清潔工（C）卻只看「今天還沒封箱的那幾箱」——已經封箱的那半，沒人敲過、沒人掃過，回報照樣寫「看過了」。

## 驗收條件

**AC-1　D 第一輪：`--round D` 講這一輪從哪算起、改過哪些檔，跟收工 hook 同一份** ✅ 對過 2026-10-05
> **白話**：驗屋師傅開工前拿到的清單，跟工頭點收用的是同一張。
> **會發生的情況**：第一次跑 `pipeline-status --round D` 多印三樣：「這一輪從叫 A 寫規格（2 小時前）那一刻的版本算起，含已存檔的（版本 abc1234）」；這一輪改過的要看的檔（標危險清單、測試檔、新檔、已刪）；
> 「拿改動：git diff abc1234 -- <那幾個檔>；標新檔的整份讀」。一輪中途存過檔，存檔過的那幾個照樣在清單上。
> 起點找不到（只看得到還沒存檔的）→ 照實寫，回報第一行寫「這一輪的起點找不到，只看了還沒存檔的改動」。
> **技術**：起點與清單跟終端機的改動體檢同一份（`changeFacts` 的 base 與那份檔案清單），講法用 `lib/scope.mjs` 那句；分類跟第二輪同一個函式。

**AC-2　C 打掃：`--round C` 給同一份範圍** ✅ 對過 2026-10-05
> **會發生的情況**：以前 `--round C` 失敗（「能用 --round 的關：D…」）。改成印同一段範圍（C 沒有第幾次、跑法——這一輪跑過就算）。
> **技術**：只限有指令的關；瀏覽器那一關（E）照舊走它自己那一套。

**AC-3　兩支 skill 照 `--round` 給的範圍看，不自己決定** ✅ 對過 2026-10-05
> **會發生的情況**：chaos-check 第一次也照 `--round D` 給的版本與檔案拿改動；cleanup 的範圍改成先跑 `pipeline-status --round C`。
> 有給參數（git ref）照舊用參數。`--round` 沒有這一段（舊版、指令不存在）→ 退回 `git diff HEAD`＋新檔，回報第一行寫「拿不到這一輪的範圍，只看了還沒存檔的改動」。
> **技術**：cleanup 的 `allowed-tools` 加 `Bash(pipeline-status --round:*)`。

**AC-4　測試釘住：中途存過檔，第一輪的範圍照樣看得到存檔過的** ✅ 對過 2026-10-05
> **會發生的情況**：劇本：叫 A → 改 `a.js` → 存檔 → 改 `b.js` → `--round D` 第一輪列 `a.js` 與 `b.js`、版本是 A 那一刻的；`--round C` 同一份；收工 hook 的範圍那句同一個起點。
> skill 的字：不准再把「沒參數 → `git diff HEAD`」當第一輪的預設（檢查意圖：「第一次也照 --round」那句在，P4）。

## 混沌推導
▸ 輸入畸形：起點那個版本已經不在這條分支上（rebase、reset）→ 起點找不到，照 AC-1 講只看得到還沒存檔的（沿用現在的判斷，不另寫）。
▸ 併發：共用資料夾、好幾個對話 → 清單含別的對話改的，照列，講一句（跟第二輪同一句）。
▸ 時間：蓋過章 → 從蓋章算（「蓋章之後的改動」）。

## 明確不做
- 不改收工 hook、儀表板怎麼算「這一輪」——它們是對的那一邊。
- 不讓 skill 自己算起點（那就是第二份實作）；第二輪以上的範圍照舊。
- 不改 A、E 的 skill；不碰危險清單上的檔。
