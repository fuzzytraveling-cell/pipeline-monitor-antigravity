## 這是為了解決什麼

終端機的每個指令都擠在 `status.mjs` 一支檔裡：改一個指令要讀整支、兩個對話改不同的指令也撞在同一支、D 每一輪都要看整支。
量的（10/7；卡片的數字是 10/6 量的，照 L34 重量一次）：1943 行；最近 60 次改程式的存檔（9/11～10/7）有 39 次碰到它。

## 白話
- 一本寫滿所有指令的厚筆記本，照指令拆成八本分冊；`status.mjs` 變成總機，只負責「這個旗標轉給哪一本」。每一頁的字都不改、不准掉頁、不准抄兩份。

## 怎麼分（新檔都放 `lib/`，`cli` 開頭＝只有終端機用）

| 新檔 | 管什麼 | 指令 |
|---|---|---|
| `cliFacts.mjs` | 大家共用的：紀錄與章住哪、這次改動／五關／分級的事實、這個對話是誰、一句話截多長 | （其他幾支從這裡拿） |
| `cliView.mjs` | 整份畫面的上半：標題、故障橫條、感測器與收工 hook 那兩行、還原點 | 不帶旗標 |
| `cliStages.mjs` | 五關那一段與規格清單 | 不帶旗標 |
| `cliTier.mjs` | 分級卡與分級的指令 | 不帶旗標、`--tier-*`、`--tier`、`--tier-retract` |
| `cliStamp.mjs` | 蓋章 | `--checkpoint` |
| `cliReport.mjs` | 記一筆給儀表板：結論、你說的話、照哪份規格、建議卡 | `--report`、`--clear`、`--spec`、`--suggest` |
| `cliRerun.mjs` | 要不要再跑 | `--round`、`--decide` |
| `cliOnOff.mjs` | 這個專案記不記 | `--on`、`--off` |

照現在每個函式的行數算：最大的一支不到 400 行，`status.mjs` 剩約 130 行。
只准單向拿：`cliFacts` 不拿任何一支；`cliRerun` 拿 `cliStages` 的 `specNotes`（「規格在哪」那句旁白，五關那段與 `--round E` 共用）；其他只從 `cliFacts` 拿。

**AC-1　拆開之後，終端機印的每一句話都跟拆之前一字不差** ✅ 對過 2026-10-07
> **白話**：分冊之後從頭唸一遍，每一句都跟原本那本一樣。
> **會發生的情況**：拆之前另存一份舊程式。拿三個專案（pipeline-monitor、TutorPod、Forma Pro）真的紀錄新舊各跑一次：每個主資料夾與還在的每個對話資料夾的整份畫面、

> **技術**：兩邊讀同一份紀錄快照——TutorPod 現在開著一個對話、一直在寫紀錄，直接讀會比出假的差異；「N 分鐘前」跨分鐘差一格就重跑那一組。比對腳本放暫存資料夾，結果寫進施作紀錄。

**AC-2　會寫東西的指令，寫到跟以前同一個地方、寫進一樣的內容；比對全程不在你真的紀錄裡多寫一筆** ✅ 對過 2026-10-07
> **白話**：搬家之後信箱地址不能跟著換——信寄到舊地址，你在新家永遠收不到，也沒有人會通知你。
> **會發生的情況**：`--report`、`--clear`、`--spec`、`--suggest`、`--decide`、分級那幾個指令、`--checkpoint`、`--on／--off`（含給錯參數）在暫存資料夾裡新舊各跑一次：
> 寫出來的紀錄、章、設定檔，除了時間那一格一字不差，印的話與結束碼也一樣。全程不碰你真的紀錄——不然儀表板會多出一筆假的結論。
> **技術**：紀錄、章、關卡清單住哪由四個地址決定（程式的資料夾 `HERE`、資料的家 `HOME_DIR`、`LOG_DIR`、`CHECKPOINT_DIR`），只在 `cliFacts.mjs` 算一次、其他每支從那裡拿（P2）。
> `HERE` 搬進 lib/ 要往上一層（照 `lib/mount.mjs` 的 `CODE_DIR` 寫法）——**這是唯一一行不能原封不動的程式**。暫存資料夾的比對靠環境變數換掉地址，正好跳過你平常走的那條路（P3），
> 所以另外把四個值在不設環境變數時印出來跟拆前比（主資料夾、worktree、透過 `pipeline-status` 捷徑各一次）：`HERE` 錯了，plugin 名字會安靜退回預設值、剛好跟真的一樣，比畫面比不出來。

**AC-3　原文每一行只搬到一個地方；每支用到的東西都拿得到，連出錯時才跑到的那幾行也算** ✅ 對過 2026-10-07
> **白話**：拆分冊時每一頁只能出現在一本——掉一頁沒人發現，抄成兩頁以後改了一頁，另一頁就在說謊。搬家也要搬滅火器：平常用不到，失火那天才發現沒搬就太晚了。
> **會發生的情況**：少 import 一個名字，程式不會一開始就報錯，要等跑到那一行才炸——你看到的是一串程式錯誤。平常跑不到的錯誤訊息那幾行，測試也跑不到，所以逐支用腳本檢查，不靠跑跑看。
> **技術**：腳本照行號切，每個切點先比對那一行的原文才寫（對不上就停、什麼都不寫）。新檔照原順序接回去跟舊檔逐行比：除了檔頭、import、export 清單與 `HERE` 那一行，一行不多一行不少。
> 函式不改名、不改內容與註解，連 `export` 都不加在函式前面（每支最後一個 export 清單——測試照原文抓函式的寫法因此不用改）。
> 用舊檔的頂層名字＋import 的名字當清單，逐支確認用到的不是自己宣告就是 import 進來的；`node --check` 每支；沒有互相 import 的圈。

## 混沌推導
▸ 併發：另一個對話同時改 `status.mjs`（特別是「終端機和網頁各寫一份的句子收成一份」那件）→ 併的時候整支撞。10/7 量的：pipeline-monitor 另外三個資料夾都沒有還沒存檔的改動、
  沒有正在跑的 pipeline-monitor 對話、那件還沒開工。開工前、併進 main 前各再看一次。拆好之後，從舊 main 開出來的資料夾再改 `status.mjs` 會整支撞 → 先跟 main 同步再動。
▸ 時間：比對時的紀錄快照與跨分鐘，見 AC-1。常駐儀表板跑的是 `server.mjs`、不經過 `status.mjs`；併進 main 之後照舊 `--serve-restart`，確認它還活著。

## 明確不做
- 不改任何函式的名字、邏輯、註解，與任何一句你看得到的話——看到想修的記下來，另外做。
- 不搬 `--serve-*`、`--open`、`--install／--uninstall`：卡片舉的例子之一，量過才知道早就住在 `lib/service.mjs`、`lib/mount.mjs`，`status.mjs` 裡只剩轉接的幾行。
- 不做「收成一份」那件；不拆 `lib/rounds.mjs`、`lib/collect.mjs`、`ui/app.js`（一件一件來）。
- 不碰危險清單上的任何一支（`hook.sh`、`hooks/hooks.json`、`lib/events.mjs`、`lib/paths.mjs`、`lib/mount.mjs`、`lib/checkpoint.mjs`）。
- 不在 `CLAUDE.md` 加新的「刻意的決定」：「`status.mjs` 只做分派」寫在它自己的檔頭——要加指令的人一定會打開它；`CLAUDE.md` 每個對話都整份讀，多一行每個對話都多付一次。
- 不加新測試（見 AC-5）。
