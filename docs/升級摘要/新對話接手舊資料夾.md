## 這是為了解決什麼

app 會把收掉的對話留下的資料夾，換一條新分支給下一個新對話用。工具沒發現換了人，把上一個對話的還原點、A／C、改動算到新對話頭上——終端機、儀表板、收工 hook 各講一種，收工 hook 擋錯東西。
**會亂擋的收工 hook，三天後就沒人理了**（9/24 你已經說過一次「不補」）。

**實測**（今天唯讀重跑那個資料夾 `spec-relocation-detection-834bf7`：9/22 規格搬家的對話用過，9/24 09:52 換到新分支給「程式整理」）：

| | 終端機 | 儀表板、收工 hook | 其實 |
|---|---|---|---|
| 還原點 | 還沒有 | 9/22 舊對話蓋的那顆 | 這條分支沒蓋過 |
| 這次改動 | 45 個檔（從舊對話的 A 算） | 40 個檔（從舊章算） | **19 個檔**（從接手那一刻算） |
| 分級 | T2（碰到 `lib/events.mjs`） | T2（同左） | **T1**——`lib/events.mjs` 是別的對話改的，早就在 main 上 |
| A、C | ✅（舊對話 9/22 跑的） | 缺 → 收工 hook 擋 | 這個對話沒跑；T1 也不要 |
| B 的清單 | 套舊對話的規格：「4/5 對過，沒對完」 | 沒套 | 這個對話沒有規格 |

**不是一次性的**：pipeline-monitor 現在 5 個工作區資料夾有 3 個、TutorPod 3 個全部，都是舊資料夾換新分支接著用（查 git 的 reflog）——寫這份規格的這個對話也是（它跑了 A，這一輪從 A 算，所以沒中）。
沒跑 A 的小修（T1 最常見的那種）每一次都會中。

## 要你決定的（兩題，都附建議）

**① 「一輪」多一個分界：資料夾換到新分支、給新對話用 → 新的一輪。**　建議：加。
你 9/21 定的是「一輪 = 到下一次 A 或蓋章」。這次是第三種：沒跑 A、沒蓋章，資料夾卻已經換了一件事。不加，舊資料夾裡的小修永遠接著上一個對話的一輪。
例外照「寧可多算」：同一個對話自己中途換分支、或 app 把收掉的對話接回它原來的分支——不算換人（AC-2）。

**② 還原點跟著「資料夾＋分支」走。**　建議：是。
換了分支，舊章留給舊分支，不當這一件的還原點：新對話在舊資料夾裡，跟在全新資料夾裡一樣，一開始都是「還沒有還原點」。
另一個選法：舊章照樣給你看（它的版本確實檢查過），只是「這次改動」不從它算。不建議：回到那顆會丟掉之後 14 次存檔，大多是別的對話併進 main 的；
而且看不看得到還原點，會取決於 app 這次剛好有沒有重用資料夾——你看不到、也管不到的事。

**AC-2　同一個對話自己換分支、或收掉的對話被接回原分支，不算換人，之前做的照算** ✅ 對過 2026-09-24

## 混沌推導（只寫有觸發的）

▸ **時間**：reflog 是秒＋本地時差、感測器只到秒 → 照 `reflogOf` 用 `--date=unix`；「差幾秒」沿用 `SKEW_MS`，不另訂門檻。
▸ **併發**：接手之後上一個對話又被叫起來動了 → 它橫跨接手 → 照 AC-2 當沒換人（跟今天一樣講共用、往大的算）。
▸ **輸入畸形**：reflog 某一行讀不懂 → 跳過那一行；整份讀不到、過期、被關掉 → AC-6。
▸ **容量**：reflog 本來就為起點讀一次，同一份拿來找接手，從新往舊找到第一筆就停。

## 明確不做

- 不改 app 重用資料夾的行為（管不到，也不用管）。
- 不動感測器、不在紀錄裡加分支欄位（危險清單；reflog 就有換分支的時間）。
- 不改 `lib/events.mjs`；非動不可先停下來問你（會變 T2）。
- 「A、蓋章」兩個分界照舊；有章時的基準照舊。
- 不改紀錄檔、不回頭重算上一個對話當時的改動數字（資料夾已經不在那個狀態，算不回來，只講明）。
- 一條分支搬到另一個資料夾、章是在舊資料夾蓋的：照「資料夾＋分支」不認（git 不讓兩個資料夾同時在同一條分支上，很少見）。
